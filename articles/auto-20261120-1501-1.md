## はじめに

Pythonの開発環境まわりは、長らく「道具が多すぎる」と言われてきました。仮想環境は `venv`、依存解決は `pip`、固定は `pip-tools`、プロジェクト管理は Poetry や pipenv……。用途ごとに別のツールを使い分ける必要があり、そのたびに設定ファイルの作法も変わります。

そこに風穴を開けたのが、Astral が開発する **uv** です。Rust 製の高速なパッケージマネージャーでありながら、仮想環境・依存解決・ロックファイル・Python 本体のバージョン管理・ツール実行までをひとつにまとめています。

この記事では、uv の基本的な使い方と、「これまで pip や Poetry でやっていたこと」をどう置き換えられるかを、実際のコマンドとともに紹介します。

## uvとは

uv は次のような機能を単体で提供します。

- 依存パッケージのインストールと解決（pip 相当）
- 仮想環境の作成・管理（venv 相当）
- ロックファイルによる再現性の担保（pip-tools / Poetry 相当）
- Python インタプリタ本体のインストールと切り替え（pyenv 相当）
- CLI ツールの一時実行・常設インストール（pipx 相当）

最大の特徴は速度です。依存解決とインストールが非常に速く、CI の待ち時間が体感で変わるレベルです。また、キャッシュを共有するため、2回目以降のセットアップはさらに短くなります。

設定は `pyproject.toml` を中心に扱うため、PEP 621 に沿ったモダンな構成と相性が良いのも利点です。

## インストール

インストールは OS ごとにいくつかの手段があります。

```bash
# 公式スクリプト（macOS / Linux）
curl -LsSf https://astral.sh/uv/install.sh | sh

# Homebrew
brew install uv

# pipx 経由
pipx install uv
```

Windows の場合は PowerShell 用のスクリプトや `winget`、`scoop` も用意されています。

インストール後はバージョンを確認しておきましょう。

```bash
uv --version
```

## プロジェクトを作る

新規プロジェクトは `uv init` で始めます。

```bash
uv init my-app
cd my-app
```

生成される主なファイルは次のとおりです。

- `pyproject.toml` — プロジェクトのメタ情報と依存関係
- `main.py` — サンプルコード
- `.python-version` — 使用する Python のバージョン
- `README.md`

`pyproject.toml` には `[project]` セクションが作られ、ここに依存関係が追加されていきます。

## 依存パッケージを追加する

パッケージの追加は `uv add` です。`pip install` のように仮想環境を手動で有効化する必要はありません。

```bash
uv add requests
```

開発用の依存は `--dev` を付けます。

```bash
uv add --dev pytest ruff
```

これだけで、仮想環境の作成、依存の解決、インストール、`pyproject.toml` と `uv.lock` の更新までが一括で行われます。

依存を削除するときは `uv remove` です。

```bash
uv remove requests
```

## コードを実行する

`uv run` を使うと、仮想環境を明示的に activate しなくてもコマンドを実行できます。

```bash
uv run main.py
uv run pytest
uv run ruff check .
```

`uv run` は実行前に依存関係の同期を確認してくれるため、「インストールし忘れて動かない」という事故が減ります。スクリプト内で追加の依存を宣言できるインラインスクリプトメタデータにも対応しており、ちょっとした使い捨てスクリプトに向いています。

```python
# /// script
# dependencies = ["httpx"]
# ///
import httpx

print(httpx.get("https://example.com").status_code)
```

```bash
uv run script.py
```

## ロックファイルと再現性

uv は `uv.lock` を生成し、依存関係を厳密に固定します。このファイルは Git にコミットするのが基本です。

チーム開発や CI では、ロックファイルどおりに環境を再現する `uv sync` を使います。

```bash
uv sync
```

CI などで「ロックファイルを更新せず、書かれたとおりにだけインストールする」場合は `--frozen` を付けます。

```bash
uv sync --frozen
```

`uv sync` はデフォルトで余計なパッケージを削除して環境をロックファイルに合わせるため、環境のドリフトを防げます。

## Python本体のバージョンを管理する

uv は Python インタプリタ自体のインストールも行えます。pyenv を別途入れる必要がありません。

```bash
# 利用可能なバージョンを確認
uv python list

# 特定バージョンをインストール
uv python install 3.12

# プロジェクトで使うバージョンを固定
uv python pin 3.12
```

`uv python pin` は `.python-version` を更新します。プロジェクトごとにバージョンを切り替えられるため、複数プロジェクトの並行開発が楽になります。

## CLIツールを実行・インストールする

`uvx` を使うと、ツールを一時的に実行できます。pipx の `pipx run` に近い感覚です。

```bash
uvx ruff check .
uvx black --check .
```

常設で使いたいツールは `uv tool install` でインストールします。

```bash
uv tool install ruff
```

ツールは独立した環境にインストールされるため、プロジェクトの依存と衝突しません。

## 既存のpipワークフローとの互換性

既存プロジェクトへ段階的に導入したい場合、`uv pip` サブコマンドが便利です。pip とほぼ同じインターフェースで動作します。

```bash
uv venv
uv pip install -r requirements.txt
uv pip compile requirements.in -o requirements.txt
```

`requirements.txt` ベースの運用を続けながら、インストールだけ高速化する、といった移行が可能です。すべてを一度に置き換える必要がないのは導入のハードルを下げてくれます。

## Poetryから移行する場合のポイント

Poetry の `pyproject.toml` は独自の `[tool.poetry]` セクションを使います。uv は PEP 621 の `[project]` を前提とするため、移行時はメタ情報と依存関係の書き換えが必要です。

おおまかな流れは次のとおりです。

1. `pyproject.toml` を `[project]` 形式へ整理する
2. `uv lock` で `uv.lock` を生成する
3. `uv sync` で環境を作り直す
4. CI のコマンドを `uv sync --frozen` などに置き換える

依存関係のグループは `[dependency-groups]`（PEP 735）で管理できるため、開発用依存の扱いも整理しやすくなっています。

## CIでの利用例

GitHub Actions での最小構成は次のようになります。

```yaml
- uses: actions/checkout@v4
- uses: astral-sh/setup-uv@v5
- run: uv sync --frozen
- run: uv run pytest
```

`setup-uv` アクションはキャッシュも扱ってくれるため、2回目以降のジョブが大きく短縮されます。ロックファイルをコミットしておけば、ローカルと CI で同じ依存関係を再現できます。

## 注意しておきたい点

uv は非常に便利ですが、いくつか留意点もあります。

- **独自機能への依存**: `[tool.uv]` 固有の設定は他ツールでは解釈されません。チーム内で uv を使う前提を共有しておきましょう。
- **ロックファイルの差分**: `uv.lock` は更新頻度が高くなりがちです。レビュー時に差分が大きくなりやすいため、依存更新はまとめて行うと扱いやすくなります。
- **進化の速さ**: 機能追加が活発なぶん、バージョン間の挙動差が生まれることがあります。CI とローカルでバージョンを揃えておくと安全です。

## まとめ

uv は「Python の環境構築が面倒」という長年の課題に対して、速度と統合という2つの方向から答えるツールです。

- `uv init` / `uv add` / `uv run` でプロジェクト管理が完結する
- `uv.lock` と `uv sync --frozen` で再現性を確保できる
- `uv python` でインタプリタ、`uvx` でツールまで扱える
- `uv pip` 経由で既存ワークフローから段階的に移行できる

まずは小さなプロジェクトで `uv init` から試し、CI のセットアップ時間がどう変わるかを体感してみるのがおすすめです。一度使うと、pip と venv を手で叩く運用には戻りにくくなるはずです。
