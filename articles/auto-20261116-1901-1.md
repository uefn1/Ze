## はじめに

Pythonの開発環境といえば、長らく `pip` と `venv` の組み合わせが定番でした。しかしここ数年で、その常識を塗り替えるツールが一気に普及しています。Astral社が開発する **uv** です。

uvはRustで書かれたPythonのパッケージマネージャー兼プロジェクト管理ツールで、pipの代替として使えます。単に速いだけでなく、これまで複数のツールに分かれていた役割をひとつにまとめてくれる点が魅力です。

この記事では、uvを中心にした開発環境の作り方を、実際のコマンドとともに紹介します。

## uvが解決する「ツールが多すぎる」問題

従来のPython開発では、目的ごとに別のツールを使い分ける必要がありました。

| やりたいこと | 従来のツール |
| --- | --- |
| パッケージのインストール | pip |
| 仮想環境の作成 | venv / virtualenv |
| Python本体のバージョン管理 | pyenv |
| 依存関係の固定 | pip-tools / Poetry |
| タスク実行 | Makefile / invoke |
| CLIツールの一時実行 | pipx |

uvはこれらをほぼ1つでカバーします。覚えることが減り、設定ファイルも散らばりません。

## インストール

macOSやLinuxでは公式のインストールスクリプトを使います。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Homebrewを使う場合は次のとおりです。

```bash
brew install uv
```

WindowsではPowerShellからインストールできます。

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

インストール後はバージョンを確認しておきましょう。

```bash
uv --version
```

## Python本体もuvで管理する

uvはPythonインタプリタのインストールも行えます。pyenvを別途入れる必要はありません。

```bash
uv python install 3.13
uv python list
```

プロジェクトで使うバージョンを固定するには `pin` を使います。

```bash
uv python pin 3.13
```

これで `.python-version` が生成され、チーム内でバージョンを揃えやすくなります。

## プロジェクトを作る

新規プロジェクトは `uv init` で作成します。

```bash
uv init myapp
cd myapp
```

生成される主なファイルは次のとおりです。

- `pyproject.toml` — プロジェクト設定と依存関係
- `.python-version` — 使用するPythonのバージョン
- `README.md`
- `main.py`（アプリケーションの場合）

ライブラリを作る場合は `--lib` を付けます。

```bash
uv init --lib mylib
```

## 依存関係の追加と同期

パッケージの追加は `uv add` です。仮想環境の作成も自動で行われます。

```bash
uv add requests
uv add --dev pytest ruff
```

開発用の依存は `--dev` で分けておくと、本番環境に余計なパッケージが入りません。

追加した依存関係は `uv.lock` に固定されます。このファイルは**必ずGitにコミット**してください。CIや他の開発者が同じバージョンを再現するために必要です。

既存のプロジェクトに参加したときは、次のコマンドで環境を再現できます。

```bash
git clone https://github.com/example/myapp.git
cd myapp
uv sync
```

`uv sync` は `uv.lock` に基づいて仮想環境を作り、依存関係をインストールします。`pip install -r requirements.txt` を叩く必要はもうありません。

## スクリプトは uv run で実行する

仮想環境を明示的にactivateしなくても、`uv run` が適切な環境でコマンドを実行してくれます。

```bash
uv run main.py
uv run pytest
uv run python -c "import sys; print(sys.version)"
```

`source .venv/bin/activate` を忘れて「なぜかモジュールが見つからない」と悩む時間がなくなります。

よく使うコマンドは `pyproject.toml` にスクリプトとして登録できます。

```toml
[project.scripts]
myapp = "myapp.main:main"
```

## CLIツールを一時的に試す

ちょっとしたツールを試したいときは `uvx` が便利です。グローバル環境を汚さずに実行できます。

```bash
uvx ruff check .
uvx black --version
```

常に使うツールは `uv tool install` でインストールします。

```bash
uv tool install ruff
```

## RuffでLintとフォーマットを統一する

uvと同じAstral社が開発している **Ruff** は、非常に高速なリンター兼フォーマッターです。Flake8、isort、Blackなどの役割をまとめて担えます。

`pyproject.toml` に設定を書きます。

```toml
[tool.ruff]
line-length = 100
target-version = "py313"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B", "SIM"]
```

実行は次のとおりです。

```bash
uv run ruff check .
uv run ruff check --fix .
uv run ruff format .
```

`check` がLint、`format` がコード整形です。保存時に自動実行するようエディタと連携しておくと、レビューでスタイルの指摘をすることが減ります。

## CIに組み込む

GitHub Actionsでは公式の `setup-uv` アクションが使えます。

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v6
        with:
          enable-cache: true
      - run: uv sync --locked
      - run: uv run ruff check .
      - run: uv run ruff format --check .
      - run: uv run pytest
```

`uv sync --locked` を使うと、ロックファイルと `pyproject.toml` がずれている場合に失敗します。依存関係の更新漏れをCIで検出できるのでおすすめです。

## 移行時にハマりやすいポイント

実際に既存プロジェクトをuvへ移すときに注意したい点をまとめます。

### requirements.txt からの移行

`uv add` で1つずつ追加するか、`uv pip install -r requirements.txt` で一時的に読み込んでから `uv add` へ移行します。移行後は `requirements.txt` を削除し、`uv.lock` を正とするのがシンプルです。

### 社内インデックスの設定

プライベートパッケージを使っている場合は、インデックスを設定します。

```toml
[[tool.uv.index]]
name = "internal"
url = "https://pypi.example.com/simple"
explicit = true
```

`explicit = true` を付けると、そのインデックスは明示的に指定したパッケージにだけ使われます。意図しないパッケージが社内インデックスへ問い合わせられるのを防げます。

### ロックファイルはコミットする

`uv.lock` を `.gitignore` に入れてしまう例を見かけますが、アプリケーションではコミットが基本です。ライブラリの場合も、CIでの再現性のためにコミットしておくと安全です。

## まとめ

uvは「速いpip」としてだけでなく、Python開発の入口をひとつにまとめるツールです。

- `uv python install` でPython本体を管理
- `uv init` でプロジェクト作成
- `uv add` / `uv sync` で依存関係を管理
- `uv run` でactivate不要の実行
- `uvx` でCLIツールを試す

まずは小さなプロジェクトで `uv init` から試してみてください。`uv.lock` と `uv run` に慣れると、従来のワークフローには戻りにくくなるはずです。
