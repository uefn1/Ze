新しい開発ツールは毎週のように登場しますが、実際に日常の開発へ定着するものは多くありません。本記事では、導入のハードルが低く、既存のワークフローへ自然に組み込めるツールを5つ紹介します。

## 選定のポイント

ツールを選ぶ際は、次の観点を重視しました。

- 既存の言語やエディタと組み合わせやすい
- 起動・実行が速く、待ち時間が少ない
- 設定ファイルがシンプルで、チームへ展開しやすい
- 特定のサービスへ過度に依存しない

もちろん、チームの技術スタックによって最適解は異なります。気になったものは小規模なリポジトリで試すところから始めるのがおすすめです。

## 1. Bun — JavaScript/TypeScriptの実行環境をまとめる

BunはJavaScript/TypeScript向けのオールインワンランタイムです。パッケージマネージャ、バンドラ、テストランナーが一体になっており、複数のツールを別々に設定する手間を減らせます。

```bash
bun init
bun add -d typescript
bun test
```

TypeScriptをそのまま実行できるため、小さなスクリプトやCLIツールの作成が快適です。Node.jsとの互換性も向上していますが、ネイティブモジュールや一部APIの挙動は異なる場合があります。本番導入前に対象プロジェクトで検証しましょう。

## 2. Biome — LintとFormatを1つに

BiomeはRust製のリンタ・フォーマッタです。JavaScript/TypeScriptやJSONを中心に、LintとFormatを高速に実行できます。

```bash
biome check --write .
```

ESLintとPrettierの設定が複雑になりがちなプロジェクトでは、設定を1か所にまとめられるのが魅力です。エディタ連携も用意されており、保存時の自動整形とCIでのチェックを同じ設定で運用できます。既存プロジェクトへ導入する場合は、まずルールを最小限にして差分を確認すると安全です。

## 3. uv — Pythonの依存管理を高速化する

uvはAstralが開発するPythonのパッケージ・プロジェクト管理ツールです。依存解決とインストールが高速で、ロックファイルによる再現性のある環境構築ができます。

```bash
uv init my-app
uv add requests
uv run python main.py
```

Python本体のバージョン管理もできるため、ローカルとCIで同じ環境を用意しやすくなります。仮想環境の作成や依存の追加をコマンドで統一できる点も、チーム開発に向いています。

## 4. Zed — 軽快さを重視したコードエディタ

ZedはRust製のコードエディタです。起動や入力のレスポンスが軽く、LSPやTree-sitterによる補完・構文解析を備えています。共同編集機能もあり、ペアプログラミングやレビューの場面で活用できます。

VS Codeのような拡張機能の豊富さはまだ及ばない部分があるため、利用する言語の対応状況は事前に確認してください。一方で、エディタ自体の動作の軽さを重視する人には有力な選択肢です。

## 5. Ollama — ローカルでLLMを動かす

Ollamaは、ローカル環境で大規模言語モデルを実行するためのツールです。CLIからモデルを取得してすぐに試せる手軽さが特徴です。

```bash
ollama run llama3
```

ローカルで完結するため、コードや文章を外部サービスへ送りたくない場面に向いています。OpenAI互換のAPIを備えており、既存のツールから接続しやすいのも利点です。ただし、モデルのサイズによっては相応のメモリとGPU性能が必要になります。

## 組み合わせの例

たとえば、TypeScriptのプロジェクトではBunとBiomeを、Pythonの処理ではuvを使い、エディタはZed、ローカルLLMはOllamaという構成が考えられます。すべてを一度に導入する必要はありません。まずは1つだけ導入し、効果を確認してから広げていくと定着しやすくなります。

## 導入時の注意点

- ロックファイルは必ずリポジトリへコミットする
- ローカルとCIで同じツールバージョンを使う
- ライセンスやセキュリティポリシーを確認する
- チーム内で設定ファイルの管理ルールを決める

## まとめ

開発ツールは、流行を追うこと自体が目的ではありません。日々の待ち時間や設定の手間を減らし、本来の実装に集中できる環境を作ることが重要です。

今回紹介した5つは、いずれも小さく試せて効果を実感しやすいものばかりです。気になるツールがあれば、まずは手元のプロジェクトで1つだけ導入してみてください。

ターミナルでの開発では、`grep` で検索し、`find` でファイルを探し、`cd` でディレクトリを移動し、`cat` でファイルを確認する——この繰り返しに地味な時間が積み重なります。本記事では、こうした基本操作を高速化・快適化する定番CLIツールを5つ紹介します。

いずれも既存コマンドの完全な置き換えではなく、対話的な作業を補助する道具です。まずは1つだけ試し、手に合うものから日常へ取り入れていくのがおすすめです。

## なぜモダンCLIツールに置き換えるのか

従来のコマンドは、あらゆる環境で動くという強みがある一方、次のような点で不便を感じることがあります。

- `grep` は `.gitignore` を考慮せず、ビルド成果物まで検索してしまう
- `find` のオプションが独特で、とっさに思い出せない
- `cd` は深い階層のパスを毎回入力する必要がある
- `cat` は長いファイルやバイナリを見ると端末が崩れる

モダンCLIツールは、これらの課題をシンプルなインターフェースと高速な実装で解決します。RustやGoで書かれたものが多く、起動が軽いのも魅力です。

## 1. ripgrep — `.gitignore` を理解する高速検索

ripgrep（コマンド名は `rg`）は、コードベースの検索に特化した高速な検索ツールです。デフォルトで `.gitignore` を尊重し、バイナリファイルや隠しファイルを自動的に除外します。

```bash
rg "TODO"
rg -t py "requests"
rg -l "deprecated" src/
rg --hidden -g '!node_modules' "apiKey"
```

`-t` で言語を指定でき、`-l` でファイル名だけを表示できます。`.gitignore` を無視したい場合は `--no-ignore`、隠しファイルも対象にするなら `--hidden` を付けます。

インストールはパッケージマネージャから行えます。

```bash
brew install ripgrep
# Debian/Ubuntu
sudo apt install ripgrep
# Rust環境がある場合
cargo install ripgrep
```

## 2. fd — 直感的なファイル検索

fd は `find` の代替となるファイル検索ツールです。構文がシンプルで、デフォルトで `.gitignore` を尊重し、結果を色付きで表示します。

```bash
fd config
fd -e ts
fd -e md -x wc -l
fd -t d src
```

`-e` は拡張子、`-t d` はディレクトリのみ、`-x` は見つかったファイルに対してコマンドを実行します。`find` のように `-name` や `-type` を組み合わせる必要がなく、意図がそのまま書けるのが利点です。

```bash
brew install fd
# Debian/Ubuntu では fd-find パッケージ。コマンド名は fdfind
sudo apt install fd-find
```

Debian/Ubuntuではバイナリ名が `fd` ではなく `fdfind` になる点に注意してください。必要であればエイリアスを設定します。

```bash
alias fd='fdfind'
```

## 3. fzf — あいまい検索で一覧から選ぶ

fzf は、標準入力の一覧をあいまい検索して選択できるツールです。単体でも便利ですが、他のコマンドとパイプで組み合わせると真価を発揮します。

```bash
fd -e ts | fzf
vim "$(fd -e ts | fzf)"
git branch | fzf
```

シェル連携を有効にすると、`Ctrl-T` でファイル選択、`Ctrl-R` でコマンド履歴検索、`Alt-C` でディレクトリ移動ができるようになります。

```bash
# bash の場合
eval "$(fzf --bash)"
# zsh の場合
source <(fzf --zsh)
```

`fd` と組み合わせれば、「候補を絞り込んでから選ぶ」という操作を高速化できます。パスの入力ミスも減るため、日常的な効果が大きいツールです。

## 4. zoxide — 学習するディレクトリ移動

zoxide（コマンド名は `z`）は、訪問したディレクトリを記録し、部分的な名前から移動できるツールです。`cd` の完全上位互換として使えます。

```bash
z proj
z src
z ..
zi
```

`z proj` のように一部の名前を渡すだけで、よく使うディレクトリへ移動できます。`zi` は fzf と連携した対話的な選択です。履歴はローカルに保存され、使うほど精度が上がります。

```bash
brew install zoxide
# シェルへ初期化を追加
eval "$(zoxide init bash)"
# zsh の場合
eval "$(zoxide init zsh)"
```

初期化の設定を `.bashrc` や `.zshrc` に追加し忘れると、`z` コマンドが使えないので注意してください。

## 5. bat — シンタックスハイライト付きのcat

bat は `cat` の代替で、シンタックスハイライト、行番号、Git差分の表示に対応しています。長いソースコードや設定ファイルの確認が格段に読みやすくなります。

```bash
bat main.ts
bat -n main.ts
bat -A .env.example
bat --diff README.md
```

`-n` は行番号のみ、`-A` は不可視文字の表示、`--diff` はGitの差分を強調します。パイプで使うとハイライトが無効になるため、その場合は `--plain` を指定します。

```bash
brew install bat
# Debian/Ubuntu ではコマンド名が batcat になる場合がある
sudo apt install bat
```

Debian/Ubuntuでは `batcat` という名前でインストールされることがあります。`alias bat='batcat'` などで調整するとよいでしょう。

## 組み合わせの例

これらは単独でも便利ですが、組み合わせると作業の流れが変わります。

```bash
# 変更されたTypeScriptファイルを選んで開く
git diff --name-only -- '*.ts' | fzf | xargs -r bat

# 設定ファイルを探してから中身を確認する
fd -e json | fzf | xargs -r bat
```

検索（`rg` / `fd`）、選択（`fzf`）、移動（`z`）、表示（`bat`）という役割を意識すると、パイプでの組み合わせが考えやすくなります。

## 導入時の注意点

- シェルの設定ファイルへ追記した後は、再読み込みか再ログインを忘れずに行う
- `grep` や `cat` をエイリアスで置き換える場合、オプションの差異で壊れるスクリプトがないか確認する
- チームで共有するスクリプトやCIでは、これらのツールに依存しない
- パッケージ名とコマンド名が異なる場合があるため、`--version` で動作確認する

特に `grep` を `rg` にエイリアスすると、`-E` や `-r` など一部オプションの挙動が異なり、思わぬ失敗につながります。対話的な利用に限定するのが安全です。

## まとめ

ターミナル作業の高速化は、特別な設定よりも「毎日使うコマンドを少し快適にする」ことの積み重ねで効果が出ます。

今回紹介した5つは、いずれも導入が簡単で、既存のワークフローを大きく変えずに試せます。まずは `ripgrep` か `fzf` から始め、効果を感じたら `fd`、`zoxide`、`bat` へ広げてみてください。
