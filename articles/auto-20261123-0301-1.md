## はじめに

近年の開発ツールは「Rust や Zig で書き直す」という流れが定着し、`pip` や `ESLint`、`Prettier` といった定番ツールの代替が実用段階に入っています。本記事では、日々の開発で効果が大きい **uv / Ruff / Biome / Bun** を取り上げ、それぞれの役割と使いどころを整理します。

「全部入れ替える」必要はありません。ボトルネックになっている工程から一つずつ置き換えるのが現実的です。

## なぜ「速いツール」に置き換えるのか

CI の待ち時間やローカルのフィードバック速度は、開発体験に直結します。特に次の3点で効果が出ます。

- **依存解決・インストール**が数秒〜数十秒単位で短縮される
- **lint / format** がファイル保存のたびに走ってもストレスにならない
- **設定ファイルの集約**により、ツール間のルール衝突や二重管理が減る

速度だけでなく、設定のシンプルさも副次的なメリットになります。

## uv — Python の依存管理を一本化する

uv は Astral 製の Python パッケージ・プロジェクトマネージャです。`pip` / `venv` / `pipx` / `pyenv` の役割をまとめて担い、Rust 実装による高速さが特徴です。

```bash
# プロジェクト作成（pyproject.toml と .venv を用意）
uv init myapp
cd myapp

# 依存追加（ロックファイル uv.lock も更新）
uv add requests

# 仮想環境を意識せずコマンド実行
uv run python main.py

# ロックファイルに沿って同期
uv sync
```

ポイントは **`uv run` で仮想環境の activate が不要**になることです。CI でも `uv sync --frozen` のようにロックを固定でき、再現性を保ちやすくなります。

## Ruff — lint と format を1ツールに

Ruff も Astral 製で、Python のリンタ兼フォーマッタです。`flake8`・`isort`・`black` などの役割を1つにまとめ、設定は `pyproject.toml` に集約できます。

```toml
# pyproject.toml
[tool.ruff]
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]
```

```bash
ruff check .        # lint
ruff check . --fix  # 自動修正
ruff format .       # フォーマット
```

flaky なプラグイン依存が減り、**lint と format のルールが同じ設定ファイルで管理できる**のが実務上の利点です。

## Biome — JS/TS の lint と format を統合

Biome は JavaScript / TypeScript 向けのリンタ兼フォーマッタで、Rust 実装です。`biome.json` 一つで lint と format を扱えます。

```bash
bunx @biomejs/biome init
bunx @biomejs/biome check --write .
```

ただし **ESLint の全プラグインを置き換えられるわけではありません**。フレームワーク固有のルールや独自プラグインに依存している場合は、まずは formatter だけ Biome に寄せる、といった段階的な移行が安全です。

## Bun — ランタイム・パッケージマネージャ・テストをまとめる

Bun は JavaScript ランタイムで、パッケージマネージャやテストランナー、バンドラも内包します。Zig 実装で、起動とインストールが高速です。

```bash
bun install          # 依存インストール
bun run dev          # package.json のスクリプト実行
bun test             # テスト
bun x create-vite    # 一時実行
```

Node.js との互換性は向上していますが、ネイティブアドオンや一部 API の挙動差は残ります。**新規プロジェクトやスクリプト用途から試す**のが無難です。

## 導入時の注意点

- **ロックファイルは必ずコミットする**（`uv.lock`、`bun.lock` など）。再現性の要です。
- **CI のキャッシュ設定を見直す**。高速化ツールはキャッシュのキー設計も変わります。
- **一気に全部置き換えない**。まず formatter、次に linter、最後にランタイム、の順が安全です。
- **チームの合意を取る**。特に Bun はランタイム変更を伴うため、影響範囲を共有しましょう。

## まとめ

| ツール | 主な役割 | 置き換え対象の例 |
| --- | --- | --- |
| uv | Python 依存管理 | pip / venv / pipx |
| Ruff | Python lint・format | flake8 / isort / black |
| Biome | JS/TS lint・format | ESLint / Prettier（一部） |
| Bun | JS ランタイム・実行環境 | npm / jest（一部） |

どれも「速い」だけでなく、**設定を減らせる**点が長期的な保守性に効きます。まずは開発体験が一番重い工程を一つ選び、小さく試してみてください。
