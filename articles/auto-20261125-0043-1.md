## はじめに

Pythonの開発環境といえば、長らく `pip` と `venv` の組み合わせが定番でした。しかし、依存関係の解決が遅い、ロックファイルがない、Python本体のバージョン管理は別ツールが必要、といった課題もあります。

そこで注目されているのが、Astralが開発している **uv** です。Rust製の高速なパッケージマネージャーで、pipやvenvの操作を置き換えつつ、プロジェクト管理やPythonバージョン管理まで一貫して扱えます。

この記事では、uvの基本から実践的な使い方までを紹介します。

## uvとは

uvは、次のような機能をひとつにまとめたPython向けツールです。

- pip互換のパッケージインストール
- 仮想環境の作成
- 依存関係の解決とロックファイル生成
- Pythonインタプリタのインストールと切り替え
- スクリプトの実行
- CLIツールのグローバルインストール

特に嬉しいのは、`pyproject.toml` と `uv.lock` を中心に、プロジェクトの依存関係を再現可能な形で管理できる点です。

## インストール

macOSやLinuxでは、公式のインストーラーを使うのが簡単です。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Homebrewを使う場合は次のとおりです。

```bash
brew install uv
```

pipx経由でインストールすることもできます。

```bash
pipx install uv
```

インストール後、バージョンを確認します。

```bash
uv --version
```

## プロジェクトを始める

新しいプロジェクトを作るには `uv init` を実行します。

```bash
uv init my-app
cd my-app
```

生成される主なファイルは次のとおりです。

```text
my-app/
├── .python-version
├── README.md
├── pyproject.toml
└── src/
    └── my_app/
        └── __init__.py
```

`pyproject.toml` にプロジェクト情報と依存関係がまとまり、`.python-version` で使用するPythonのバージョンを固定できます。

## 依存関係を追加する

パッケージを追加するときは `uv add` を使います。

```bash
uv add requests
```

開発用の依存関係は `--dev` を付けます。

```bash
uv add --dev pytest ruff
```

`uv add` を実行すると、`pyproject.toml` の更新、仮想環境の作成、パッケージのインストール、`uv.lock` の生成までが自動で行われます。

## 依存関係を同期する

リポジトリを clone した直後など、ロックファイルに沿って環境を再現するには `uv sync` を使います。

```bash
uv sync
```

`uv.lock` があるため、チームメンバーやCI環境でも同じ依存関係を再現しやすくなります。

CIでは、ロックファイルの更新を禁止する `--frozen` を付けると安全です。

```bash
uv sync --frozen
```

## コマンドを実行する

仮想環境を明示的に activate しなくても、`uv run` でプロジェクト内のコマンドを実行できます。

```bash
uv run python main.py
uv run pytest
uv run ruff check .
```

仮想環境の有効化を忘れる心配がなく、CIでもそのまま使えるのが便利です。

## Pythonのバージョンを管理する

uvはPython本体のインストールも扱えます。

```bash
uv python install 3.12
uv python list
```

プロジェクトで使うバージョンを固定する場合は次のようにします。

```bash
uv python pin 3.12
```

これにより `.python-version` が更新され、チーム内でPythonのバージョンを揃えやすくなります。

## CLIツールをインストールする

`ruff` や `httpie` のようなCLIツールは `uv tool install` で管理できます。

```bash
uv tool install ruff
uv tool install httpie
```

一時的にツールを実行したいだけなら `uvx` が便利です。

```bash
uvx ruff check .
```

`uvx` はツールを一時的な環境で実行するため、グローバル環境を汚さずに試せます。

## 既存プロジェクトをuvへ移行する

すでに `requirements.txt` があるプロジェクトでは、まず `pyproject.toml` を用意します。

```bash
uv init --bare
```

その後、依存関係を追加していきます。

```bash
uv add -r requirements.txt
```

pip互換のコマンドも用意されているため、段階的な移行も可能です。

```bash
uv venv
uv pip install -r requirements.txt
```

すべてを一度に置き換えるのではなく、まずはローカル開発で試し、問題がなければCIへ広げるのがおすすめです。

## 使うときの注意点

uvは非常に高速ですが、既存のpip環境と完全に同じ挙動を期待する場合は注意が必要です。

- `uv pip` はpip互換だが、プロジェクト管理は `uv add` / `uv sync` を使う
- CIでは `uv.lock` をコミットし、`--frozen` を検討する
- 社内レジストリや認証設定が必要な場合は、pipの設定を確認する
- チーム内でuvのバージョンを揃える

特に、`uv pip install` と `uv add` は目的が異なります。プロジェクトの依存関係として管理するなら `uv add`、一時的なpip互換操作なら `uv pip` と使い分けましょう。

## まとめ

uvは、Pythonのパッケージ管理、仮想環境、バージョン管理、スクリプト実行をまとめて扱えるツールです。

まずは次の流れで試してみてください。

```bash
uv init my-app
cd my-app
uv add requests
uv run python -c "import requests; print(requests.__version__)"
```

pipとvenvの煩わしさを減らしつつ、再現性の高い開発環境を作りたいときに、uvは有力な選択肢になります。
