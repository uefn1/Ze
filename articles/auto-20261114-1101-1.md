## はじめに

ここ数年、JavaScript界隈ではRustやGoで書き直された高速ツールが次々と登場し、開発体験を大きく変えてきました。同じ波はPythonにも押し寄せています。その代表格が、Astral社が開発する **uv** です。

uvはRust製のPythonパッケージマネージャーで、pip・virtualenv・pip-tools・Poetryなどが担ってきた役割を、ひとつのCLIに統合することを目指しています。とにかく速く、ロックファイルによる再現性も確保できるのが特徴です。

この記事では、uvの基本概念から実際のコマンド、既存プロジェクトへの導入ポイントまでを一通り紹介します。

## uvで何が変わるのか

従来のPython開発では、用途ごとにツールが分かれていました。

- 仮想環境の作成 → `python -m venv`
- パッケージのインストール → `pip`
- 依存関係の固定 → `pip-tools` や `Poetry`
- Python本体のバージョン管理 → `pyenv` など
- CLIツールの一時実行 → `pipx`

uvはこれらを1つのコマンド体系にまとめます。しかもRust実装による高速化と、グローバルキャッシュによるディスク効率の良さを両立しています。

| 用途 | 従来 | uv |
| --- | --- | --- |
| プロジェクト初期化 | 手動 | `uv init` |
| 依存追加 | `pip install` | `uv add` |
| 環境同期 | `pip install -r` | `uv sync` |
| スクリプト実行 | 手動でvenv有効化 | `uv run` |
| Python本体管理 | pyenv等 | `uv python install` |
| CLIツール実行 | pipx | `uvx` |

## インストール

公式のインストーラーを使うのが手軽です。

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Homebrewやpipx経由でも導入できます。インストール後は `uv --version` で確認しましょう。

## プロジェクトを作ってみる

まずは新規プロジェクトの作成から。

```bash
uv init my-app
cd my-app
```

`uv init` を実行すると、`pyproject.toml` とサンプルスクリプト、そして `.python-version` などが生成されます。続けて依存パッケージを追加します。

```bash
uv add requests
```

このコマンド一発で、依存関係の解決・仮想環境の作成・インストール・ロックファイル（`uv.lock`）の更新までが行われます。`pyproject.toml` には依存が追記され、`uv.lock` には解決済みのバージョンが記録されます。

### 同期と実行

リポジトリをクローンしたら、まず環境を同期します。

```bash
uv sync
```

`uv.lock` に基づいて、誰の環境でも同じ依存関係が再現されます。スクリプトの実行は `uv run` を使えば、仮想環境を明示的に有効化する必要がありません。

```bash
uv run python main.py
```

## 既存プロジェクトへ導入する

すでに `requirements.txt` がある場合は、pip互換のインターフェースが便利です。

```bash
uv venv
uv pip install -r requirements.txt
```

`uv venv` で仮想環境を作り、`uv pip` でpipと同じ感覚でインストールできます。既存のワークフローを大きく変えずに、速度の恩恵だけを受けたい場合に向いています。

## Python本体のバージョンも管理できる

uvはインタプリタの管理もこなします。

```bash
uv python install 3.12
uv python list
```

プロジェクトごとに使うバージョンを固定したいときは、`.python-version` を用意しておけば `uv sync` 時に適切なインタプリタが使われます。pyenvを別途入れる必要がなくなるのは嬉しいポイントです。

## スクリプトを単体で動かす

ちょっとしたスクリプトに依存を埋め込みたいときは、PEP 723のインライン依存メタデータが使えます。

```python
# /// script
# requires-python = ">=3.11"
# dependencies = ["httpx"]
# ///
import httpx

print(httpx.get("https://example.com").status_code)
```

これを `uv run script.py` で実行すると、uvが必要な依存を一時環境に用意してくれます。使い捨ての検証には非常に便利です。

## uvxでCLIツールを試す

グローバル環境を汚さずにツールを実行したいときは `uvx` が使えます。

```bash
uvx ruff check .
uvx httpie GET https://example.com
```

pipxに近い体験ですが、初回以降はキャッシュが効くため起動が高速です。

## 導入時の注意点

uvは非常に便利ですが、いくつか押さえておきたい点もあります。

- **ロックファイルはコミットする**：`uv.lock` をバージョン管理に含めることで再現性が保てます。
- **CIでのキャッシュ**：GitHub Actionsなどではuv用のキャッシュを設定すると効果的です。
- **チームの合意**：Poetryなどから移行する場合は、コマンド体系が変わるためチーム内でルールを揃えましょう。
- **エコシステムの成熟度**：急速に進化しているツールなので、定期的にドキュメントを確認するのがおすすめです。

## まとめ

uvは「速い」だけでなく、Python開発の散らばりがちなツール群をひとつにまとめてくれる点が本質的な魅力です。新規プロジェクトなら最初から採用し、既存プロジェクトでも `uv pip` から段階的に試す、という入り方が現実的でしょう。

Rust製ツールによる開発体験の改善は、もはやJavaScriptだけの話ではありません。Pythonを書く人こそ、一度uvを触ってみてください。その速度と統合された体験に、きっと驚くはずです。
