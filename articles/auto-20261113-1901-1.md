## はじめに

ここ数年で、開発ツールの世界は静かに、しかし確実に塗り替えられてきました。その中心にあるのが **Rust製（あるいはGo製）のCLIツール**です。

Pythonの `pip` と `virtualenv`、JavaScriptの `ESLint` と `Prettier`、バンドラの `webpack`。長年使われてきたこれらのツールは、いま同じ役割をより高速に果たす代替品へと置き換えが進んでいます。

この記事では、実際に導入しやすいツールを「言語・役割」ごとに整理し、それぞれの使いどころと注意点をまとめます。特定のバージョンに依存した話ではなく、考え方と導入手順を中心に解説します。

## なぜRust製ツールが選ばれるのか

理由はシンプルです。

- **とにかく速い**。起動時間が短く、大規模リポジトリでもリントやフォーマットがストレスにならない
- **単一バイナリで配布できる**。Node.jsやPythonのランタイムを介さず動くため、環境差異が小さい
- **設定を引き継げる**。既存ツールの設定ファイルやルールをある程度そのまま読めるものが多い

「速い」ことは単なる快適さにとどまりません。保存のたびに走るフォーマッタが一瞬で終われば、開発者は待ち時間を意識しなくなります。CIのリントが数十秒縮めば、レビューの回転が上がります。小さな改善の積み重ねが、チーム全体の生産性に効いてきます。

## Python——uv と Ruff

### uv：パッケージ管理と仮想環境を一つに

`uv` は Astral が開発するPythonのパッケージマネージャです。`pip`、`pip-tools`、`virtualenv`、`pipx` の役割をまとめて担い、依存解決とインストールが非常に高速です。

導入はシンプルです。

```bash
# インストール（公式スクリプト）
curl -LsSf https://astral.sh/uv/install.sh | sh

# プロジェクト初期化
uv init my-project
cd my-project

# 依存追加
uv add requests

# 仮想環境込みでコマンド実行
uv run python main.py
```

`uv.lock` によって依存が固定されるため、CIや本番環境でも再現性が保てます。`uv sync` でロックファイルどおりに環境を揃えられるのは、チーム開発で大きな利点です。

### Ruff：リントとフォーマットを一本化

`Ruff` も同じくAstral製で、`flake8`、`isort`、`pyupgrade`、そして `black` 相当のフォーマットをまとめて扱えます。

```toml
# pyproject.toml
[tool.ruff]
line-length = 100
target-version = "py312"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]
```

```bash
ruff check --fix .
ruff format .
```

従来は複数のツールを組み合わせて設定していたものが、一つの設定ファイルに集約できます。ルールの互換性が完全ではないため、移行時は `ruff check` の差分を確認しながら段階的に適用するのが安全です。

## JavaScript / TypeScript——Biome と Oxc

### Biome：LintとFormatを一つのツールで

`Biome` はRust製で、ESLintとPrettierの役割を兼ねます。設定は `biome.json` にまとまり、`biome check` でリント・フォーマット・import整理をまとめて実行できます。

```json
{
  "formatter": { "indentStyle": "space", "indentWidth": 2 },
  "linter": { "enabled": true },
  "organizeImports": { "enabled": true }
}
```

```bash
npx @biomejs/biome check --write .
```

ESLintのプラグインエコシステムは非常に広いため、すべてのルールを置き換えられるわけではありません。フレームワーク固有のルールに強く依存しているプロジェクトでは、まずフォーマッタだけBiomeに任せる、といった段階的な導入が現実的です。

### Oxc：パーサとツールチェーンの土台

`Oxc` はJavaScript/TypeScript向けのRust製パーサおよびツール群です。単体で使うというより、リンタやミニファイア、変換器の基盤として注目されています。エコシステムの内部で採用が進んでいるため、開発者が直接触る機会は少なくても、間接的に恩恵を受ける場面は増えています。

## ビルドツール——Rspack / Rolldown / Turbopack

バンドラの世界もRust製が主流になりつつあります。

- **Rspack**：webpack互換を意識した高速バンドラ。既存のwebpack設定からの移行がしやすい
- **Rolldown**：Rollup互換を目指すRust製バンドラ。Viteの内部での採用が進む
- **Turbopack**：Next.jsと組み合わせて使われる高速バンドラ

特にRspackは、webpackのローダーやプラグインに近い概念を保っているため、大規模な既存プロジェクトでも移行コストを抑えやすいのが特徴です。ビルド時間が長いプロジェクトほど、投資対効果は大きくなります。

## ランタイム——Bun と Deno

### Bun

`Bun` はJavaScript/TypeScriptのランタイムで、バンドラ、テストランナー、パッケージマネージャを統合しています。Node.js互換を志向しており、`bun install` や `bun test` をそのまま試せます。

```bash
bun install
bun run dev
bun test
```

ツールをまたいで設定が散らばりがちなJSプロジェクトでは、一つにまとまる恩恵は大きいです。ただしNode.js固有のAPIやネイティブモジュールへの依存がある場合は、事前に検証しておきましょう。

### Deno

`Deno` はセキュリティを重視した設計で、権限を明示的に与える方式を採ります。TypeScriptをそのまま実行でき、標準ツール（`deno fmt`、`deno lint`、`deno test`）が最初から揃っている点が特徴です。

## 導入時のチェックリスト

高速化は魅力的ですが、闇雲に置き換えるとハマります。導入前に次を確認しておくと安全です。

1. **互換性**：既存の設定ファイルやルールをどこまで読めるか
2. **CIの再現性**：ロックファイルがコミットされているか
3. **エディタ連携**：VS Code拡張やLSPが該当ツールに対応しているか
4. **エコシステム**：必要なプラグインが存在するか
5. **ロールバック手段**：元のツールに戻せる状態を保っているか

最初からすべてを置き換えるのではなく、**フォーマッタ → リンタ → パッケージ管理** の順で、影響の小さいところから試すのがおすすめです。

## まとめ

Rust製ツールの共通点は「速い」だけではありません。設定の集約、単一バイナリでの配布、既存ツールとの互換性への配慮など、日々の開発体験を静かに改善してくれる設計が詰まっています。

まずは自分のプロジェクトで一番時間がかかっている工程を洗い出し、そこに合うツールを一つだけ試してみてください。フォーマッタの一瞬の応答や、CIの短縮された待ち時間が、開発のリズムを変えてくれるはずです。
