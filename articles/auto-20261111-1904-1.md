新しい開発ツールは毎週のように登場しますが、実際に日常の開発へ定着するものは多くありません。本記事では、導入のハードルが低く、既存のワークフローへ自然に組み込めるツールを5つ紹介します。

## 選定のポイント

ツールを選ぶ際は、次の観点を重視しました。

- 既存の言語やエディタと組み合わせやすい
- 起動・実行が速く、待ち時間が少ない
- 設定ファイルがシンプルで、チームへ展開しやすい
- 特定のサービスへ過度に依存しない

もちろん、チームの技術スタックによって最適解は異なります。気になったものは小規模なリポジトリで試すところから始めるのがおすすめです。

## 1. Bun — JavaScript/TypeScriptの実行環境をまとめる

BunはJavaScript/TypeScript向けのオールインワンランタイムです。パッケージマネージャ、バンドラ、テストランナーが一体になっており、複数のツールを別々に設定する手間を減らせます。

```bash
bun init
bun add -d typescript
bun test
```

TypeScriptをそのまま実行できるため、小さなスクリプトやCLIツールの作成が快適です。Node.jsとの互換性も向上していますが、ネイティブモジュールや一部APIの挙動は異なる場合があります。本番導入前に対象プロジェクトで検証しましょう。

## 2. Biome — LintとFormatを1つに

BiomeはRust製のリンタ・フォーマッタです。JavaScript/TypeScriptやJSONを中心に、LintとFormatを高速に実行できます。

```bash
biome check --write .
```

ESLintとPrettierの設定が複雑になりがちなプロジェクトでは、設定を1か所にまとめられるのが魅力です。エディタ連携も用意されており、保存時の自動整形とCIでのチェックを同じ設定で運用できます。既存プロジェクトへ導入する場合は、まずルールを最小限にして差分を確認すると安全です。

## 3. uv — Pythonの依存管理を高速化する

uvはAstralが開発するPythonのパッケージ・プロジェクト管理ツールです。依存解決とインストールが高速で、ロックファイルによる再現性のある環境構築ができます。

```bash
uv init my-app
uv add requests
uv run python main.py
```

Python本体のバージョン管理もできるため、ローカルとCIで同じ環境を用意しやすくなります。仮想環境の作成や依存の追加をコマンドで統一できる点も、チーム開発に向いています。

## 4. Zed — 軽快さを重視したコードエディタ

ZedはRust製のコードエディタです。起動や入力のレスポンスが軽く、LSPやTree-sitterによる補完・構文解析を備えています。共同編集機能もあり、ペアプログラミングやレビューの場面で活用できます。

VS Codeのような拡張機能の豊富さはまだ及ばない部分があるため、利用する言語の対応状況は事前に確認してください。一方で、エディタ自体の動作の軽さを重視する人には有力な選択肢です。

## 5. Ollama — ローカルでLLMを動かす

Ollamaは、ローカル環境で大規模言語モデルを実行するためのツールです。CLIからモデルを取得してすぐに試せる手軽さが特徴です。

```bash
ollama run llama3
```

ローカルで完結するため、コードや文章を外部サービスへ送りたくない場面に向いています。OpenAI互換のAPIを備えており、既存のツールから接続しやすいのも利点です。ただし、モデルのサイズによっては相応のメモリとGPU性能が必要になります。

## 組み合わせの例

たとえば、TypeScriptのプロジェクトではBunとBiomeを、Pythonの処理ではuvを使い、エディタはZed、ローカルLLMはOllamaという構成が考えられます。すべてを一度に導入する必要はありません。まずは1つだけ導入し、効果を確認してから広げていくと定着しやすくなります。

## 導入時の注意点

- ロックファイルは必ずリポジトリへコミットする
- ローカルとCIで同じツールバージョンを使う
- ライセンスやセキュリティポリシーを確認する
- チーム内で設定ファイルの管理ルールを決める

## まとめ

開発ツールは、流行を追うこと自体が目的ではありません。日々の待ち時間や設定の手間を減らし、本来の実装に集中できる環境を作ることが重要です。

今回紹介した5つは、いずれも小さく試せて効果を実感しやすいものばかりです。気になるツールがあれば、まずは手元のプロジェクトで1つだけ導入してみてください。
-----
name: Zenn Auto Draft
on:
  workflow_dispatch:
    inputs:
      iteration:
        description: 'イテレーション番号（ログ用）'
        required: false
        type: number
        default: 1

permissions:
  contents: write

jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0   # draftブランチの取得に必要

      - name: Install OpenCode CLI
        run: npm install -g opencode-ai

      - name: Generate draft with OpenCode Zen
        env:
          OPENCODE_API_KEY: ${{ secrets.OPENCODE_API_KEY }}
        run: |
          opencode run \
            --model opencode/deepseek-v4.1-flash-free \
            "プログラミング関連のニュースやツールを紹介するZenn向け技術記事を、日本語で書いてください。必ず以下のfrontmatterから始め、publishedは絶対にfalseのままにしてください：
          ---
          title: \"（具体的で魅力的なタイトル）\"
          emoji: \"（内容に合う絵文字1文字）\"
          type: \"tech\"
          topics: [\"（関連タグを最大5つ）\"]
          published: false
          ---
          本文はMarkdownで、見出しは##から始めてください。" 2>&1 | tee /tmp/draft.md

      - name: Clean generated content
        run: |
          # ANSIエスケープシーケンスを除去
          sed -E 's/\x1B\[[0-9;]*[mGKHF]//g' /tmp/draft.md > /tmp/draft_clean.md

          # 最初の "---" 行以降（frontmatter以降）を抽出
          awk 'BEGIN{found=0} /^---[[:space:]]*$/{found=1} found{print}' /tmp/draft_clean.md > /tmp/draft_final.md

          # frontmatter以降に混ざったTUIログ行を除去
          grep -v -E '^(◈|> build|> )' /tmp/draft_final.md > /tmp/draft_clean2.md || true

          # 抽出結果を確認
          echo "=== 抽出後の先頭20行 ==="
          head -n 20 /tmp/draft_clean2.md

          # 空でないことを確認
          if [ ! -s /tmp/draft_clean2.md ]; then
            echo "エラー: 抽出後のファイルが空です"
            exit 1
          fi

          mv /tmp/draft_clean2.md /tmp/draft.md

      - name: Commit draft to draft branch
        env:
          ITER: ${{ inputs.iteration }}
        run: |
          SLUG="auto-$(date +%Y%m%d-%H%M)-${ITER}"
          mkdir -p articles
          cp /tmp/draft.md "articles/${SLUG}.md"
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"

          # draft/ 配下の衝突ブランチを自動削除
          for ref in $(git ls-remote --heads origin 'refs/heads/draft/*' | awk '{print $2}'); do
            git push origin --delete "${ref#refs/heads/}" || true
          done

          # draftブランチが存在すればチェックアウト、なければ作成
          if git ls-remote --exit-code --heads origin draft > /dev/null 2>&1; then
            git checkout draft
            git pull origin draft
          else
            git checkout -b draft
          fi

          git add "articles/${SLUG}.md"
          git commit -m "draft: ${SLUG} (iteration ${ITER})"
          git push origin draft

AIコーディングツールや新しいエディタに注目が集まる一方で、毎日の開発時間をじわじわ削っているのは、依存関係のインストール待ちやコマンドの入力ミスのような小さな摩擦だったりします。本記事では、そうした摩擦を減らしてくれるCLIツールを7つ紹介します。どれも「1つのことに集中する」設計で、既存のワークフローへ小さく足せるものばかりです。

## 選定の基準

今回の選定では、次の観点を重視しました。

- 役割が明確で、覚えることが少ない
- 設定ファイルをリポジトリで共有できる
- macOS・Linuxを中心に、主要な環境で動く
- チームへの導入を強制しなくても使える

すべてを一度に入れる必要はありません。気になったものを1つだけ試し、効果があれば定着させるのがおすすめです。

## 1. mise — 言語とツールのバージョンを1か所で管理

miseは、Node.jsやPython、Goなどのバージョンをプロジェクト単位で切り替えられるツールです。`.mise.toml` に利用バージョンを書いておけば、ディレクトリを移動するだけで環境が切り替わります。

```toml
[tools]
node = "22"
python = "3.13"
```

```bash
mise install
mise use --global node@22
mise exec -- node --version
```

asdfの代替として使われることが多く、言語だけでなくCLIツールのバージョンも管理できます。環境変数やタスクランナーの機能も持っていますが、まずはバージョン管理だけに絞って導入すると理解しやすいです。

## 2. uv — Pythonの依存解決を待たせない

uvはAstralが開発するPythonのパッケージ・プロジェクト管理ツールです。Rust製で依存解決とインストールが高速なうえ、`uv.lock` による再現性のある環境構築ができます。

```bash
uv init my-app
uv add requests
uv run python main.py
```

Python本体のバージョン管理もできるため、ローカルとCIで同じ環境を用意しやすくなります。既存プロジェクトへ導入する場合は、`pyproject.toml` とロックファイルの扱いをチームで確認してから進めると安全です。

## 3. Ruff — LintとFormatを高速に回す

RuffはRust製のPythonリンタ兼フォーマッタです。Flake8やisort、Blackなどで分かれがちだった設定を、`pyproject.toml` の一か所にまとめられます。

```bash
uvx ruff check --fix .
uvx ruff format .
```

編集中はエディタの保存時実行、CIでは変更がないかのチェック、という使い分けがしやすいのが利点です。既存コードへ一括適用すると差分が大きくなるため、最初はルールを絞り、プリコミットフックなどで少しずつ広げるのが現実的です。

## 4. just — Makefileより読みやすいタスクランナー

justは、プロジェクトでよく使うコマンドを `Justfile` にまとめるタスクランナーです。Makefileに似ていますが、タブインデントが不要で、引数や説明を素直に書けます。

```make
test:
    uv run pytest

lint:
    uvx ruff check .

check: lint test
```

```bash
just --list
just test
```

「このリポジトリでは何を実行すればよいか」が一目で分かるため、新しく参加した人への説明コストも下がります。ビルドシステムではなくコマンドの入口として使うと、責務がはっきりします。

## 5. watchexec — ファイル変更でコマンドを自動実行

watchexecは、ファイルの変更を監視して任意のコマンドを実行するツールです。テストの再実行や開発サーバーの再起動を自動化できます。

```bash
watchexec -e py -- uv run pytest
watchexec --restart -- npm run dev
```

`--restart` を付けると、変更のたびに前のプロセスを終了してから再起動してくれます。監視対象を拡張子で絞れるので、ビルド成果物やログによる無限ループを避けやすいのも助かります。

## 6. delta — git diffを読みやすくする

deltaは、gitの差分表示を見やすくするページャーです。行番号、シンタックスハイライト、単語単位の差分表示などにより、レビュー時の読み取り負担を減らせます。

```bash
git config --global core.pager delta
git config --global interactive.diffFilter "delta --color-only"
```

設定はgitのグローバル設定に追加するだけです。チーム全員に強制する必要はありませんが、差分を読む時間が長い人ほど効果を実感しやすいツールです。

## 7. zoxide — ディレクトリ移動を最短化する

zoxideは、よく使うディレクトリを学習して短いコマンドで移動できるようにする `cd` の代替です。

```bash
eval "$(zoxide init bash)"
z project
zi
```

`z` の後にディレクトリ名の一部を入力すると、使用頻度の高い候補へ移動します。`zi` は候補を一覧から選べるため、曖昧な記憶でも目的の場所へたどり着けます。シェルの初期化設定を変更するので、まずは自分の環境だけで試すのがよいでしょう。

## 組み合わせの例

たとえば、次のような役割分担が考えられます。

| 役割 | ツール |
| --- | --- |
| ツールのバージョン固定 | mise |
| Pythonの依存管理 | uv |
| LintとFormat | Ruff |
| 定番コマンドの入口 | just |
| 変更監視 | watchexec |
| 差分の閲覧 | delta |
| ディレクトリ移動 | zoxide |

すべてを同じ日に導入する必要はありません。まずはuvとRuffでPython周りを軽くし、次にjustでコマンドを整理する、といった順番が効果を実感しやすいです。

## 導入時の注意点

- ロックファイルやバージョン指定はリポジトリへコミットする
- ローカルとCIで同じツールバージョンを使う
- シェル設定の変更は、チームで共有する範囲を決める
- 便利でも、全員への導入を必須にしない

特にバージョン管理系のツールは、個人の環境だけを整えてもCIで差異が出ると意味が薄れます。設定ファイルをコードとしてレビューできる状態にしておくことが重要です。

## まとめ

開発体験の改善は、大きなツールの導入よりも、毎日何度も通るコマンドの小さな改善から始めたほうが定着しやすいことがあります。

今回紹介した7つは、いずれも単機能で、設定も比較的少なめです。気になるものがあったら、まずは手元の小さなリポジトリで1つだけ試してみてください。
