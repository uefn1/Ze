ターミナルでの作業時間は、気づかないうちに積み上がります。ファイルを探す、ディレクトリを移動する、Gitの状態を確認する。こうした小さな操作を高速化するだけでも、開発のリズムは大きく変わります。

本記事では、日常的に使えるCLIツールを5つ紹介します。いずれも導入が簡単で、既存のワークフローを壊さずに試せるものばかりです。

## なぜ今、CLIツールを見直すのか

エディタやIDEの進化に目が行きがちですが、ターミナルは今も開発の中心にあります。ビルド、テスト、Git操作、ログ確認など、多くの作業がシェルから始まります。

CLIツールを置き換えるメリットは、主に次の3つです。

- 待ち時間が減り、思考の流れが途切れにくくなる
- コマンドが短くなり、入力の負担が減る
- 設定ファイルを共有でき、チームで同じ体験を揃えられる

ただし、すべてを一度に置き換える必要はありません。まずは1つ導入し、手に馴染むか確認してから広げるのがおすすめです。

## 1. ripgrep — grepを置き換える高速検索

ripgrep（`rg`）はRust製の検索ツールです。`grep -r`の代替として使え、デフォルトで`.gitignore`を尊重するため、不要なファイルを検索対象から外してくれます。

```bash
# カレントディレクトリ以下を検索
rg "createServer"

# ファイル名だけを表示
rg -l "TODO"

# TypeScriptファイルに限定
rg "useEffect" -t ts
```

大量のファイルがあるリポジトリほど効果を実感しやすいツールです。`.gitignore`を無視して検索したい場合は`--no-ignore`を指定します。また、バイナリファイルは自動でスキップされるため、意図的に含めたい場合は`-a`を使います。

エディタ内の検索で十分と感じる場面もありますが、ログや生成物をまたいだ調査では`rg`の速さが効きます。

## 2. fd — 直感的なfind代替

`fd`は`find`の代替となるファイル検索ツールです。構文がシンプルで、色付きの出力と`.gitignore`の尊重がデフォルトで有効になっています。

```bash
# 名前に "config" を含むファイル
fd config

# 拡張子で絞り込み
fd -e ts

# 隠しファイルも含める
fd -H

# 見つかったファイルを一括削除（実行前に確認）
fd -e log -x rm
```

`find`の細かいオプションを覚えなくても、直感的に目的のファイルへたどり着けるのが魅力です。`-x`や`-X`を使えば、検索結果に対するコマンド実行も簡潔に書けます。

## 3. fzf — あいまい検索で候補を一瞬で絞る

`fzf`は汎用のあいまい検索ツールです。標準入力を受け取り、対話的に候補を絞り込めます。ファイル検索、コマンド履歴、Gitブランチの選択など、使い道は幅広いです。

```bash
# ファイルを選択して開く
vim "$(fd -t f | fzf)"

# Gitブランチを選択してチェックアウト
git checkout "$(git branch --format='%(refname:short)' | fzf)"

# コマンド履歴から選択して実行
history | fzf
```

シェルのキーバインドを有効にすると、`Ctrl-R`で履歴検索、`Ctrl-T`でファイル選択、`Alt-C`でディレクトリ移動ができます。設定はシェルの初期化ファイルに1行追加するだけです。

```bash
# bashの場合
eval "$(fzf --bash)"
```

あいまい検索に慣れると、正確な名前を思い出す必要がなくなり、候補から選ぶ感覚で操作できるようになります。

## 4. zoxide — cdを賢くする

`zoxide`は、よく使うディレクトリを学習して移動を短縮するツールです。`cd`の代わりに`z`を使い、ディレクトリ名の一部を入力するだけで移動できます。

```bash
# 初回のみシェルへ設定を追加
eval "$(zoxide init bash)"

# "proj" を含むよく使うディレクトリへ移動
z proj

# 候補を対話的に選択
zi
```

履歴はアクセス頻度に基づいて更新されるため、使うほど精度が上がります。深いディレクトリ階層を行うき来するプロジェクトでは、特に効果を実感しやすいでしょう。

`cd`を完全に置き換えるのではなく、慣れるまでは`z`を補助的に使うのが安全です。

## 5. lazygit — Git操作をTUIで可視化する

`lazygit`は、ターミナル上で動くGitのTUIクライアントです。ステータス、差分、ブランチ、コミット履歴を1画面で確認でき、キーボード操作でコミットやステージングを行えます。

```bash
lazygit
```

複雑なコマンドを覚えていなくても、変更の確認とコミットが直感的に行えます。特に次のような場面で便利です。

- 変更をファイル単位・行単位でステージしたい
- ブランチを切り替えながら差分を確認したい
- コンフリクトの解消箇所を把握したい

GUIクライアントほど重くなく、SSH接続先でも使えるのが利点です。ただし、チームのGit運用ルール（コミットメッセージの形式など）はツールに任せきりにせず、別途整備しておきましょう。

## 組み合わせ例

5つは独立して使えますが、組み合わせると効果が重なります。

```bash
# fdでファイルを絞り込み、fzfで選択してエディタで開く
code "$(fd -t f | fzf)"

# ripgrepで検索したファイルをfzfで選び、lazygitで差分確認
rg -l "TODO" | fzf | xargs -r lazygit
```

まずは`rg`と`fd`から始め、慣れたら`fzf`と`zoxide`を追加、Git操作を減らしたいなら`lazygit`という順番がおすすめです。

## 導入時の注意点

- 既存コマンドをエイリアスで置き換える場合、チームメンバーの環境差を考慮する
- シェルの設定ファイルはdotfilesとして管理し、複数マシンで共有する
- CIやスクリプトでは、対話的なツールに依存しないよう注意する
- ツールのバージョン差で挙動が変わる場合があるため、必要に応じてバージョンを固定する

特に`fzf`や`lazygit`は対話操作を前提としているため、自動化スクリプトの中では無理に使わないのが賢明です。

## まとめ

今回紹介した5つは、どれも「毎日の小さな待ち時間」を減らすためのツールです。

- `rg`で検索を速くする
- `fd`でファイル探索を簡単にする
- `fzf`で候補選択を直感的にする
- `zoxide`でディレクトリ移動を短縮する
- `lazygit`でGit操作を可視化する

すべてを導入する必要はありません。まずは1つだけ試し、自分の作業に合うと感じたら少しずつ広げてみてください。ターミナルの操作が軽くなるだけでも、開発に向き合う時間は確実に増えます。
