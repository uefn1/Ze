Pythonの依存管理といえば、長らく `pip` と `venv`、あるいは `Poetry` や `pyenv` の組み合わせが定番でした。そこに風穴を開けているのが、Ruff を開発した Astral 社のパッケージマネージャー **uv** です。

「とにかく速い」と話題になりがちですが、実際に触ると本質はスピードだけではありません。ツールの乱立をひとつにまとめ、ロックファイルとPython本体のバージョンまで一貫管理できる点が、開発体験を大きく変えます。この記事では、uv の位置づけと実践的な使い方を整理します。

## uvとは何か

uv は Rust で書かれた Python のパッケージ・プロジェクトマネージャーです。単なる `pip` の高速版ではなく、次のような役割をひとつに統合することを狙っています。

- `pip` / `pip-tools`：依存解決とインストール
- `virtualenv` / `venv`：仮想環境の作成
- `poetry` / `pdm`：プロジェクト管理とロックファイル
- `pyenv`：Pythonインタプリタのバージョン管理
- `pipx`：CLIツールの隔離インストール

つまり「Pythonを入れて、仮想環境を作って、依存を入れて、ツールを動かす」という一連の流れを、同じコマンド体系で扱えます。

## なぜ速いのか

uv の速度は、主に次の仕組みに支えられています。

1. **Rust実装**：依存解決やファイル操作のオーバーヘッドが小さい
2. **グローバルキャッシュ**：ダウンロード済みのパッケージを共有し、ハードリンクやreflinkで仮想環境へ展開する
3. **並列処理**：メタデータ取得やインストールを並行して進める
4. **PubGrubベースのリゾルバ**：矛盾を早期に検出しながら高速に依存を解決する

特にキャッシュの効き方が強烈で、2回目以降の `uv sync` は体感で「何もしていないのでは」と思うほど一瞬で終わります。CI での待ち時間削減効果も大きいです。

## インストール

公式のインストーラを使うのが手軽です。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

macOS なら Homebrew、Windows なら PowerShell でも導入できます。

```bash
brew install uv
```

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

## プロジェクトを作る

新規プロジェクトは `uv init` で始めます。

```bash
uv init myapp
cd myapp
```

`pyproject.toml` とサンプルコード、そして `.python-version` が生成されます。ここで重要なのは、uv が **プロジェクト中心** の設計になっていることです。

依存を追加するときは `uv add` を使います。

```bash
uv add requests
uv add --dev pytest ruff
```

`pyproject.toml` の `dependencies` と `dependency-groups` が更新され、同時に `uv.lock` が生成・更新されます。`pip install` を手で叩いて `requirements.txt` を管理する必要はありません。

## 仮想環境と同期

uv はプロジェクト配下に `.venv` を作り、そこへ依存を同期します。

```bash
uv sync
```

`uv.lock` の内容に一致するように環境を整えるコマンドで、CI では `--frozen` を付けてロックファイルの変更を禁止するのが定番です。

```bash
uv sync --frozen
```

スクリプトやコマンドの実行は `uv run` 経由にすると、環境を意識せずに済みます。

```bash
uv run python main.py
uv run pytest
```

`uv run` は必要なら環境を自動で同期してから実行するため、「仮想環境をactivateし忘れた」という事故が減ります。

## Python本体のバージョンも管理できる

uv はインタプリタのインストールも担当します。

```bash
uv python install 3.12
uv python list
```

プロジェクトで使うバージョンを固定する場合は次の通りです。

```bash
uv python pin 3.12
```

`.python-version` が更新され、チーム内でPythonのバージョンがずれる問題を抑えられます。pyenv と uv を併用する必要がなくなるのは大きなメリットです。

## CLIツールは uvx で試す

ちょっとしたツールを試したいときは `uvx` が便利です。

```bash
uvx ruff check .
uvx cowsay "hello"
```

グローバル環境を汚さず、一時的な環境で実行できます。常設したい場合は `uv tool install` を使います。

```bash
uv tool install ruff
```

## ロックファイルの考え方

`uv.lock` はプラットフォーム非依存の **universal lockfile** です。OSやPythonバージョンの違いをまたいで依存を固定できるため、ローカルとCIで同じ解決結果を再現しやすくなります。

運用のポイントは次の2つです。

- `uv.lock` は必ずリポジトリにコミットする
- CIでは `uv sync --frozen` でロックを尊重する

依存を更新したいときは明示的に行います。

```bash
uv lock --upgrade
uv lock --upgrade-package requests
```

## CIでの最小構成

GitHub Actions なら公式アクションを使うとセットアップが簡潔です。

```yaml
- uses: actions/checkout@v4
- uses: astral-sh/setup-uv@v5
  with:
    enable-cache: true
- run: uv sync --frozen
- run: uv run pytest
```

キャッシュを有効にすると、依存の再ダウンロードを避けられます。Pythonのセットアップを別途行わなくてよいのも嬉しい点です。

## 導入時の注意点

便利なuvですが、移行時に意識しておきたい点もあります。

- **ビルドバックエンドは別途必要**：uv はパッケージ管理を担いますが、配布物のビルドには `hatchling` や `setuptools` などのバックエンド設定が依然として必要です。
- **既存プロジェクトの移行**：`requirements.txt` から移す場合は `uv add -r requirements.txt` で取り込めますが、バージョン指定の揺れは確認しましょう。
- **チーム内の合意**：ロックファイルの更新タイミングや `--frozen` の運用ルールを決めておくと衝突が減ります。
- **エッジケース**：特殊なビルド要件や社内インデックスを使う場合は、`pyproject.toml` の `[tool.uv]` でインデックス設定を明示します。

## まとめ

uv の価値は「pipが速くなった」にとどまりません。プロジェクト管理、仮想環境、Pythonバージョン、ツール実行を一貫した操作で扱えるため、Python開発のセットアップが驚くほどシンプルになります。

まずは小さなプロジェクトで `uv init` から試し、`uv sync` と `uv run` の快適さを体感してみてください。一度慣れると、`pip` と `venv` を手作業で組み合わせる運用には戻りにくくなるはずです。
