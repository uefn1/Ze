Pythonの開発環境管理といえば、長らく `pip`、`venv`、`pyenv`、`Poetry` などを組み合わせるのが一般的でした。そこに登場したのが、Astral社が開発するRust製のパッケージマネージャー **uv** です。

uvは「速いpip」としてだけでなく、Python本体のバージョン管理、仮想環境、依存関係のロック、ツール実行までを1つのCLIにまとめています。この記事では、uvの基本的な使い方と、既存プロジェクトへ導入する際のポイントを整理します。

## uvとは

uvは次のような機能を単体で提供します。

- pip互換のパッケージインストール
- 仮想環境の作成・管理
- Pythonインタプリタのインストールとバージョン切り替え
- `pyproject.toml` とロックファイルによる依存関係管理
- `uv run` によるスクリプト・ツールの実行
- プロジェクトのビルドと公開

従来は複数のツールを組み合わせていた作業を、uvひとつで完結できるのが大きな特徴です。Rust製であることによる高速化も魅力で、依存関係の解決やインストールが体感できるレベルで速くなります。

## インストール

macOSやLinuxではインストールスクリプトを使います。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Homebrewを使う場合は次の通りです。

```bash
brew install uv
```

WindowsではPowerShellからインストールできます。

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

インストール後はバージョンを確認しておきましょう。

```bash
uv --version
```

## プロジェクトを作る

新規プロジェクトは `uv init` で作成します。

```bash
uv init my-app
cd my-app
```

アプリケーション用のプロジェクトでは、次のようなファイルが生成されます。

```text
my-app/
├── .python-version
├── README.md
├── main.py
└── pyproject.toml
```

`pyproject.toml` がプロジェクト設定の中心です。ライブラリとして配布する場合は `--lib` を付けると、`src` レイアウトの構成になります。

```bash
uv init --lib my-library
```

## 依存パッケージを追加する

パッケージの追加は `uv add` です。

```bash
uv add requests
```

開発用の依存関係は `--dev` を付けます。

```bash
uv add --dev pytest ruff
```

追加すると `pyproject.toml` に依存関係が追記され、`uv.lock` が生成されます。

```toml
[project]
name = "my-app"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [
    "requests>=2.32.0",
]

[dependency-groups]
dev = [
    "pytest>=8.0.0",
    "ruff>=0.6.0",
]
```

`uv.lock` は依存関係を厳密に固定するファイルなので、必ずGitで管理します。チーム開発では、このロックファイルがあることで全員が同じ依存関係を再現できます。

## 仮想環境と同期

uvはプロジェクトごとに `.venv` を自動で扱います。明示的に作成したい場合は次のコマンドです。

```bash
uv venv
```

ロックファイルに基づいて環境を同期するには `uv sync` を使います。

```bash
uv sync
```

`uv sync` は必要なパッケージのインストールだけでなく、ロックファイルにない不要なパッケージの削除も行います。CIや新しい開発環境のセットアップでは、このコマンド1つで環境を揃えられるのが便利です。

## Pythonのバージョンを管理する

uvはPythonインタプリタ自体のインストールもできます。

```bash
uv python install 3.12
```

利用可能なバージョンを確認する場合:

```bash
uv python list
```

プロジェクトで使うバージョンを固定するには `uv python pin` を使います。

```bash
uv python pin 3.12
```

これにより `.python-version` が更新され、`uv run` 実行時に指定バージョンが使われます。pyenvを別途インストールする必要がないため、環境構築の手順を大幅に減らせます。

## スクリプトを実行する

仮想環境を自分でactivateしなくても、`uv run` が適切な環境でコマンドを実行します。

```bash
uv run python main.py
```

テストやリンターも同様です。

```bash
uv run pytest
uv run ruff check .
```

`uv run` は実行前に環境を同期してくれるため、「activateし忘れて別のPythonが使われていた」という事故を防げます。

## 単発のツールを実行する

リポジトリに追加せず、一時的にツールを使いたい場合は `uvx` が便利です。

```bash
uvx ruff check .
```

よく使うツールをグローバルにインストールする場合は `uv tool install` を使います。

```bash
uv tool install ruff
uv tool install black
```

`uv tool` はツールごとに独立した環境を用意するため、依存関係の衝突を気にせず管理できます。

## 既存プロジェクトを移行する

`requirements.txt` を使っているプロジェクトでは、まず `pyproject.toml` を用意します。

```bash
uv init --bare
```

その後、依存関係を追加していきます。

```bash
uv add -r requirements.txt
```

`uv pip` を使えば、pip互換のコマンドで既存ワークフローを保ったまま試すこともできます。

```bash
uv pip install -r requirements.txt
```

まずはCIやローカルで `uv pip` から試し、問題がなければ `uv sync` ベースの運用へ移行するのが現実的です。

## CIでの活用

GitHub Actionsでは公式の `astral-sh/setup-uv` アクションが利用できます。

```yaml
name: test

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v5
        with:
          enable-cache: true
      - run: uv sync --locked
      - run: uv run pytest
```

`--locked` を付けると、`uv.lock` が更新される場合にエラーになります。CIではロックファイルとの不整合を検出できるため、再現性の維持に役立ちます。

## 導入時の注意点

uvは非常に便利ですが、いくつか押さえておきたい点もあります。

- `uv.lock` は必ずコミットする
- CIでは `--locked` や `--frozen` を検討する
- 社内レジストリを使う場合はインデックス設定を確認する
- 既存のPoetryプロジェクトは一度に移行せず、検証しながら進める
- Python本体の管理をuvに寄せる場合は、pyenvとの併用ルールを決めておく

特にチーム開発では、誰がどのツールでPythonを管理するのかを最初に決めておくと混乱を避けられます。

## まとめ

uvは、Python開発における「環境構築が面倒」「ツールが多すぎる」「インストールが遅い」といった課題をまとめて解決してくれるツールです。

- `uv init` でプロジェクト作成
- `uv add` で依存関係追加
- `uv sync` で環境同期
- `uv run` でコマンド実行
- `uv python` でPython本体を管理

まずは小さなプロジェクトで `uv run` と `uv sync` から試し、効果を感じられたらCIやチーム開発へ広げていくのがおすすめです。pipやPoetryに慣れている人ほど、その速さと一元管理の快適さを実感できるはずです。
