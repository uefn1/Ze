## はじめに

AIコーディングエージェントが当たり前になった今、「AIに自分の環境の情報をどう渡すか」が開発体験を大きく左右します。その標準規格として定着しつつあるのが **MCP（Model Context Protocol）** です。

本記事では、MCPの考え方を整理したうえで、TypeScriptで最小構成のMCPサーバーを実際に作り、AIクライアントから呼び出せる状態までを解説します。

## MCPとは何か

MCPは、AIアプリケーションと外部のデータソース・ツールをつなぐためのオープンなプロトコルです。Anthropicが提唱し、現在は幅広いクライアント／サーバー実装が存在します。

登場人物は大きく2つです。

- **クライアント（ホスト）**: AIエージェント本体。IDE拡張やCLIなど
- **サーバー**: ツール・リソース・プロンプトを公開する側

通信はJSON-RPC 2.0をベースにしており、トランスポートは主に次の2種類です。

| トランスポート | 用途 |
| --- | --- |
| `stdio` | ローカルプロセスとして起動するツール向け |
| Streamable HTTP | リモート／共有サーバー向け |

かつての「HTTP + SSE」方式はStreamable HTTPに置き換わっているため、新規実装では後者を選ぶのが基本です。

## なぜ注目されているのか

MCPの価値は「N対M問題」の解消にあります。従来は、クライアントごとにツール連携を個別実装する必要がありました。MCPに準拠すれば、**1つのサーバーを書けば、対応するあらゆるクライアントから使える**ようになります。

たとえば社内のデプロイツールや社内Wiki検索をMCPサーバー化しておけば、エディタを乗り換えても同じツール資産を再利用できます。

## 最小構成のMCPサーバーを作る

ここでは「2つの数値を足す」だけの小さなサーバーを作り、仕組みを確認します。

### セットアップ

```bash
mkdir my-mcp-server && cd my-mcp-server
npm init -y
npm install @modelcontextprotocol/sdk zod
npm install -D typescript tsx @types/node
```

`package.json` に `"type": "module"` を追加しておくと、ESMのimportが素直に書けます。

### ツールの定義

`server.ts` を作成します。

```ts
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({
  name: "my-tools",
  version: "1.0.0",
});

// ツールを登録する
server.tool(
  "add",
  "2つの数値を足し算して結果を返す",
  { a: z.number(), b: z.number() },
  async ({ a, b }) => ({
    content: [{ type: "text", text: String(a + b) }],
  })
);

// stdioで待ち受ける
const transport = new StdioServerTransport();
await server.connect(transport);
```

ポイントは、引数のスキーマを **Zod** で定義する点です。これによりクライアント側は引数の型を理解でき、AIは正しい形式でツールを呼び出せます。

### 動作確認

MCPサーバーは単体でHTTPを待ち受けるわけではないため、動作確認はクライアント経由か、公式のInspectorを使うのが手軽です。

```bash
npx @modelcontextprotocol/inspector npx tsx server.ts
```

Inspectorが起動したら、`add` ツールに `a: 2, b: 3` を渡して `5` が返れば成功です。あとは利用しているAIクライアントの設定ファイルに、このサーバーの起動コマンドを追記すれば接続できます。

## 実運用での注意点

小さく動かせたら、次は運用面です。特に押さえておきたいのは次の3点です。

### 1. ツールの粒度を設計する

1ツール1責務を徹底すると、AIが適切なツールを選びやすくなります。「何でもやる巨大ツール」は呼び出しミスを招きます。

### 2. 出力を絞る

ツールの戻り値が巨大だとコンテキストを圧迫します。必要な情報だけを返し、詳細はページングや引数で制御できるようにしましょう。

### 3. 破壊的操作は明示する

ファイル削除やデプロイなど副作用の大きい操作は、ツール名や説明文で危険性を明示し、可能なら確認ステップを挟みます。AIは説明文を読んで判断するため、**説明文はプロンプトの一部**という意識が重要です。


## まとめ

- MCPはAIと外部ツールをつなぐ標準プロトコル
- `stdio` と Streamable HTTP の2トランスポートを用途で使い分ける
- TypeScript SDKなら数十行でツールを公開できる
- ツール粒度・出力サイズ・危険操作の明示が運用の鍵

まずは社内のちょっとしたスクリプトを1つMCP化してみるのがおすすめです。小さく始めるほど、AIエージェントとの協働がぐっと快適になります。
