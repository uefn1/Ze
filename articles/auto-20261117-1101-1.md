Pythonの環境構築は、長らく `pip` / `venv` / `pip-tools` / `pyenv` の組み合わせが定番でした。ただ、ツールごとに役割が分かれているため、「結局どれをどこで使えばいいのか」がわかりにくいのも事実です。

そこで注目されているのが、Astral社が開発する **uv** です。Rust製の高速なパッケージマネージャーで、Python本体の導入から仮想環境、依存解決、ロックファイル、スクリプト実行までをひとつにまとめられます。この記事では、実際の開発フローに沿ってuvの使い方を整理します。

## uvとは

uvは、Pythonのプロジェクト管理を一箇所に集約するCLIツールです。主な役割は次のとおりです。

- Pythonインタプリタのインストールとバージョン切り替え
- 仮想環境の作成
- `pyproject.toml` を起点にした依存関係の追加・解決
- `uv.lock` による再現性のあるインストール
- 仮想環境を明示的に有効化しないスクリプト実行
- CLIツールの一時実行・グローバルインストール

pip互換のコマンドも用意されているため、既存プロジェクトから段階的に移行できます。

## インストール

macOS / Linuxでは公式のインストーラーを使います。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Homebrewやpipx経由でも導入できます。インストール後はバージョンを確認しておきましょう。

```bash
uv --version
```

## プロジェクトを新規作成する

まずはプロジェクトの雛形を作ります。

```bash
uv init myapp
cd myapp
```

`pyproject.toml` とサンプルスクリプト、`.python-version` などが生成されます。依存パッケージの追加は `uv add` です。

```bash
uv add requests
uv add --dev pytest
```

`pyproject.toml` に依存が追記され、同時に `uv.lock` が更新されます。実行は `uv run` を使うと、必要に応じて環境を同期したうえでコマンドが走ります。

```bash
uv run python -c "import requests; print(requests.__version__)"
uv run pytest
```

仮想環境を自分で `source` する必要がないのは、地味ですが大きなメリットです。

## 依存関係を再現する

チーム開発やCIでは、ロックファイルからのインストールが基本になります。

```bash
uv sync
```

`uv.lock` はプラットフォームに依存しない形式で管理されるため、リポジトリにコミットしておけば、同じ依存関係を再現しやすくなります。CIではロックファイルの更新を禁止する `--frozen` が便利です。

```bash
uv sync --frozen
```

依存関係の全体像を確認したいときは `uv tree` が使えます。

```bash
uv tree
```

## Python本体もuvで管理する

uvはPythonインタプリタの管理も担います。

```bash
uv python install 3.12
uv python pin 3.12
```

`uv python pin` でプロジェクトのバージョンを固定できます。複数バージョンを切り替えたい場合も、プロジェクト単位で完結するため、環境の取り違えを減らせます。

## ツールを一時実行する

フォーマッタやリンタなど、プロジェクトの依存に含めたくないツールは `uvx` で実行できます。

```bash
uvx ruff check .
uvx ruff format .
```

常に使うツールは `uv tool install` でグローバルに導入できます。ツールごとに独立した環境が作られるため、依存の衝突を気にせず済みます。

```bash
uv tool install ruff
```

## 既存プロジェクトから移行する

すでに `requirements.txt` を使っている場合は、いきなりすべてを置き換えず、仮想環境の作成とインストールだけuvに任せるのが安全です。

```bash
uv venv
uv pip install -r requirements.txt
```

慣れてきたら `pyproject.toml` へ依存を移し、`uv add` と `uv sync` の運用に切り替えていくとよいでしょう。

## CIで使う

GitHub Actionsでは専用のアクションが用意されています。

```yaml
steps:
  - uses: actions/checkout@v4
  - uses: astral-sh/setup-uv@v5
  - run: uv sync --frozen
  - run: uv run pytest
```

キャッシュを有効にすると、依存インストールの時間をさらに短縮できます。利用するアクションのバージョンは公式ドキュメントで最新を確認してください。

## 注意しておきたいポイント

uvは高速で便利ですが、移行時にはいくつか確認が必要です。

- **ロックファイルはコミットする**：`uv.lock` を共有しないと再現性が崩れます。
- **解決結果はpipと完全一致しないことがある**：依存解決のアルゴリズムが異なるため、移行時にテストを流して確認します。
- **プライベートインデックス**：社内PyPIなどを使う場合は `pyproject.toml` の `[[tool.uv.index]]` で設定します。認証情報は環境変数やCIのシークレットで渡しましょう。
- **バージョンを固定する**：チーム内でuvのバージョンが大きく違うと挙動が変わる可能性があります。CIと開発環境で揃えておくと安心です。

## まとめ

uvは、Python開発で散らばりがちなツールをひとつにまとめ、依存管理と実行をシンプルにしてくれます。

- `uv init` / `uv add` でプロジェクトを管理
- `uv sync` と `uv.lock` で再現性を確保
- `uv run` で仮想環境の有効化を不要に
- `uv python` でインタプリタも一元管理
- `uvx` でツールを気軽に試せる

まずは新規プロジェクトか、小さな既存プロジェクトから試してみると、その速さと手軽さを実感しやすいはずです。
