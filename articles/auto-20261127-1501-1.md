## はじめに

Pythonの開発環境づくりは、長らく「道具が多すぎる」問題を抱えてきました。パッケージ管理は `pip`、仮想環境は `venv`、依存の固定は `pip-tools`、プロジェクト管理は `Poetry`、Python本体のバージョン管理は `pyenv`……。目的ごとに別のツールを使い分ける必要があり、初心者にもチーム開発にも優しいとは言えませんでした。

その状況を一変させているのが、Astral社が開発する **uv** です。Rust製で非常に高速、かつ `pip` や `venv` と互換性を持ちながら、プロジェクト管理・Pythonバージョン管理・ツール実行までを1つにまとめています。

この記事では、uvの基本から実践的な使い方、既存プロジェクトからの移行までを一通り紹介します。

## uvとは

uvは「Python向けの統合ツール」と表現できるものです。主な機能は次の通りです。

- `pip` 互換のパッケージインストール
- `venv` の代替となる仮想環境作成
- `pyproject.toml` と `uv.lock` によるプロジェクト管理
- Python本体のバージョンインストールと切り替え
- `uvx` によるCLIツールの一時実行

最大の特徴は速度です。依存解決やインストールが高速で、CIの待ち時間削減にも効きます。また、ロックファイル `uv.lock` によって再現性の高い環境を構築できます。

## インストール

macOS / Linuxでは次のコマンドで導入できます。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Windows（PowerShell）の場合:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Homebrewを使っている場合はこちらでも構いません。

```bash
brew install uv
```

インストール後、バージョンを確認します。

```bash
uv --version
```

## プロジェクトを始める

新規プロジェクトは `uv init` で作成します。

```bash
uv init myapp
cd myapp
```

`pyproject.toml` が生成されるので、依存パッケージは `uv add` で追加します。

```bash
uv add requests
uv add --dev pytest ruff
```

追加すると `pyproject.toml` が更新され、`uv.lock` が生成されます。依存を反映した環境を作るには `uv sync` を実行します。

```bash
uv sync
```

スクリプトの実行は `uv run` を使います。仮想環境を自分でactivateする必要はありません。

```bash
uv run python main.py
uv run pytest
```

`uv run` は必要に応じて環境を同期してからコマンドを実行するため、依存を追加した直後でもそのまま動きます。

## 依存関係を操作する

よく使うコマンドを整理しておきます。

```bash
uv add requests          # 依存を追加
uv add --dev pytest      # 開発用依存を追加
uv remove requests       # 依存を削除
uv lock                  # ロックファイルを更新
uv sync                  # ロックに合わせて環境を同期
uv sync --frozen         # ロックを更新せずに同期（CI向け）
```

`uv.lock` は必ずリポジトリにコミットしましょう。チーム全員が同じ依存バージョンで作業できるようになります。

## Pythonのバージョンを管理する

uvはPython本体のインストールもできます。

```bash
uv python install 3.12
uv python list
```

プロジェクトで使うバージョンを固定するには `uv python pin` が便利です。

```bash
uv python pin 3.12
```

これにより `.python-version` が作成され、`uv run` 実行時に適切なPythonが使われます。

## スクリプトを単体で実行する

uvの便利な機能のひとつが、PEP 723のインラインスクリプトメタデータ対応です。スクリプト内に依存を書いておけば、単体ファイルとして実行できます。

```python
# /// script
# dependencies = [
#   "requests",
# ]
# ///

import requests

response = requests.get("https://example.com")
print(response.status_code)
```

実行は次の通りです。

```bash
uv run script.py
```

ちょっとした検証スクリプトや共有用のサンプルに最適です。

## CLIツールを一時実行する

`uvx` を使うと、グローバル環境を汚さずにツールを実行できます。

```bash
uvx ruff check .
uvx black --check .
```

常に使うツールであれば `uv tool install` でインストールできます。

```bash
uv tool install ruff
```

## 既存プロジェクトから移行する

`requirements.txt` があるプロジェクトなら、次のように依存を取り込めます。

```bash
uv init
uv add -r requirements.txt
```

`pip` 互換のインターフェースも用意されているので、既存の手順を大きく変えずに試すこともできます。

```bash
uv venv
uv pip install -r requirements.txt
```

まずはCIやローカルで試験的に使い、問題がなければ `pyproject.toml` + `uv.lock` の管理へ移行するのがおすすめです。

## CIで活用する

GitHub Actionsでは公式の `astral-sh/setup-uv` アクションが利用できます。

```yaml
- uses: astral-sh/setup-uv@v5
- run: uv sync --frozen
- run: uv run pytest
```

`--frozen` を付けることで、ロックファイルを更新せずに同期し、CIでの意図しない依存変更を防げます。uvはキャッシュも効きやすいため、ジョブ全体の実行時間短縮が期待できます。

## 注意点

uvは開発が活発で、機能や挙動がアップデートされることがあります。チームで使う場合は、利用するuvのバージョンをある程度統一しておくと安心です。

また、`pip` 互換とはいえ完全に同一ではありません。特殊なビルド設定や社内インデックスを使っている場合は、移行前に検証しておきましょう。ロックファイルの運用ルールも併せて決めておくと、後のトラブルを避けられます。

## まとめ

uvは、Python開発における「ツールが多すぎる」問題に対する実用的な答えです。

- `pip` / `venv` / `Poetry` 相当の機能を1つに統合
- Rust製で高速、CIの時間短縮にも貢献
- `uv.lock` による再現性の高い依存管理
- インラインスクリプトやCLIツール実行までカバー

まずは小さなプロジェクトや個人開発から試し、効果を実感してからチームへ広げていくのがよいでしょう。まだ使ったことがない方は、この機会に `uv init` から始めてみてください。
