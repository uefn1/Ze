新しい開発ツールは毎週のように登場しますが、実際に日常の開発へ定着するものは多くありません。本記事では、導入のハードルが低く、既存のワークフローへ自然に組み込めるツールを5つ紹介します。

## 選定のポイント

ツールを選ぶ際は、次の観点を重視しました。

- 既存の言語やエディタと組み合わせやすい
- 起動・実行が速く、待ち時間が少ない
- 設定ファイルがシンプルで、チームへ展開しやすい
- 特定のサービスへ過度に依存しない

もちろん、チームの技術スタックによって最適解は異なります。気になったものは小規模なリポジトリで試すところから始めるのがおすすめです。

## 1. Bun — JavaScript/TypeScriptの実行環境をまとめる

BunはJavaScript/TypeScript向けのオールインワンランタイムです。パッケージマネージャ、バンドラ、テストランナーが一体になっており、複数のツールを別々に設定する手間を減らせます。

```bash
bun init
bun add -d typescript
bun test
```

TypeScriptをそのまま実行できるため、小さなスクリプトやCLIツールの作成が快適です。Node.jsとの互換性も向上していますが、ネイティブモジュールや一部APIの挙動は異なる場合があります。本番導入前に対象プロジェクトで検証しましょう。

## 2. Biome — LintとFormatを1つに

BiomeはRust製のリンタ・フォーマッタです。JavaScript/TypeScriptやJSONを中心に、LintとFormatを高速に実行できます。

```bash
biome check --write .

ESLintとPrettierの設定が複雑になりがちなプロジェクトでは、設定を1か所にまとめられるのが魅力です。エディタ連携も用意されており、保存時の自動整形とCIでのチェックを同じ設定で運用できます。既存プロジェクトへ導入する場合は、まずルールを最小限にして差分を確認すると安全です。

## 3. uv — Pythonの依存管理を高速化する

uvはAstralが開発するPythonのパッケージ・プロジェクト管理ツールです。依存解決とインストールが高速で、ロックファイルによる再現性のある環境構築ができます。

```bash
uv init my-app
uv add requests
uv run python main.py
```

Python本体のバージョン管理もできるため、ローカルとCIで同じ環境を用意しやすくなります。仮想環境の作成や依存の追加をコマンドで統一できる点も、チーム開発に向いています。

## 4. Zed — 軽快さを重視したコードエディタ

ZedはRust製のコードエディタです。起動や入力のレスポンスが軽く、LSPやTree-sitterによる補完・構文解析を備えています。共同編集機能もあり、ペアプログラミングやレビューの場面で活用できます。

VS Codeのような拡張機能の豊富さはまだ及ばない部分があるため、利用する言語の対応状況は事前に確認してください。一方で、エディタ自体の動作の軽さを重視する人には有力な選択肢です。

## 5. Ollama — ローカルでLLMを動かす

Ollamaは、ローカル環境で大規模言語モデルを実行するためのツールです。CLIからモデルを取得してすぐに試せる手軽さが特徴です。

```bash
ollama run llama3
```

ローカルで完結するため、コードや文章を外部サービスへ送りたくない場面に向いています。OpenAI互換のAPIを備えており、既存のツールから接続しやすいのも利点です。ただし、モデルのサイズによっては相応のメモリとGPU性能が必要になります。

## 組み合わせの例

たとえば、TypeScriptのプロジェクトではBunとBiomeを、Pythonの処理ではuvを使い、エディタはZed、ローカルLLMはOllamaという構成が考えられます。すべてを一度に導入する必要はありません。まずは1つだけ導入し、効果を確認してから広げていくと定着しやすくなります。

## 導入時の注意点

- ロックファイルは必ずリポジトリへコミットする
- ローカルとCIで同じツールバージョンを使う
- ライセンスやセキュリティポリシーを確認する
- チーム内で設定ファイルの管理ルールを決める

開発ツールは、流行を追うこと自体が目的ではありません。日々の待ち時間や設定の手間を減らし、本来の実装に集中できる環境を作ることが重要です。

AIコーディングエージェントが日常の開発に入り込むようになり、開発ツールの選び方も少しずつ変わってきました。以前は「エディタが軽いか」「ビルドが速いか」が中心でしたが、今は**AIがどれだけ正確に文脈を理解できるか**、そして**ツール同士を安全につなげられるか**が重要な判断軸になっています。

本記事では、その変化を踏まえて注目したいツールと仕組みを5つ紹介します。特定のサービスへロックインせず、小さく試せるものを中心に選びました。

## 開発ツールの選定軸はどう変わったか

AIエージェントにコードを書かせる場合、モデルの性能だけでなく「どんな情報を渡せるか」が結果を大きく左右します。リポジトリの構造、Issue、データベースのスキーマ、社内APIの仕様。これらを都度コピペする運用はすぐに限界が来ます。

そこで重要になるのが、次の3点です。

- 文脈を渡すための標準的なインターフェースがあるか
- ローカルで完結でき、秘密情報を外部へ出さずに済むか
- CLIや設定ファイルで自動化しやすいか

## 1. MCP — AIに文脈と道具を渡す共通規格

MCP（Model Context Protocol）は、AIアプリケーションと外部のデータ・ツールをつなぐためのオープンな規格です。クライアントとサーバーがJSON-RPCでやり取りするシンプルな設計で、ファイルシステムやデータベース、社内ツールを「MCPサーバー」として公開できます。

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "./"]
    }
  }
}
```

モデルごとに独自の連携を実装するのではなく、共通の口を用意できる点が魅力です。ただし、渡す権限は最小限に絞りましょう。読み取り専用で足りる場面に書き込み権限を与えると、事故の影響が一気に大きくなります。

## 2. OpenCode — ターミナルで動くコーディングエージェント

OpenCodeは、ターミナルから操作するAIコーディングエージェントです。リポジトリを読み、ファイルを編集し、コマンドを実行しながらタスクを進められます。設定を `opencode.json` にまとめられるため、チームで同じモデルや権限を共有しやすいのが特徴です。

```bash
opencode
```

エディタを問わず使えるので、VS CodeでもNeovimでも同じ体験を保てます。一方で、エージェントに実行を許すコマンドの範囲は明確に決めておくべきです。テストや整形は自動化しやすく、デプロイや削除操作は人の確認を挟む、といった線引きが現実的です。

## 3. uv — Pythonの環境構築を高速かつ再現可能に

uvはAstralが開発するPythonのパッケージ・プロジェクト管理ツールです。依存解決とインストールが高速で、ロックファイルによって環境を再現できます。Python本体のバージョン管理もできるため、ローカルとCIの差異を減らせます。

```bash
uv init my-app
uv add requests
uv run python main.py
```

AIエージェントにPythonコードを書かせる場合も、`uv run` で実行方法を統一しておくと検証が安定します。仮想環境の有効化を忘れる、といった古典的なつまずきも減らせるでしょう。

## 4. Bun — JavaScript/TypeScriptの実行からテストまで

BunはJavaScript/TypeScript向けのオールインワンランタイムです。パッケージマネージャ、バンドラ、テストランナーが一体になっており、小さなスクリプトからCLIツールまで素早く試せます。

```bash
bun init
bun add -d typescript
bun test
```

TypeScriptをそのまま実行できるため、ちょっとした検証コードを書くときに便利です。Node.jsとの互換性は向上していますが、ネイティブモジュールや一部APIの挙動が異なる場合があります。本番導入の前に対象プロジェクトで確認しておきましょう。

## 5. Biome — LintとFormatを1つの設定に

BiomeはRust製のリンタ・フォーマッタです。JavaScript/TypeScriptやJSONを中心に、LintとFormatを高速に実行できます。

```bash
biome check --write .
```

ESLintとPrettierの設定が複雑になりがちなプロジェクトでは、設定を1か所にまとめられるのが利点です。AIが生成したコードの品質を一定に保つ用途とも相性がよく、保存時の自動整形とCIでのチェックを同じ設定で運用できます。既存プロジェクトへ入れる場合は、まずルールを最小限にして差分を確認すると安全です。

## 組み合わせの例

たとえば、次のような構成が考えられます。

- エージェントはOpenCodeから起動する
- リポジトリや社内ツールへのアクセスはMCPサーバー経由に限定する
- Pythonはuv、JavaScript/TypeScriptはBunで実行する
- コード品質はBiomeで統一する

すべてを一度に導入する必要はありません。まずはMCPで読み取り専用の文脈を1つ渡すところから始め、効果を確認してから権限や対象を広げていくのが定着しやすいです。

## 導入時の注意点

- MCPサーバーには必要最小限の権限だけを与える
- エージェントが実行できるコマンドを明示的に決める
- ロックファイルは必ずリポジトリへコミットする
- ローカルとCIで同じツールバージョンを使う
- ライセンスとセキュリティポリシーを確認する

## まとめ

AIエージェント時代の開発ツールは、単に速いだけでなく「AIに何を渡し、何を許すか」を設計できるかが問われます。MCPのような共通規格と、uv・Bun・Biomeのような軽量なツールを組み合わせると、その土台を作りやすくなります。

流行を追うこと自体が目的ではありません。日々の待ち時間と設定の手間を減らし、本来の実装に集中できる環境を少しずつ整えていきましょう。
