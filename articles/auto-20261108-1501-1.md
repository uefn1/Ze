## はじめに

Pythonの開発環境構築は、長らく「ツールが多すぎる」問題を抱えてきました。パッケージ管理は `pip`、仮想環境は `venv`、依存関係のロックは `pip-tools`、プロジェクト管理は `Poetry` や `Pipenv`……。目的ごとに別のツールを使い分ける必要があり、学習コストも運用コストも高い状態が続いています。

そこに登場したのが、Ruff を開発する Astral 社による **uv** です。Rust 製の高速なパッケージマネージャで、`pip`・`venv`・`pip-tools`・`Poetry` の役割をひとつに統合することを目指しています。

本記事では、uv の基本から実践的な使い方までを一通り紹介します。

## uvとは

uv は次のような特徴を持つ Python のパッケージ・プロジェクトマネージャです。

- **とにかく速い** — Rust 製で、依存解決とインストールが従来比で桁違いに高速
- **pip 互換** — 既存の `requirements.txt` や PyPI のエコシステムをそのまま利用できる
- **オールインワン** — 仮想環境、依存ロック、Python 本体のバージョン管理、ツール実行までカバー
- **ユニバーサルロックファイル** — `uv.lock` により、OS や Python バージョンが異なる環境でも再現性の高いインストールが可能
- **単一バイナリ** — 依存が少なく、導入が簡単

「速い pip」としてだけでなく、「Python 版 Cargo」に近い体験を目指しているツールだと考えるとイメージしやすいでしょう。

## インストール

公式のインストーラを使うのが手軽です。

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

```powershell
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Homebrew や pip 経由でも導入できます。

```bash
brew install uv
# または
pip install uv
```

インストール後はバージョンを確認しておきましょう。

```bash
uv --version
```

## 基本コマンド早見表

まずは全体像を掴みましょう。従来のツールとの対応関係は次のとおりです。

| やりたいこと | 従来 | uv |
| --- | --- | --- |
| 仮想環境の作成 | `python -m venv .venv` | `uv venv` |
| パッケージのインストール | `pip install requests` | `uv add requests` |
| requirements からの一括導入 | `pip install -r requirements.txt` | `uv pip install -r requirements.txt` |
| 依存のロック | `pip-compile` | `uv lock` |
| ロックに基づく同期 | `pip-sync` | `uv sync` |
| ツールの一時実行 | `pipx run` | `uvx` |
| Python 本体の導入 | pyenv など | `uv python install` |

## プロジェクトを作ってみる

新しいプロジェクトは `uv init` で始めます。

```bash
uv init my-app
cd my-app
```

`--app` を付けるとアプリケーション用、`--lib` を付けるとライブラリ用の構成になります。生成される `pyproject.toml` は次のような形です。

```toml
[project]
name = "my-app"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = []
```

`requires-python` が明示されている点がポイントです。uv はこの制約を満たす Python インタプリタを自動で探し、必要であればダウンロードして使います。

## 依存パッケージの追加と削除

パッケージの追加は `uv add` です。`pip install` と違い、`pyproject.toml` の更新とロックファイルの生成まで面倒を見てくれます。

```bash
uv add requests
uv add "fastapi>=0.115" uvicorn
```

開発用の依存は `--dev` を付けます。

```bash
uv add --dev pytest ruff mypy
```

削除は `uv remove` です。

```bash
uv remove requests
```

追加・削除のたびに `uv.lock` が更新されるため、チーム間での再現性が保たれます。

## 依存関係の同期

`uv.lock` の内容を環境に反映するには `uv sync` を使います。

```bash
uv sync
```

仮想環境がなければ自動で作成され、ロックファイルどおりにパッケージがインストールされます。CI などで「ロックファイルを変更せずに厳密に再現したい」場合は `--frozen` を付けます。

```bash
uv sync --frozen
```

`--frozen` を指定するとロックファイルの更新を行わず、書かれている内容だけをインストールします。本番ビルドや CI ではこの指定がおすすめです。

## スクリプトの実行

`uv run` を使うと、仮想環境を明示的に activate しなくてもコマンドを実行できます。

```bash
uv run python main.py
uv run pytest
uv run ruff check .
```

`uv run` は実行前に依存関係を自動で同期してくれるため、「activate し忘れて別の環境で動いた」という事故を減らせます。

さらに、単発のスクリプトに依存を埋め込むインラインスクリプトにも対応しています。

```python
# /// script
# requires-python = ">=3.12"
# dependencies = ["httpx"]
# ///

import httpx

response = httpx.get("https://example.com")
print(response.status_code)
```

このファイルを `uv run script.py` で実行すると、必要な依存を一時環境に用意してから実行してくれます。ちょっとした検証コードを共有するのに便利です。

## ツールを汚さずに実行する

グローバル環境を汚さずに CLI ツールを使いたいときは `uvx`（`uv tool run` の短縮形）が便利です。

```bash
uvx ruff check .
uvx black --check .
uvx cowsay "hello uv"
```

常に使うツールは `uv tool install` でインストールできます。

```bash
uv tool install ruff
```

`pipx` を使っていたケースはほぼそのまま置き換えられるでしょう。

## Python本体のバージョン管理

uv は Python インタプリタ自体の管理もできます。pyenv の代わりとして使えるイメージです。

```bash
# 利用可能なバージョンを確認
uv python list

# 特定バージョンをインストール
uv python install 3.11 3.12 3.13

# プロジェクトで使うバージョンを固定
uv python pin 3.12
```

`uv python pin` を実行すると `.python-version` が生成され、プロジェクト単位でバージョンを固定できます。

## 既存のpipプロジェクトから移行する

すでに `requirements.txt` があるプロジェクトでも、uv は段階的に導入できます。まずは pip 互換コマンドで試すのがおすすめです。

```bash
uv venv
uv pip install -r requirements.txt
```

速度面の恩恵だけをまず受けたい場合はこれだけでも十分です。その後、余裕があるときに `pyproject.toml` ベースへ移行していくとよいでしょう。

`uv init` を既存ディレクトリで実行し、依存を `uv add` で登録し直すことで、ロックファイルを使った管理へスムーズに移行できます。

## Dockerでの利用

uv 公式のイメージを使うと、Docker ビルドもシンプルに書けます。

```dockerfile
FROM python:3.12-slim

COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/

WORKDIR /app

COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev

COPY . .

CMD ["uv", "run", "python", "main.py"]
```

`uv sync --frozen` を使うことで、ロックファイルどおりの依存を再現しつつ、ビルドを高速化できます。依存のコピーとインストールをソースコードのコピーより前に置くのが、レイヤーキャッシュを効かせる定石です。

## 導入時の注意点

便利な uv ですが、いくつか押さえておきたい点もあります。

- **チーム全員のバージョンを揃える** — uv 自体のバージョン差異で挙動が変わる可能性があるため、CI やドキュメントでバージョンを明示しましょう
- **ロックファイルは必ずコミットする** — `uv.lock` をリポジトリに含めることで再現性が保たれます
- **`--frozen` と通常の `sync` の違いを理解する** — CI では `--frozen`、ローカル開発では通常の `uv sync` と使い分けると安全です
- **既存ツールとの共存を意識する** — いきなりすべてを置き換えず、まずは pip 互換モードから試すとリスクを抑えられます

## まとめ

uv は「速い pip」にとどまらず、仮想環境・依存ロック・Python 本体管理・ツール実行までをひとつにまとめた、Python 開発環境の新しい標準候補です。

まずは `uv venv` と `uv pip install` の pip 互換モードから試し、慣れてきたら `uv init` によるプロジェクト管理へ移行する、という段階的な導入がおすすめです。日々の依存インストールにかかる時間が減るだけでも、開発体験は大きく変わります。ぜひ一度、手元のプロジェクトで試してみてください。
