## はじめに

2026年のJavaScriptランタイム界隈で、最も勢いを感じるのが **Bun** です。2026年8月20日にリリースされた **Bun 1.4** では、ランタイム本体がZigからRustへ書き換えられ、10月の **1.4.4** ではPrettier互換のフォーマッタ `bun fmt` が追加されました。

いまやBunは「ランタイム + パッケージマネージャ + テストランナー + 型チェッカー + フォーマッタ」を1つのバイナリに詰め込んだ、まさにオールインワンのツールキットへと進化しています。

この記事では、Bun 1.4系の変更点を整理し、実務でどう使うのか、どこに注意すべきかを解説します。

## Bun 1.4の主な変更点

まずは全体像です。Bun 1.4では次のような変更が入りました。

- ZigからRustへの書き換え
- Node.jsのテストスイートから **1,517件** のテストを追加（1.0以来最大）
- 2,900件以上のissue修正
- アイドル時CPU使用率を最大 **5分の1** に削減
- メモリ使用量を最大 **35%** 削減
- Linuxでの起動を **50%高速化**
- `Bun.WebView`、`Bun.Image`、`Bun.markdown`、`Bun.cron()`、`Bun.Terminal` などの新API
- `bun run --parallel`、`bun test --parallel`
- `bun audit fix`、`bun dedupe`、`bun prune`

| 項目 | 改善幅 |
| --- | --- |
| アイドル時CPU | 最大 1/5 |
| メモリ使用量 | 最大 35% 削減 |
| Linux起動時間 | 50% 高速化 |
| Node.js互換テスト | +1,517件 |

数値だけ見てもかなり攻めたリリースであることが分かります。

## ZigからRustへ — 何が変わるのか

Bun 1.4の最大のトピックは、実装言語が **ZigからRustへ** 移行したことです。

これまでBunはZig製であることが特徴のひとつでしたが、Rustへの移行によって次のようなメリットが期待されます。

- メモリ安全性の向上
- Rustエコシステムからのコントリビュータ獲得
- 周辺ツールやライブラリとの連携がしやすくなる

利用者から見ると、CLIやJavaScript APIの使い勝手は基本的にこれまでと変わりません。ただし、ネイティブアドオンやビルド周りで内部実装に依存していた場合は、移行時に検証が必要です。特に本番利用では、バージョンを固定してCIで検証するのが無難でしょう。

### Node.js互換性の現在地

BunはNode.jsのドロップイン代替を目指しています。Bun 1.4では以下のモジュールで高い互換性が示されています。

- `node:events`、`node:sqlite`、`node:trace_events` → 100%
- `node:quic` → 99%
- `node:http`、`node:fs`、`node:cluster`、`node:timers`、`node:zlib`、`node:vm`、`node:stream` → 97%前後

とはいえ **100%互換ではない** 点は重要です。既存のNode.jsアプリをそのまま移す場合は、テストを厚めに用意しておきましょう。

## ツールチェーンが1つに集約される

Bun 1.4系で個人的に最も注目しているのが、開発ツールの統合です。

### bun fmt — Prettier互換のフォーマッタ

Bun 1.4.4で追加された `bun fmt` は、Prettier互換のフォーマッタです。既存のPrettierやoxfmtの設定ファイルを読み込んでくれるため、プロジェクトの設定を大きく変えずに乗り換えられます。

```bash
# フォーマットを実行
bun fmt

# CI向け：差分があるかをチェック
bun fmt --check
```

公式ブログでは、Prettierのリポジトリに対して **59.7ms**（比較対象は17.1秒）という計測や、oxfmt比で **3〜6倍高速** という結果が示されています。TailwindのクラスソートやSvelteのサポートも組み込まれているのが嬉しいポイントです。

フォーマッタを別途インストールする必要がなくなるので、依存関係を減らしたいプロジェクトには向いています。

### bun check — 組み込みの型チェッカー

Bun 1.4.3では、TypeScriptの型チェッカー `bun check` が追加されました。公式によると `tsc 7` 比で **3〜6.4倍高速** とのことです。

```bash
# 型チェック
bun check

# 実行前に型チェック
bun run --check dev

# ビルド前に型チェック
bun build --check ./src/index.ts

# テスト前に型チェック
bun test --check
```

`--check` を `run` / `build` / `test` に付けられるのが便利です。「実行は速いけど型チェックは別プロセス」という従来の面倒さが軽くなります。

### 並列実行

`--parallel` も地味に効きます。

```bash
# 複数のスクリプトを並列実行
bun run --parallel dev:api dev:web

# テストを並列実行
bun test --parallel
```

モノレポやフロント・バックエンド同時起動の場面で、わざわざ `concurrently` などを入れずに済みます。

## ランタイムの新API

Bun 1.4ではランタイムAPIも大きく拡充されました。

- `Bun.WebView` — ヘッドレスブラウザ自動化
- `Bun.Image` — 画像処理
- `Bun.markdown` — Markdownパース
- `Bun.cron()` — cronスケジューリング
- `Bun.Terminal` — ターミナル操作
- `Bun.SQL` — クエリあたりのCPU使用量を最大48%削減

特に `Bun.WebView` は、これまでPlaywrightなどを別途用意していたブラウザ自動化をランタイムに取り込むもので、テストやスクレイピングの選択肢が広がります。APIの詳細は公式ブログに譲りますが、依存を減らせる方向性は魅力的です。

また1.4.1では `Bun.serve` のHTTP/2対応や `crypto.argon2`、1.4.3では `Bun.FetchSession` や実験的な `Bun.ModuleGraph` なども追加されています。マイナーリリースの速度がかなり速いので、定期的にキャッチアップしておきたいところです。

## パッケージ管理とセキュリティ

サプライチェーン攻撃が話題になる中、パッケージマネージャ側の防御も進んでいます。

### インストールスクリプトの制限

Bun 1.4では、`postinstall` などのライフサイクルスクリプトの自動実行が制限され、**npmレジストリから取得したパッケージのみ** 自動信任の対象になりました。信頼できないソースからのインストールスクリプト実行を抑える動きで、npm 12やpnpm 12の流れとも一致しています。

### bun audit fix

脆弱性対応も組み込みで行えます。

```bash
bun audit
bun audit fix
```

別途 `npm audit` を呼び出す必要がないのは、オールインワンならではの利点です。

### その他のパッケージ管理機能

- `bun install` がYarn Berryの `yarn.lock` を移行
- `bun dedupe` で依存の重複を整理
- `bun prune` で不要なパッケージを削除
- `packageExtensions` によるメタデータ補完

移行時は、ロックファイルが意図通りに変換されているか必ず差分を確認しましょう。

## 導入方法

インストールはこれまで通り簡単です。

```bash
# 公式スクリプト
curl -fsSL https://bun.sh/install | bash

# Homebrew
brew install oven-sh/bun/bun

# Docker
docker pull oven/bun
```

既存のBunユーザーはアップグレードするだけです。

```bash
bun upgrade
```

## 導入時の注意点

便利な一方で、いくつか注意しておきたい点もあります。

1. **Node.js完全互換ではない** — 主要モジュールでも97%前後。移行前にテストを用意する。
2. **Rust書き換えの影響** — ネイティブアドオンやビルド設定は検証が必要。
3. **`bun fmt` は新しい** — Prettier互換とはいえ、初回はフォーマット差分を確認する。
4. **ロックファイル移行** — Yarn Berryからの移行は差分レビューを必須にする。
5. **バージョン固定** — リリースサイクルが速いため、CIと本番ではバージョンを固定する。

「とりあえず開発環境だけBunにする」といった段階的な導入が現実的です。

## まとめ

Bun 1.4は、単なる高速ランタイムから **開発ツールキット全体** へと踏み出したリリースでした。

- Rustへの書き換えで内部品質とパフォーマンスを強化
- `bun fmt` と `bun check` でフォーマッタと型チェッカーを統合
- `--parallel` で実行とテストを高速化
- `bun audit fix` などセキュリティ面も強化

「Node.js + npm + tsx + Jest + Prettier + tsc」と揃えていた道具が、1つのバイナリに寄っていく流れは、開発体験の面で大きな魅力です。まずは小さなプロジェクトで試し、差分と挙動を確認しながら採用を広げていくのが良さそうです。
