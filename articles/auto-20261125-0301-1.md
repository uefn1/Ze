Pythonの依存管理まわりは、長らく「道具が多すぎる」状態が続いてきました。`pip`、`venv`、`pip-tools`、`pipx`、`Poetry`、`pyenv`……。用途ごとにコマンドを覚え分ける必要があり、CIのセットアップも煩雑になりがちです。

そこで注目したいのが **uv** です。Rust製の超高速パッケージマネージャーで、Python本体のバージョン管理から仮想環境、依存解決、ロックファイル、ツール実行までを1つのCLIにまとめてくれます。

この記事では、uvの基本から実践的な使い方、既存プロジェクトからの移行までを一通り紹介します。

## uvとは

uvはAstral社が開発しているPython向けの統合ツールです。主な特徴は次のとおりです。

- **とにかく速い**: 依存解決やインストールが従来比で桁違いに高速
- **オールインワン**: `pip` / `venv` / `pip-tools` / `pipx` / `pyenv` 相当の機能を内包
- **ロックファイル標準搭載**: `uv.lock` による再現性のある環境構築
- **pyproject.toml ベース**: モダンなPythonパッケージング規格に準拠
- **クロスプラットフォーム**: macOS / Linux / Windows で同じように動く

「複数のツールを組み合わせる」から「uvひとつで完結する」へ、というのが一番の魅力です。

## インストール

公式のインストーラーを使うのが手軽です。

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

```powershell
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

すでにPython環境があるなら `pipx` 経由でも導入できます。

```bash
pipx install uv
```

インストール後はバージョンを確認しておきましょう。

```bash
uv --version
```

## プロジェクトを作る

新規プロジェクトは `uv init` で始めます。

```bash
uv init my-app
cd my-app
```

生成される `pyproject.toml` はこのような形です。

```toml
[project]
name = "my-app"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.12"
dependencies = []
```

`requires-python` を指定しておくと、uvが適切なPythonを自動で用意してくれます。Python本体のインストールもuvに任せられます。

```bash
# 利用可能なPythonを確認
uv python list

# 特定バージョンをインストール
uv python install 3.12
```

## 依存パッケージの追加・削除

依存の追加は `uv add` です。`pip install` のように「入れるだけ」ではなく、`pyproject.toml` と `uv.lock` を同時に更新してくれる点が重要です。

```bash
uv add requests
uv add --dev pytest ruff
```

削除は `uv remove`。

```bash
uv remove requests
```

追加後の `pyproject.toml` はこうなります。

```toml
[project]
name = "my-app"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [
    "requests>=2.32",
]

[dependency-groups]
dev = [
    "pytest>=8.0",
    "ruff>=0.6",
]
```

チーム開発では `uv.lock` を必ずコミットしましょう。`uv sync` を実行すれば、ロックファイルどおりの環境が誰のマシンでも再現されます。

```bash
uv sync
```

## スクリプトとツールを動かす

仮想環境を明示的にactivateしなくても、`uv run` がいい感じに環境を用意して実行してくれます。

```bash
uv run python main.py
uv run pytest
uv run ruff check .
```

ちょっとしたツールを一時的に使いたいときは `uvx`（`uv tool run` の短縮形）が便利です。

```bash
# インストールせずに実行
uvx ruff format .

# 常設ツールとしてインストール
uv tool install ruff
```

`pipx` を使っていた場面は、ほぼそのまま `uv tool` に置き換えられます。

## 既存プロジェクトからの移行

### requirements.txt からの移行

すでに `requirements.txt` がある場合は、そのまま取り込めます。

```bash
uv init --bare
uv add -r requirements.txt
```

`--bare` を付けると、サンプルコードを生成せず `pyproject.toml` だけを作ります。

### Poetry からの移行

Poetryの `pyproject.toml` は概ねそのまま読めます。`[tool.poetry]` セクションを `[project]` に寄せたうえで、依存を入れ直すのが確実です。

```bash
uv add $(cat requirements.txt)
```

あるいは既存のロックを尊重したい場合は、`uv pip install` 系のコマンドで段階的に移行する方法もあります。

```bash
uv venv
uv pip install -r requirements.txt
```

## CIでの活用

uvはセットアップが速いので、GitHub Actionsとの相性も良好です。公式アクションを使うと導入が簡単です。

```yaml
name: test

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install uv
        uses: astral-sh/setup-uv@v3
        with:
          enable-cache: true

      - name: Set up Python
        run: uv python install

      - name: Install dependencies
        run: uv sync --frozen

      - name: Run tests
        run: uv run pytest
```

`--frozen` を付けると `uv.lock` を更新せずに同期するため、CIではロックファイルとのズレを検出できます。キャッシュを有効にすれば2回目以降のジョブはさらに高速になります。

## 運用上の注意点

便利なuvですが、いくつか押さえておきたい点もあります。

- **`uv.lock` はコミットする**: アプリケーション開発では必須。ライブラリ開発でもチーム方針に合わせて管理しましょう。
- **`uv pip` は低レベルAPI**: `uv add` と混在させると意図しない挙動になりがちです。基本は `uv add` / `uv sync` に統一するのがおすすめです。
- **Python本体の管理方針を決める**: uvで入れるのか、システムや `pyenv` に任せるのかをチームで決めておくと混乱しません。
- **既存ツールとの共存**: `pip` や `Poetry` と併用する場合は、どちらが `pyproject.toml` を更新するのかを明確にしておきましょう。

## まとめ

uvは「Pythonの環境構築が面倒」という長年の課題に対して、速度と統合という2つの軸で答えてくれるツールです。

- `uv init` / `uv add` / `uv sync` でプロジェクト管理
- `uv run` / `uvx` で実行とツール利用
- `uv python install` でPython本体も管理
- `uv.lock` で再現性を担保

まずは小さなプロジェクトで `uv init` から試してみて、その速さを体感してみてください。一度慣れると、もう `pip` と `venv` を手で叩く生活には戻れなくなります。
