Pythonの環境構築といえば、長らく `pip`・`venv`・`pyenv`・`poetry` などを組み合わせるのが当たり前でした。しかしここ数年で、その常識をまとめて塗り替えつつあるツールがあります。Astral社が開発する **uv** です。

本記事では、uvが何を解決するのか、インストールから実務で使うコマンドまでを一通り紹介します。

## uvとは

uvはRust製の高速なPythonパッケージ・プロジェクトマネージャです。同じAstral社が手がけるリンタ「Ruff」と同じ設計思想で、**とにかく速い**ことが最大の特徴です。

単なる `pip` の高速版にとどまらず、次の役割を1つのバイナリで担います。

- パッケージ管理（pip互換）
- 仮想環境の作成（venv相当）
- Python本体のバージョン管理（pyenv相当）
- 依存解決とロックファイル（poetry / pipenv相当）
- スクリプトの依存管理と実行
- CLIツールの実行・インストール（pipx相当）

つまり、これまで複数のツールを繋ぎ合わせていた作業を、uvひとつに集約できます。

## インストール

公式のインストーラを使うのが手軽です。

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

```powershell
# Windows (PowerShell)
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

パッケージマネージャ経由でも入れられます。

```bash
brew install uv
# または
pipx install uv
```

インストール後はバージョンを確認しておきましょう。

```bash
uv --version
```

## pipの代替として使う

まずは既存のワークフローを置き換えるところから始めると導入しやすいです。`uv pip` サブコマンドはpipとほぼ同じ感覚で使えます。

```bash
# 仮想環境を作成
uv venv

# 有効化（従来どおり）
source .venv/bin/activate

# パッケージをインストール
uv pip install requests

# requirements.txt からまとめてインストール
uv pip install -r requirements.txt

# 現在の環境を書き出す
uv pip freeze > requirements.txt
```

`uv venv` は `.venv` を自動で作るため、`python -m venv` を叩く必要がありません。仮想環境を有効化せずとも、`uv pip install --python .venv/bin/python` のように対象を指定して操作できる点も便利です。

## プロジェクト管理: pyproject.toml + uv.lock

uvの本領はプロジェクト単位の管理にあります。`uv init` でプロジェクトを作ると、`pyproject.toml` が生成されます。

```bash
uv init my-app
cd my-app
```

依存関係の追加・削除は `uv add` / `uv remove` で行います。

```bash
uv add requests
uv add --dev pytest ruff
uv remove requests
```

`uv add` は `pyproject.toml` を更新し、同時に `uv.lock` を生成します。この **ロックファイルがあるおかげで、チーム全員が同じ依存バージョンを再現できます**。

依存関係を一括で揃えるのは `uv sync` です。

```bash
uv sync
```

`uv sync` はロックファイルと仮想環境の状態を一致させ、不要なパッケージも削除してくれます。`pip install -r` との違いは、**環境を「宣言された状態」に収束させる**点にあります。

## Python本体のバージョンを管理する

pyenvを使わなくても、uvがPython本体を管理できます。

```bash
# 利用可能なバージョンを確認
uv python list

# 特定バージョンをインストール
uv python install 3.12

# プロジェクトで使うバージョンを固定
uv python pin 3.12

# バージョンを指定して仮想環境を作成
uv venv --python 3.12
```

`uv python pin` を実行すると `.python-version` が生成され、プロジェクト単位でバージョンを固定できます。複数プロジェクトを横断して開発する人にとっては、この統合はかなり快適です。

## スクリプトを単体で実行する

uvはPEP 723のインラインスクリプトメタデータに対応しています。ちょっとしたスクリプトに依存を埋め込んで、そのまま実行できます。

```python
# /// script
# requires-python = ">=3.12"
# dependencies = ["requests"]
# ///
import requests

res = requests.get("https://example.com", timeout=10)
print(res.status_code)
```

このファイルは次のように実行できます。

```bash
uv run script.py
```

依存は自動で解決・キャッシュされるため、事前の `pip install` も仮想環境の有効化も不要です。後から依存を追加したい場合は次のコマンドが使えます。

```bash
uv add --script script.py httpx
```

「使い捨てスクリプトのために環境を作る」という手間から解放されます。

## CLIツールを実行する

`uvx`（`uv tool run` のエイリアス）を使うと、グローバル環境を汚さずにツールを実行できます。

```bash
# 一時的に実行
uvx ruff check .
uvx pycowsay "hello uv"

# 常設ツールとしてインストール
uv tool install ruff
uv tool list
```

pipxの代替として使えるうえ、実行のたびに隔離された環境が使われるため依存衝突の心配がありません。

## 既存プロジェクトからの移行

移行は段階的に進められます。まずは `uv pip` でpipを置き換え、慣れてきたら `pyproject.toml` + `uv.lock` の管理へ、という順序がおすすめです。

- `pip install` → `uv pip install`
- `python -m venv` → `uv venv`
- `pip freeze` → `uv pip freeze`
- `pip-compile` 相当 → `uv pip compile requirements.in -o requirements.txt`
- poetry / pipenv → `uv init` 後に `uv add` で依存を移し替え

CIではロックファイルを厳密に使うのが定石です。

```bash
uv sync --frozen
```

`--frozen` を付けるとロックファイルの更新を行わず、書かれたとおりに環境を構築します。再現性を保つため、`uv.lock` は必ずリポジトリにコミットしましょう。

## ハマりやすいポイント

導入時につまずきがちな点をまとめておきます。

- **`uv pip` と `uv add` は別物**。前者は低レベルのpip互換操作、後者はプロジェクト管理用です。`pyproject.toml` を管理しているなら基本は `uv add` を使います。
- **ロックファイルはコミットする**。`uv.lock` を無視すると再現性が失われます。
- **システムPythonを汚さない**。uvはデフォルトで仮想環境を前提とするため、意図せずグローバルへ入る事故が起きにくい設計です。
- **CIでは `--frozen`**。ロックファイルとの不整合を早期に検出できます。

## まとめ

uvは「速いpip」としてだけでなく、Python開発の環境構築をひとつにまとめるツールです。

- `pip`・`venv`・`pyenv`・`poetry`・`pipx` の役割を統合
- `uv.lock` による再現性の高い依存管理
- PEP 723対応でスクリプト実行も手軽
- Rust製で動作が高速

まずは `uv pip` から試し、プロジェクト管理へと移行していくと無理なく導入できます。まだ触ったことがない方は、この機会に既存プロジェクトの1つで試してみてはいかがでしょうか。
