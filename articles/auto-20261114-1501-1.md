## はじめに

AIコーディングエージェントが当たり前になり、開発中の「待ち時間」の価値が変わりました。人間だけでなく、エージェントも頻繁にlint・テスト・ビルドを実行します。つまり、**ツールの起動速度とフィードバックの速さが、そのまま開発体験に直結する**時代です。

本記事では、ここ数年で存在感を増している「速い・軽い・設定が素直」な開発ツールを5つ紹介します。特定のプロダクトの新機能ニュースではなく、日常の開発基盤として取り入れやすいものを中心にまとめました。

## 1. uv — Pythonの環境構築を高速化する

`uv` はAstralが開発するPythonのパッケージ・プロジェクト管理ツールです。Rust製で、依存解決やインストールが非常に高速なのが特徴です。

従来は `pip`、`venv`、`pip-tools`、`pyenv` などを組み合わせていた処理を、`uv` ひとつでかなり賃えます。

```bash
# プロジェクト作成
uv init my-app
cd my-app

# 依存追加
uv add requests

# スクリプト実行
uv run main.py
```

ロックファイルによる再現性のあるインストールや、Python本体のバージョン管理にも対応しています。CIでのセットアップ時間短縮を狙う場合にも相性が良いでしょう。

## 2. Ruff — lintとformatを1つに

`Ruff` もAstral製のPython向けツールで、LinterとFormatterを兼ねています。Flake8、isort、Blackなどで分担していた役割をまとめられるため、設定ファイルとCIのステップを減らせます。

```toml
# pyproject.toml
[tool.ruff]
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I", "UP"]
```

```bash
ruff check .
ruff format .
```

Rust製で起動が速く、エディタの保存時フォーマットとも組み合わせやすいのが利点です。まずはlintだけ導入し、チームの合意が取れたらformatterも有効化する、といった段階的な移行が現実的です。

## 3. Biome — JS/TSのlintとformatを統合

`Biome` はJavaScript/TypeScript向けのLinter・Formatterです。ESLintとPrettierの組み合わせを置き換える選択肢として注目されています。

```json
{
  "formatter": {
    "enabled": true,
    "indentStyle": "space"
  },
  "linter": {
    "enabled": true
  }
}
```

```bash
biome check .
biome format --write .
```

設定がひとつの `biome.json` に集約されるため、プラグインや設定の依存関係が複雑になりがちなESLint構成を整理したいときに便利です。ただし、既存プロジェクトでは独自ESLintルールとの互換性を確認してから移行しましょう。

## 4. Bun — 実行・パッケージ管理・テストをまとめる

`Bun` はJavaScript/TypeScriptのランタイムであり、パッケージマネージャやテストランナーも内蔵しています。Node.jsプロジェクトの一部をそのまま置き換えられる場合があり、インストールやスクリプト起動の速さが魅力です。

```bash
bun install
bun run dev
bun test
```

すべてを一度に置き換えるのではなく、まずはローカル開発のパッケージインストールやテストから試すのが安全です。Node.js固有のAPIやネイティブモジュールに依存している場合は、CIでの互換性確認を忘れないようにしましょう。

## 5. just — Makefileより読みやすいタスクランナー

`just` はコマンドを列挙して実行するタスクランナーです。Makefileに似ていますが、タブやファイル名依存の罠が少なく、クロスプラットフォームで扱いやすいのが特徴です。

```makefile
# justfile
test:
    uv run pytest

lint:
    ruff check .
    ruff format --check .

check: lint test
```

```bash
just check
```

プロジェクト固有のコマンドを `justfile` に集約しておくと、人間にもAIエージェントにも「何を実行すればよいか」が明確になります。READMEのコマンド例が古くなる問題も減らせるでしょう。

## 共通するトレンド

今回紹介したツールには、次のような共通点があります。

- 単一バイナリ、または起動の速い実装が多い
- 設定ファイルが少なく、役割が明確
- 「lint」「format」「test」などの定番操作を短いコマンドで実行できる
- CIやエディタとの連携がしやすい

AIエージェントに作業を任せる場合、ツールの出力が簡潔で、実行時間が短いことは特に重要です。エージェントが何度も試行錯誤する前提では、1回あたりのフィードバックが速いほど、結果的に品質も安定しやすくなります。

## 導入時の注意点

高速なツールは魅力的ですが、いきなり全部を置き換えるのはおすすめしません。

1. **まずローカルで試す** — 既存のCIはそのままにし、開発者個人の環境で検証する
2. **設定をリポジトリに置く** — `pyproject.toml` や `biome.json` などでチーム全体に配布する
3. **CIで差分を確認する** — lint結果やテスト結果が既存ツールと一致するか比較する
4. **移行範囲を小さく保つ** — formatterだけ、テストだけ、など段階的に進める

特にformatterの移行は大量の差分を生みやすいため、機能開発と混ぜず、専用のPRに分けるとレビューが楽になります。

## まとめ

- Pythonなら `uv` と `Ruff` で環境構築と品質チェックを高速化
- JS/TSなら `Biome` と `Bun` で設定と実行をシンプルに
- 日常のコマンドは `just` に集約して、人間にもAIにも優しい開発環境に

ツール選びの基準は「多機能さ」よりも、**チームが迷わず使えて、フィードバックが速いこと**です。まずは1つだけ導入し、効果を確認しながら広げていくのがよいでしょう。
