## はじめに

コードを書いている時間より、環境構築・lint・ビルド・検索に待たされている時間のほうが長い——そんな経験はないでしょうか。

近年の開発ツールは、RustやGoで書き直されることで**起動時間とフィードバック速度**が大きく改善されています。本記事では、日常の開発体験を静かに変えるCLIツールを7つ紹介します。すべて「入れて損がない」ものに絞りました。

## なぜ今、CLIツールを見直すのか

理由はシンプルです。**待ち時間は集中力を削ぐ**からです。

- 保存してからlint結果が出るまで3秒
- 依存追加のたびに数十秒のインストール
- プロジェクトごとにNodeやPythonのバージョンを切り替える手間

これらは1回では大したことなくても、1日に何十回も発生します。ツールを置き換えるだけで、この積み重ねが消えるなら投資対効果は高いと言えます。

## 1. uv — Python環境構築を秒で終わらせる

`uv` はAstral製のPythonパッケージマネージャです。pipやvenv、pyenvの役割をかなり置き換えられます。

```bash
uv init myapp
cd myapp
uv add requests
uv run python main.py
```

`uv run` は仮想環境の activate を忘れても動くのが便利です。Python本体のバージョン管理もできます。

```bash
uv python install 3.12
uv python pin 3.12
```

`pyproject.toml` と `uv.lock` で依存が再現可能になるため、チーム開発との相性も良好です。

## 2. Ruff — lintとformatを1ツールに

`Ruff` はPythonのlinter兼formatterです。Flake8、isort、pyupgradeなどの役割をまとめて担います。

```bash
ruff check --fix .
ruff format .
```

`pyproject.toml` に設定を集約できます。

```toml
[tool.ruff]
line-length = 100
target-version = "py312"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]
```

設定ファイルが1つにまとまるだけで、レビュー時の「どのルールが効いているのか分からない」問題が減ります。

## 3. Bun — ランタイム兼パッケージマネージャ

`Bun` はJavaScript/TypeScriptのランタイムであり、パッケージマネージャでもあります。

```bash
bun install
bun run dev
bun test
bunx create-vite
```

既存のNode.jsプロジェクトでも `bun install` を試すだけで、依存解決の速さを体感できます。まずはCIではなくローカルから試すのがおすすめです。

## 4. Biome — JS/TSのlintとformatを統合

`Biome` はJavaScript/TypeScript向けのlinter兼formatterです。ESLintとPrettierの設定が二重管理になりがちな問題を整理できます。

```bash
biome check --write .
biome format --write .
```

`biome.json` でルールを管理します。

```json
{
  "formatter": { "indentStyle": "space", "indentWidth": 2 },
  "linter": { "enabled": true, "rules": { "recommended": true } }
}
```

すべてのESLintプラグインを置き換えられるわけではないため、プロジェクトの依存ルールを確認してから段階的に移行しましょう。

## 5. mise — ランタイムのバージョン管理を統一

`mise` はNode、Python、Ruby、Goなどのバージョンを1つのツールで管理できます。asdfの代替として採用が進んでいます。

```bash
mise use -g node@22
mise use python@3.12
mise install
```

プロジェクト直下の `.mise.toml` に固定できます。

```toml
[tools]
node = "22"
python = "3.12"
```

「このリポジトリは何で動かすんだっけ」をREADMEから探す時間が減ります。

## 6. just — Makefileの代わりに

`just` はコマンドランナーです。Makefileのタブ地獄や、`.PHONY` の記述から解放されます。

```makefile
# justfile
dev:
    bun run dev

test:
    bun test

lint:
    biome check .
```

```bash
just --list
just test
```

レシピ名を一覧できるため、新しく参加したメンバーにも優しいです。

## 7. ripgrep / fd — 探す時間を短く

`ripgrep` と `fd` は、それぞれ `grep` と `find` の高速な代替です。

```bash
rg "TODO" --type ts
fd "\.test\.ts$"
```

`.gitignore` を尊重してくれるので、`node_modules` やビルド成果物を意識せず検索できます。エディタの検索で足りない場面の切り札として入れておくと便利です。

## 導入は「1つずつ」が失敗しない

おすすめの進め方は次のとおりです。

1. まず `ripgrep` と `fd` を入れる（既存フローへの影響が少ない）
2. 次に `Ruff` か `Biome` でlint/formatを統一する
3. パッケージマネージャ（`uv` / `bun`）は新規プロジェクトから試す
4. `mise` と `just` はチーム合意が取れてから導入する

一気に置き換えると、CIやエディタ拡張との差異でハマりやすくなります。**新規プロジェクトか個人環境から始める**のが安全です。

## チーム導入で気をつけたこと

- **ロックファイルは必ずコミットする**（`uv.lock`、`bun.lock` など）
- **CIのバージョンを固定する**（`mise` やセットアップアクションで明示）
- **エディタ設定を共有する**（formatterの競合を防ぐ）
- **移行期間を設ける**（旧ツールと併用し、警告だけ出す期間を作る）

特にformatterの二重適用は、差分がノイズになる最大の原因です。どちらか一方に寄せましょう。

## まとめ

今回紹介したツールは、いずれも「導入した瞬間に速さを実感しやすい」ものばかりです。

| ツール | 置き換えるもの | 効果 |
| --- | --- | --- |
| uv | pip / venv / pyenv | 環境構築と依存解決の高速化 |
| Ruff | Flake8 / isort / Black | lintとformatの統合 |
| Bun | npm / Node | インストールと実行の高速化 |
| Biome | ESLint / Prettier | JS/TSの設定統一 |
| mise | asdf / nvm / pyenv | バージョン管理の一本化 |
| just | Make | コマンド定義の整理 |
| ripgrep / fd | grep / find | 検索の高速化 |

すべてを今日入れる必要はありません。**一番待たされていると感じる工程から**、1つだけ試してみてください。開発環境の速度は、そのまま思考の速度につながります。
