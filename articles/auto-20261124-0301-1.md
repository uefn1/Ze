## はじめに

ここ数年、開発ツール界隈でひとつの大きな流れが続いています。それは**「RustやGoで書き直された、とにかく速いツール」**の台頭です。

従来はPythonのpip、JavaScriptのESLintやPrettier、Node.jsのnpmといった「定番」を何となく使い続けるのが普通でした。しかし今は、同じ役割をより高速に、よりシンプルにこなす選択肢が育っています。

この記事では、日々の開発体験を確実に軽くしてくれるツールを5つ、実際の使い方とともに紹介します。特定のバージョンに依存した話は避け、執筆時点で広く使える内容に絞りました。導入前に公式ドキュメントで最新仕様を確認してください。

## なぜ今「速いツール」なのか

理由はシンプルです。**待ち時間は集中力を削ぐ**からです。

- Lintやフォーマットが数秒待たされるたびに、思考の流れが切れる
- 依存解決やテスト実行が遅いと、CIのフィードバックも遅れる
- 設定ファイルが複雑だと、新メンバーの学習コストが上がる

最近のツールは「速い」だけでなく、**設定を減らす**方向に振り切っているものが多く、結果としてチーム全体の保守コストが下がります。

## 1. uv — Pythonの依存管理と仮想環境を一本化

Pythonの環境構築は長らく悩みの種でした。pip、venv、pip-tools、pyenv...と道具が分散しがちです。`uv` はこれらをひとつにまとめ、非常に高速に動作します。

```bash
# プロジェクト初期化
uv init myapp
cd myapp

# 依存追加（ロックファイルも自動生成）
uv add requests

# 仮想環境込みでスクリプト実行
uv run python main.py
```

`uv.lock` が生成されるため、再現性の高い環境を保てます。Python本体のバージョン管理もこなせるので、pyenvを別途入れる必要が減るのも嬉しい点です。

## 2. Ruff — Lintとフォーマットを1ツールに

`Ruff` はPythonのLinter兼フォーマッタです。従来のFlake8・isort・Blackをまとめて置き換えられるケースが多く、実行速度も桁違いです。

```toml
# pyproject.toml
[tool.ruff]
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]
```

設定は `pyproject.toml` に集約でき、`ruff check --fix` と `ruff format` の2コマンドでほぼ完結します。ツールごとに設定が散らばらないのが精神衛生的にも良いです。

## 3. Biome — JS/TSのLintとフォーマットを高速化

JavaScript/TypeScriptでは `Biome` が有力です。ESLintとPrettierの役割をひとつにまとめ、Rust製の高速実行が特徴です。

```bash
npx @biomejs/biome check --write .
```

`biome.json` でルールを管理し、`check` 一発でLint・フォーマット・import整理まで行えます。既存プロジェクトにESLintのルール資産が大量にある場合は、無理に全部移行せず、新規プロジェクトから試すのが現実的です。

## 4. Bun — 実行・テスト・パッケージ管理を一体化

`Bun` はJavaScriptランタイムであり、パッケージマネージャであり、テストランナーでもあります。

```bash
bun install
bun run dev
bun test
```

複数のツールを組み合わせる必要が減り、特に小〜中規模のプロジェクトでは構成がすっきりします。一方で、Node.js固有の挙動に依存するライブラリでは差異が出ることがあるため、本番導入は検証を挟むと安心です。

## 5. just — Makefileより読みやすいタスクランナー

`just` はコマンドを並べるだけのシンプルなタスクランナーです。Makefileのタブ地獄や暗黙ルールに悩まされずに済みます。

```just
# justfile
test:
    uv run pytest

lint:
    uv run ruff check .
    npx @biomejs/biome check .

check: lint test
```

`just check` のようにタスクを呼び出せ、依存関係も宣言できます。プロジェクトの「よく使うコマンド」を1か所に集約できるので、READMEのコマンド欄が短くなる副産物もあります。

## 導入時の注意点

速さや便利さだけで飛びつくと、思わぬところでハマります。特に意識したいのは次の3点です。

- **チームの合意を取る**: 個人の環境だけ変えると、CIや他メンバーの環境とズレる
- **CIと手元を揃える**: バージョンを固定し、ロックファイルをコミットする
- **段階的に移行する**: まずフォーマット、次にLint、最後に実行環境、のように一歩ずつ

## まとめ

今回紹介したツールに共通するのは、**「速い」だけでなく「設定と道具を減らす」**という設計思想です。

| ツール | 主な役割 | 置き換え対象の例 |
| --- | --- | --- |
| uv | Python環境・依存管理 | pip / venv / pyenv |
| Ruff | Lint・フォーマット | Flake8 / Black / isort |
| Biome | JS/TSのLint・フォーマット | ESLint / Prettier |
| Bun | 実行・テスト・依存管理 | npm / Jest |
| just | タスクランナー | Makefile |

全部を一度に導入する必要はありません。まずは1つ、いちばん待ち時間が気になっている作業から試してみると、効果を実感しやすいはずです。
