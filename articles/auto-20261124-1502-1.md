ここ数年、RustやGoで書かれた高速なCLIツールが実用段階に定着してきました。大きなフレームワークを入れ替えなくても、日々のコマンド操作を少しずつ短くするだけで、開発のリズムは確実に変わります。

本記事では、既存のワークフローに自然に組み込めるCLIツールを7つ、導入コマンドと注意点つきで紹介します。

## 選定のポイント

ツールを選ぶ際は、次の観点を重視しました。

- 既存のシェルやエディタと併用できる
- 設定が小さく、チームへ展開しやすい
- 学習コストに対して得られる効果が大きい
- メンテナンスが活発で、普段の開発を止めない

流行を追うことよりも、自分の手に馴染むかを基準にすると定着しやすくなります。

## 1. mise — 言語とツールのバージョンを1か所で管理

miseは、Node.jsやPython、Goなどのバージョンをプロジェクト単位で切り替えられるツールです。従来のnvmやpyenvを置き換えたり、併用したりできます。

```bash
mise use --global node@22
mise install
```

プロジェクト直下に`mise.toml`を置けば、リポジトリに入った瞬間に必要なバージョンへ切り替わります。

```toml
[tools]
node = "22"
python = "3.12"
```

既存のバージョン管理ツールとPATHが競合する場合は、シェルの初期化順序を確認してください。まずは1つの言語だけで試すと安全です。

## 2. just — Makefileより読みやすいタスクランナー

justは、よく使うコマンドを`justfile`にまとめて実行できるタスクランナーです。Makeのタブインデント問題がなく、レシピを素直に書けます。

```make
# justfile
test:
    cargo test

lint:
    cargo clippy -- -D warnings
```

```bash
just test
just --list
```

`just --list`でタスク一覧を確認できるため、新しく参加したメンバーも使い方を把握しやすいのが利点です。ただしMakeの依存解決や機能をすべて置き換えるものではないため、既存のビルド体系とは役割を分けて考えましょう。

## 3. zoxide — 履歴からディレクトリへ一発移動

zoxideは、訪問履歴をもとにディレクトリを移動できる`z`コマンドを提供します。長いパスを何度も入力する必要がなくなります。

```bash
eval "$(zoxide init bash)"
z project
```

一部の文字列を入力するだけで、よく使うディレクトリへ移動できます。初回は履歴がないため、しばらく`cd`を使ってから効果が出始めます。シェルごとに初期化コマンドが異なる点だけ注意してください。

## 4. fzf — あいまい検索で候補を絞る

fzfは、標準入力の候補をあいまい検索できるツールです。シェル連携を有効にすると、履歴検索やファイル選択が快適になります。

```bash
# 例: パッケージマネージャから導入
sudo apt install fzf
```

導入後は`Ctrl-R`でコマンド履歴、`Ctrl-T`でファイル選択、`Alt-C`でディレクトリ移動が使えるようになります。既存のキーバインドと衝突する場合は、設定で変更できます。

## 5. ripgrep — 高速で.gitignoreを尊重する検索

ripgrepは`rg`コマンドで使う検索ツールです。高速なだけでなく、デフォルトで`.gitignore`を尊重するため、検索結果がノイズになりにくいのが特徴です。

```bash
rg "TODO" src/
rg -t ts "useEffect"
```

`-t`でファイル種別を指定すれば、対象を絞った検索ができます。隠しファイルや無視対象も含めたい場合は`-uu`を使いますが、まずはデフォルトの挙動に慣れると扱いやすくなります。

## 6. lazygit — Git操作をターミナルで俯瞰

lazygitは、Gitの状態をターミナル上で一覧しながら操作できるTUIツールです。ステージング、コミット、stash、rebaseなどをキーボードで行えます。

```bash
lazygit
```

差分を見ながら部分的にステージできるため、コミットの粒度を整えたいときに便利です。ただし複雑な操作は結局Gitの理解が必要です。最初は閲覧と部分ステージから使い始めると、事故を減らせます。

## 7. direnv — ディレクトリごとに環境変数を自動切替

direnvは、ディレクトリに入ると`.envrc`の内容を自動で読み込み、出ると元に戻すツールです。プロジェクトごとの環境変数を切り替える手間を減らせます。

```bash
echo 'export API_URL=http://localhost:3000' > .envrc
direnv allow
```

`.envrc`はシェルスクリプトとして実行されるため、信頼できるリポジトリでのみ`allow`してください。`.envrc`をコミットするか、個人用に留めるかはチームの方針を決めておくと運用が安定します。

## 組み合わせの例

miseとdirenvを入れておくと、リポジトリへ移動した時点で言語バージョンと環境変数が揃います。そこにjustを加えれば、テストやLintの実行コマンドも統一できます。

さらにzoxide、fzf、ripgrep、lazygitを加えると、移動・検索・Git操作の往復が短くなります。すべてを一度に入れる必要はありません。まずは1つだけ導入し、効果を実感してから広げるのがおすすめです。

## 導入時の注意点

- シェルの初期化ファイルは、既存設定との順序を確認する
- チーム全員への強制はせず、まず個人で試す
- ツールのバージョンは固定し、CIとローカルで揃える
- direnvのようにコードを実行するツールは、信頼できる対象だけ許可する

## まとめ

AIを使った開発支援が注目される一方で、土台となるターミナル操作を速くする効果は、地味ですが確実に積み上がります。

今回紹介した7つは、いずれも小さく試せて、合わなければすぐ外せます。気になったものを1つだけ、今日の開発環境に足してみてください。
