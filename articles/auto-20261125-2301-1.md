## はじめに

Pythonの開発環境構築といえば、長らく `pip` と `venv`、そしてプロジェクト管理には Poetry や pip-tools を組み合わせるのが定番でした。しかしここ数年で、Astral 社が開発する **uv** が急速に存在感を増しています。

uv は Rust 製の超高速な Python パッケージマネージャー兼プロジェクトマネージャーです。pip・pip-tools・pipx・Poetry・pyenv・virtualenv といった複数のツールの役割を、ひとつの CLI にまとめてくれます。

本記事では、uv の基本的な使い方と、従来ツールからの移行ポイントを整理します。

## uvとは

uv の特徴を一言で表すと「**速い・全部入り・ロックファイルが強力**」です。

- Rust 製で、pip と比べて 10〜100 倍高速とされる
- 仮想環境の作成、依存解決、ロック、Python 本体のバージョン管理まで一貫して担当
- `pyproject.toml` と `uv.lock` による再現性の高い依存管理
- `uv pip` という pip 互換インターフェースも用意されていて移行が容易

特に「依存解決が速い」点は、CI の実行時間やローカル開発の体験に直結します。大規模なプロジェクトほど恩恵を実感しやすいでしょう。

## インストール

インストールは公式スクリプトを使うのが手軽です。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

macOS の Homebrew や、pip 経由でも導入できます。

```bash
brew install uv
# または
pip install uv
```

インストール後はバージョンを確認しておきましょう。

```bash
uv --version
```

## プロジェクトを作成する

新規プロジェクトは `uv init` で始めます。

```bash
uv init myproject
cd myproject
```

これだけで `pyproject.toml`、`README.md`、`.python-version`、サンプルの `main.py` などが生成されます。`uv init --lib` を使えばライブラリ用の構成、`uv init --app` ならアプリケーション用の構成になります。

## 依存関係を追加する

依存パッケージの追加は `uv add` です。自動で仮想環境が作られ、`pyproject.toml` と `uv.lock` が更新されます。

```bash
uv add requests
uv add --dev pytest ruff
```

開発用の依存は `--dev` を付けることで分離できます。削除は `uv remove` です。

```bash
uv remove requests
```

既存の `requirements.txt` から移行する場合は、`uv add` でまとめて取り込めます。

```bash
uv add -r requirements.txt
```

## スクリプトを実行する

uv 管理下のプロジェクトでは、`uv run` を使うと仮想環境を意識せずにコマンドを実行できます。

```bash
uv run main.py
uv run pytest
```

`uv run` は実行前に依存関係を同期してくれるため、「環境を作り忘れて動かない」という事故が減ります。仮想環境を手動で activate する必要もありません。

## 依存関係を同期・固定する

チーム開発や CI では、ロックファイルに基づいて環境を再現します。

```bash
uv sync
```

`uv sync` は `uv.lock` の内容に合わせて仮想環境を整えます。`--frozen` を付けるとロックファイルを更新せずに同期するため、CI での再現性が高まります。

```bash
uv sync --frozen
```

ロックファイルだけを更新したい場合は `uv lock` です。

## Pythonのバージョンを管理する

uv は Python 本体のバージョン管理もこなします。pyenv を別途入れる必要がありません。

```bash
uv python install 3.12
uv python pin 3.12
```

`uv python pin` で `.python-version` にバージョンが記録され、プロジェクトごとに使用する Python を固定できます。複数バージョンの切り替えも簡単です。

## ツールを一時実行する

pipx のように、グローバル環境を汚さずに CLI ツールを実行できます。

```bash
uvx ruff check .
```

`uvx` は `uv tool run` のショートカットで、必要ならツールを一時的に取得して実行します。常設したい場合は `uv tool install` を使います。

```bash
uv tool install ruff
```

## 従来ツールとの対応関係

移行時に混乱しやすいので、役割の対応をまとめておきます。

| 用途 | 従来のツール | uv |
| --- | --- | --- |
| パッケージ導入 | pip | `uv add` / `uv pip install` |
| 仮想環境 | venv / virtualenv | `uv venv` |
| 依存解決・ロック | pip-tools / Poetry | `uv lock` / `uv sync` |
| Python バージョン管理 | pyenv | `uv python` |
| CLI ツール実行 | pipx | `uvx` / `uv tool` |

既存の pip ワークフローをそのまま使いたい場合は、`uv pip install` や `uv venv` がほぼ互換的に動くので、段階的な移行が可能です。

## 移行のポイント

実際に移行する際に押さえておきたい点をいくつか挙げます。

- **まずは `uv pip` から**: いきなりプロジェクト管理まで移行せず、pip 互換コマンドで速さを体感するのがおすすめです。
- **`uv.lock` は必ずコミット**: 再現性の要です。`.gitignore` に入れないよう注意しましょう。
- **CI では `uv sync --frozen`**: ロックファイルを勝手に更新させない設定が安全です。
- **Python バージョンは `.python-version` で固定**: チーム内の環境差異を減らせます。

## まとめ

uv は「速さ」だけでなく、Python 開発周辺のツールをひとつに統合してくれる点が魅力です。仮想環境・依存解決・バージョン管理・ツール実行が一貫した CLI で扱えるため、環境構築の悩みがかなり減ります。

まずは小さなプロジェクトで `uv init` と `uv add` を試し、快適さを確認してみてください。pip に戻れなくなるかもしれません。
