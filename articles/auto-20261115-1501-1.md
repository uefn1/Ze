## はじめに

2026年11月、開発ツール界隈の主役は完全に「ターミナルで動くAIエージェント」になりました。コードを提案するだけの時代は終わり、いまは**複数のエージェントを並列で走らせ、どれだけ安全に監督できるか**がツール選びの軸になっています。

この記事では、直近のリリースノートや公式ブログを追いながら、実務に効くアップデートを整理します。「全部追うのは無理」という人のために、影響度の高いものだけを拾いました。

## 1. CLIエージェントは「並列実行」フェーズへ

### Codex CLI 0.167 / 0.169

OpenAIのCodex CLIは、`codex agents` による**エージェントのコマンドセンター**を導入しました。0.167.0では `--no-daemon` 付きで複数タスクを一画面から監督でき、未読の結果がマークされます。0.169.0ではターミナルワークスペースに複数のサイドチャットタブが追加され、再起動後もローカルのサイドチャットを再開できるようになりました。

ポイントは「1タスク＝1セッション」から「複数タスクを束ねて監督する」への転換です。レビューや中断からの復帰がボトルネックになるので、**3並列くらいのタスクを流して復旧できるか**をまず試すのがおすすめです。

```bash
# インストール例（公式の手順に従ってください）
npm install -g @openai/codex
codex agents --no-daemon
```

### OpenCode 2.3.0

オープンソースのOpenCodeも同じ方向に進んでいます。2.3.0では**サブエージェントがデフォルトでバックグラウンド実行**になり、アイドル時に親セッションへ報告する方式に変更されました。TUIはツール呼び出しを折りたたみ可能な行にまとめ、会話の見通しがかなり良くなっています。

特定ベンダーにロックインされず、75以上のプロバイダーを切り替えられるのが強みです。`/init` で `AGENTS.md` を生成し、プロジェクト固有の文脈をエージェントに渡せます。

```bash
curl -fsSL opencode.ai/install | bash
opencode
```

### Google系の選択肢

Googleは個人・Google Oneユーザー向けにGemini CLIから**Antigravity CLI（`agy`）**へと導線を移しています（2026年6月18日付）。一方、Gemini CLI自体は有料APIキーやエンタープライズ向けに残っており、コンテナサンドボックスとIDE Companionのブリッジ、キャンセル後のツール実行防止などが追加されています。

つまり「無料で使いたいならAntigravity、APIキーで組むならGemini CLI」という住み分けです。どちらを使うにせよ、**キャンセル後に本当にツールが止まるか**は一度テストしておく価値があります。

## 2. エージェントに「文脈」を与えるMCPの標準化

ツール単体の性能より、**エージェントが組織やプロダクトの文脈をどれだけ読めるか**が成果を左右する——この認識が一気に広がりました。

- **Red Hat Developer Hub 2.1**（11月2日）は「agent-ready」を掲げ、MCP経由でAIエージェントにソフトウェアカタログや標準プラクティスを渡します。エージェント向けCLIで、既存サービスとの重複や未承認技術の採用を抑える狙いです。
- **RHEL 10.3 / 9.9**（11月11日）では、RHEL用MCPサーバーがGA。コマンドラインからのAI支援トラブルシューティングが正式に使えるようになりました。
- **OpenCode Browse**（11月6日発表）は、MITライセンスのMCPサーバー＋Chromium拡張で、エージェントが**実際にログイン済みのブラウザ**を操作できます。ログインや2FA、決済は人間にタブを返す設計です。

ここで重要なのは、MCPは「魔法の箱」ではないという点です。渡す文脈が古いTODOや死んだコードだらけだと、エージェントはそのまま迷走します。Googleのエンジニアも「agent distraction（エージェントの気散らし）」として、技術的負債の整理がエージェントの出力品質に直結すると指摘しています。**リファクタリングは人間のためだけでなく、エージェントのためでもある**わけです。

## 3. 地味だけど重要：言語とセキュリティのアップデート

華やかなAIニュースの陰で、見逃すと痛い変更もあります。

### Rust 1.100

10年越しで `!`（never type）が任意の場所で型として書けるようになり stabilized。`Vec` と `Box` のアロケータAPIのコアも安定化され、ロールバック用の `DropGuard` が追加されました。Cargoには未使用依存のレポートと、公開直後のクレートを一定期間避ける `min-publish-age` 設定が入り、**サプライチェーン攻撃への防御**が現実的になっています。

```toml
# Cargo.toml の例（新しすぎるクレートを避ける）
[registries.crates-io]
# min-publish-age はCargoのドキュメント記載の形式に従って設定
```

### Git 2.56.1 系のセキュリティ修正

悪意あるリポジトリの再帰クローン時のコード実行、サーバーが広告するHEAD経由のパストラバーサル、マージやバイナリパッチでのメモリ破壊など、6件の脆弱性が修正されました。**Gitを同梱するツールも含めて更新**が推奨されています。

### Rust標準ライブラリのメモリ安全性

MicrosoftのFORGE Labは、AI駆動スキャナで `std` / `core` の安全性バグを発見したと報告しました。safe Rustだけで書かれたコードが未定義動作を引き起こすケースがあり、主に `unsafe` 内部がパニックやユーザー実装の正しさを信頼しすぎている箇所だといいます。「Rustなら絶対安全」ではなく、**境界の `unsafe` をどう監査するか**が引き続き論点です。

## 4. ツール選定の指針

直近の動きを踏まえると、選定基準は次の3点に集約できます。

| 観点 | 問いかけ | チェック例 |
| --- | --- | --- |
| 並列性 | 複数タスクを監督・復帰できるか | 3並列で中断→再開を試す |
| 文脈 | リポジトリや組織の規約を読めるか | `AGENTS.md` / MCPの接続確認 |
| 安全性 | 危険操作を止められるか | サンドボックス、権限、キャンセル動作 |

特に「安全性」は軽視されがちです。11月には、xAIのGrok Buildで作られた約35,000のアプリが誰でもアクセス可能で、機密情報が露出していたという報告もありました。エージェントにデプロイまで任せるなら、**アクセス既定値の確認をワークフローに組み込む**必要があります。

## まとめ

- CLIエージェントは「並列実行＋監督」が標準機能に。Codex CLIとOpenCodeのアップデートが象徴的
- MCPは文脈供給の共通言語になりつつある。ただし文脈の質＝コードベースの健全性
- Rust 1.100やGitのセキュリティ修正など、基盤ツールの更新も欠かせない
- 選定軸は「並列性・文脈・安全性」。特に危険操作の停止とアクセス既定値の確認を習慣化したい

新機能を追うだけでなく、**自分のワークフローに組み込んで検証する**ところまでが2026年の開発者術なのだと思います。
