## はじめに

Pythonの開発環境構築は、長らく「ツールが多すぎる」問題を抱えてきました。パッケージ管理は `pip`、仮想環境は `venv`、Python本体のバージョン管理は `pyenv`、ツール実行は `pipx`……と、目的ごとに別々のコマンドを覚える必要があります。

この状況を一変させたのが、Astral社が開発する **uv** です。Rust製で非常に高速なうえ、パッケージ管理・仮想環境・Pythonバージョン管理・ツール実行をひとつのCLIに統合しています。本記事では、uvの基本から実践的な使い方までを一気に紹介します。

## uvとは

uvは「Python向けの超高速パッケージインストーラ兼リゾルバ」として登場し、現在はPython開発ワークフロー全体をカバーするツールに成長しています。主な特徴は次のとおりです。

- **高速**: 依存解決とインストールがpipより桁違いに速い
- **オールインワン**: `pip` / `venv` / `pyenv` / `pipx` の役割を統合
- **ロックファイル**: `uv.lock` による再現性の高い依存管理
- **標準準拠**: `pyproject.toml` を中心としたモダンな構成

まずはインストールから見ていきましょう。

## インストール

公式のインストーラを使うのが最も簡単です。

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Homebrewやpipからも導入できます。

```bash
brew install uv
# または
pip install uv
```

インストール後はバージョンを確認しておきましょう。

```bash
uv --version
```

## プロジェクトを作成する

uvでは `uv init` でプロジェクトの雛形を作成します。

```bash
uv init my-app
cd my-app
```

生成される `pyproject.toml` がプロジェクト設定の中心です。アプリケーション用とライブラリ用でテンプレートを切り替えられます。

```bash
# ライブラリ用（ビルド設定を含む）
uv init --lib my-lib
```

## 依存関係を管理する

依存パッケージの追加は `uv add` です。`pip install` と違い、`pyproject.toml` と `uv.lock` の両方が自動で更新されます。

```bash
uv add requests
uv add --dev pytest ruff
```

削除は `uv remove`、ロックファイルに従って環境を同期するのは `uv sync` です。

```bash
uv remove requests
uv sync
```

`uv sync` は `uv.lock` の内容どおりに仮想環境を構築するため、チーム全員が同じ依存関係を再現できます。CIでは `--frozen` を付けてロックファイルの変更を禁止するのが定番です。

```bash
uv sync --frozen
```

## スクリプトを実行する

`uv run` を使うと、仮想環境を明示的にアクティベートしなくてもコマンドを実行できます。

```bash
uv run python main.py
uv run pytest
```

さらに便利なのが **PEP 723** のインラインスクリプトメタデータ対応です。スクリプトファイル内に依存を書いておけば、単体で実行可能になります。

```python
# /// script
# requires-python = ">=3.12"
# dependencies = ["httpx"]
# ///
import httpx

response = httpx.get("https://example.com")
print(response.status_code)
```

このファイルは次のコマンドだけで動きます。依存はuvが自動で解決してくれます。

```bash
uv run script.py
```

ちょっとした検証スクリプトを共有するときに非常に便利です。

## Python本体のバージョンを管理する

uvはPythonインタプリタのインストールと切り替えも担います。`pyenv` を別途入れる必要はありません。

```bash
# 利用可能なバージョンを確認
uv python list

# 特定バージョンをインストール
uv python install 3.12

# プロジェクトで使うバージョンを固定
uv python pin 3.12
```

`uv python pin` を実行すると `.python-version` が生成され、プロジェクトのバージョンが固定されます。

## ツールを一時実行する

`pipx` の代わりに `uvx`（`uv tool run` のエイリアス）が使えます。グローバル環境を汚さずにCLIツールを実行できます。

```bash
# 一時実行
uvx ruff check .

# 常設インストール
uv tool install ruff
```

## 従来ツールとの対応表

移行時の参考として、よく使うコマンドの対応をまとめます。

| 従来 | uv |
| --- | --- |
| `pip install` | `uv add` / `uv pip install` |
| `pip uninstall` | `uv remove` |
| `python -m venv .venv` | `uv venv` |
| `pyenv install` | `uv python install` |
| `pipx run` | `uvx` |
| `pip-compile` | `uv lock` |

既存プロジェクトで `requirements.txt` を使っている場合は、`uv add -r requirements.txt` で取り込むこともできます。

## 移行のポイント

実際に移行する際に意識したい点を挙げます。

- **`uv.lock` はコミットする**: アプリケーションでは再現性のため必ずバージョン管理に含める
- **CIでは `--frozen`**: ロックファイルと `pyproject.toml` の不整合を検出できる
- **`uv pip` は緊急用**: 通常は `uv add` を使い、`pyproject.toml` を唯一の情報源にする
- **Docker**: 公式イメージ `ghcr.io/astral-sh/uv` を使うと構築が簡単

Dockerでの最小例は次のようになります。

```dockerfile
FROM ghcr.io/astral-sh/uv:python3.12-bookworm-slim
WORKDIR /app
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev
COPY . .
CMD ["uv", "run", "python", "main.py"]
```

## まとめ

uvは「速いpip」から始まり、今やPython開発環境の統一ツールとして完成度を高めています。

- `uv init` / `uv add` / `uv sync` でプロジェクト管理
- `uv run` で仮想環境を意識せず実行
- `uv python` でインタプリタ管理
- `uvx` でツール実行

複数のツールを使い分けていた手間がなくなり、コマンド体系も一貫するため、新規プロジェクトはもちろん既存プロジェクトの移行にもおすすめです。まずは小さなスクリプトを `uv run` で動かすところから試してみてください。
