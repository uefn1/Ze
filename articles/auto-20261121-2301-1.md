コードを探す、ファイルを開く、コマンドを実行する。開発中のこうした作業は一つひとつは数秒でも、積み重なると大きな時間になります。本記事では、従来のコマンドを置き換えて作業の待ち時間と迷いを減らすモダンCLIツールを7つ紹介します。

## 選定のポイント

今回のツールは、次の条件を意識して選びました。

- 起動が速く、大量のファイルでも待たされにくい
- デフォルト設定のままでも使いやすい
- `.gitignore` など既存のプロジェクトルールを尊重する
- 既存コマンドと共存でき、導入・撤去が簡単
- シェルスクリプトやCIへ過度に依存させない

すべてを一度に置き換える必要はありません。まずは一番よく使う操作から試すのがおすすめです。

## 1. ripgrep — grepを高速化する

ripgrep（`rg`）はRust製の検索ツールです。再帰検索がデフォルトで、`.gitignore` を尊重しながら高速にコードを探せます。

```bash
rg "TODO"
rg -t ts "useEffect"
rg -l "deprecated" src/
```

`-t` で言語を指定できるため、TypeScriptやRustなど対象を絞った検索が快適です。`.gitignore` を無視して検索したい場合は `-u`、隠しファイルも含める場合は `--hidden` を使います。

```bash
rg -uu "secret"
```

grepに慣れている人ほど、検索対象の絞り込みと速度の差を実感しやすいツールです。

## 2. fd — findより直感的なファイル検索

fdはRust製のファイル検索ツールです。findよりも短い記法で、ファイル名や拡張子から目的のファイルを探せます。

```bash
fd logo
fd -e tsx
fd -e md -x wc -l {}
```

デフォルトでスマートケースと`.gitignore`の尊重が有効になっています。隠しファイルを探す場合は `-H`、ignore対象も含める場合は `-I` を付けます。

```bash
fd -H -I "\.env"
```

`-x` を使えば検索結果に対してコマンドを実行できるため、一括処理の起点としても便利です。

## 3. bat — catに色と行番号を

batはRust製の`cat`代替です。構文ハイライト、行番号、Gitの差分表示を備えており、ファイルの中身を確認するだけで情報量が増えます。

```bash
bat src/main.rs
bat --diff README.md
```

パイプやスクリプト内で使うときは、ページャーを無効にすると扱いやすくなります。

```bash
bat --paging=never --style=plain config.yml
```

`cat`の完全な代替としてaliasにしてもよいですが、出力が装飾されることを前提にしていないスクリプトでは注意が必要です。

## 4. fzf — あいまい検索で履歴とファイルを横断

fzfはGo製のファジーファインダーです。コマンド履歴、ファイル一覧、Gitブランチなど、標準入力から渡したものをあいまい検索できます。

```bash
# シェル統合を有効にすると使える操作
# Ctrl+R: 履歴検索
# Ctrl+T: ファイル選択
# Alt+C: ディレクトリ移動
```

パイプと組み合わせると真価を発揮します。

```bash
fd -e ts -e tsx | fzf --preview 'bat --color=always --line-range=:80 {}'
git branch | fzf
```

プレビューを付けておくと、ファイルを開く前に中身を確認できるため、選択の迷いが減ります。

## 5. zoxide — cdを学習する

zoxideはRust製のディレクトリ移動ツールです。訪問履歴と頻度を記録し、ディレクトリ名の一部から目的の場所へ移動できます。

```bash
eval "$(zoxide init bash)"
z proj
zi
```

`z` は履歴から候補を選んで移動し、`zi` はfzfのようなインターフェースで対話的に選択します。深い階層を行き来するプロジェクトほど効果を実感しやすいでしょう。

シェルごとに初期化コマンドが異なるため、zshやfishを使っている場合は公式の手順に合わせて設定してください。

## 6. eza — lsを読みやすく

ezaはRust製の`ls`代替です。色分け、アイコン、Gitステータス、ツリー表示などを備え、ディレクトリの把握がしやすくなります。

```bash
eza -la --git --icons
eza --tree --level=2
```

`ls`とはオプションの意味が一部異なるため、aliasにする場合は対話シェルだけに限定するのが安全です。

```bash
alias ls='eza --icons'
```

スクリプト内では`ls`の挙動を変えないよう、aliasを適用しない運用がおすすめです。

## 7. just — Makefileより気軽なタスクランナー

justはRust製のコマンドランナーです。`Justfile` にレシピを書いて、プロジェクトの定型作業を呼び出せます。

```make
build:
    bun run build

test:
    bun test

deploy env:
    ./scripts/deploy.sh {{env}}
```

```bash
just --list
just build
just deploy production
```

Makefileのようなファイル更新時刻の依存解決は行わず、コマンドのショートカットとして使える点が特徴です。プロジェクト固有の手順を`Justfile`にまとめておけば、READMEのコマンド例が古くなる問題も減らせます。

## 導入をスムーズに進めるコツ

- まずは`rg`か`fd`を1つだけ導入する
- aliasは対話シェルに限定し、スクリプトの挙動を変えない
- dotfilesで設定とインストール手順を管理する
- CIではツールを明示的にインストールし、バージョンを固定する
- チーム全員への強制はせず、共有したいものだけREADMEに書く

特に`ls`や`cat`のaliasは、既存のスクリプトやドキュメントとの差異を生みやすいため、適用範囲を意識して設定しましょう。

## 組み合わせの例

ファイルを探して中身を確認する流れは、次のようにまとめられます。

```bash
fd -e ts -e tsx | fzf --preview 'bat --color=always --line-range=:80 {}'
```

プロジェクトの定型作業は`Justfile`へ、コード検索は`rg`へ寄せておくと、ターミナルでの操作が自然と統一されます。

## まとめ

モダンCLIツールの価値は、派手な機能よりも日々の小さな待ち時間と迷いを減らせることにあります。今回紹介した7つは、いずれも小さく試せて、不要ならすぐに元へ戻せます。

まずは`rg`で検索を速くする、`fd`でファイルを探しやすくする。その程度から始めてみてください。
