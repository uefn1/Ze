ターミナルでの作業は、ちょっとしたツールの違いで驚くほど快適になります。本記事では、日々のファイル検索・閲覧・Git操作を軽くしてくれるCLIツールを7つ紹介します。いずれも小規模な環境から試せるものばかりです。

## なぜ今、CLIツールを見直すのか

近年はRustやGoで書かれた高速なCLIツールが増え、従来のコマンドをそのまま置き換えられる場面が多くなりました。また、fzfのようなファジー検索を組み合わせることで、複数のツールをパイプでつなぐだけで自分専用のワークフローを作れます。

GUIツールを否定するものではありません。ただ、リモートサーバーやコンテナの中でも同じ操作ができるCLIは、環境を選ばないという大きな利点があります。

## 選定のポイント

- 既存のコマンドを置き換えやすいインターフェース
- 起動が速く、大量のファイルでも待たされない
- 設定ファイルがシンプルで、dotfilesへ管理しやすい
- Linux・macOSを中心に、主要な環境で利用できる
- メンテナンスが継続されている

## 1. ripgrep — 検索の待ち時間をなくす

`ripgrep`（`rg`）は高速な検索ツールです。デフォルトで再帰検索を行い、`.gitignore`を尊重し、バイナリファイルを自動で除外してくれます。

```bash
rg "TODO"
rg -t ts "fetchUser"
rg -F "a.b.c"
rg --files | rg "\.test\.ts$"
```

`-t`で言語を指定でき、`-F`で正規表現を無効にした固定文字列検索になります。`--files`はファイル一覧の出力に便利です。設定は`~/.ripgreprc`にまとめ、`RIPGREP_CONFIG_PATH`を指定するとチームで共有しやすくなります。

## 2. fd — findを直感的に使う

`fd`は`find`の代替を目指したファイル検索ツールです。構文がシンプルで、デフォルトで隠しファイルを除外し、`.gitignore`を尊重します。

```bash
fd "config"
fd -e ts
fd -e log -x rm {}
fd -e md -X wc -l
```

`-e`で拡張子を指定し、`-x`は見つかったファイルごとにコマンドを実行、`-X`はまとめて実行します。Debian/Ubuntuではパッケージ名が`fd-find`で、コマンド名が`fdfind`になる場合があるため、必要に応じてエイリアスを設定しましょう。

```bash
alias fd='fdfind'
```

## 3. bat — catに色と行番号を足す

`bat`は`cat`の代替で、構文ハイライト・行番号・Gitの差分表示を備えています。長いファイルを読むときの負担を減らせます。

```bash
bat main.go
bat -p main.go
bat --diff main.go
bat -A .env.example
```

`-p`は行番号やヘッダーを抑えた表示、`--diff`は変更箇所の強調、`-A`は不可視文字の表示です。テーマは`bat --list-themes`で確認でき、`BAT_THEME`環境変数で指定できます。Ubuntuではコマンド名が`batcat`になる場合があります。

## 4. fzf — あらゆる一覧を絞り込む

`fzf`は汎用のファジーファインダーです。標準入力から受け取った一覧を対話的に絞り込めるため、履歴・ファイル・ブランチなど何にでも使えます。

```bash
history | fzf
fd -e ts | fzf --preview 'bat --color=always {}'
git branch | fzf | xargs git checkout
```

`--preview`を使うと、選択中のファイルをその場で確認できます。シェル統合を有効にすると、`Ctrl-R`でコマンド履歴、`Ctrl-T`でファイル選択、`Alt-C`でディレクトリ移動が使えるようになります。

## 5. zoxide — ディレクトリ移動を学習させる

`zoxide`は使用頻度と直近性をもとにディレクトリを記憶し、`z`コマンドで素早く移動できるようにします。

```bash
eval "$(zoxide init bash)"
z proj
zi
```

`z proj`のように一部の文字列だけで移動でき、`zi`はfzfと連携した対話選択です。`cd`を置き換えるのではなく、よく使うディレクトリへの近道として併用すると安全です。`zoxide init`の設定は`.bashrc`や`.zshrc`に追加します。

## 6. lazygit — Git操作を一画面にまとめる

`lazygit`はGit操作をターミナル上で行えるTUIツールです。ステージング、コミット、ブランチ切り替え、rebase、コンフリクト解消などをキーボードで操作できます。

```bash
lazygit
```

「複数のファイルから一部だけステージしたい」「コミット前に差分を確認したい」といった場面で特に便利です。GUIのGitクライアントほど重くなく、SSH先でも同じ操作ができます。設定は`~/.config/lazygit/config.yml`に置けます。

## 7. gh — GitHubの操作をターミナルへ

`gh`はGitHub公式のCLIです。プルリクエストの作成・チェックアウト、Issueの確認、Actionsの実行監視などをターミナルから行えます。

```bash
gh auth login
gh pr create --fill
gh pr checkout 123
gh run watch
gh issue list --assignee @me
```

`gh api`を使えば、CLIが対応していないAPIも呼び出せます。認証情報はOSのキーチェーンなどに保存されるため、トークンを平文で管理する必要がありません。CIでは`GH_TOKEN`を環境変数で渡すのが一般的です。

## 組み合わせるとこうなる

たとえば、次のようにファイルを探してプレビューし、そのままエディタで開けます。

```bash
fd -e ts | fzf --preview 'bat --color=always --line-range=:80 {}' | xargs -r code
```

Git操作はlazygit、検索はripgrepとfd、閲覧はbat、GitHub関連はgh、というように役割を分けると覚えやすくなります。すべてを一度に導入する必要はありません。まずは`rg`と`fd`から試し、慣れたらfzfやlazygitを足していくのがおすすめです。

## 導入時の注意点

- `curl | sh`形式のインストーラは配布元と内容を確認してから実行する
- パッケージ名とコマンド名が異なる環境（`fd-find`、`batcat`など）に注意する
- dotfilesで設定を管理し、複数マシンで同じ環境を再現する
- チームで使う場合は、ツールのバージョンを揃える
- エイリアスは既存のコマンドを上書きしすぎない範囲で設定する

## まとめ

CLIツールは、流行を追うためではなく、日々の小さな待ち時間や操作ミスを減らすために使うものです。今回紹介した7つは、どれも導入が簡単で効果を実感しやすいものばかりです。

気になるものがあれば、まずは1つだけ手元の環境へ入れて、いつもの作業がどう変わるかを試してみてください。
