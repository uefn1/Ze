新しい開発ツールは毎週のように登場しますが、実際に日常の開発へ定着するものは多くありません。本記事では、導入のハードルが低く、既存のワークフローへ自然に組み込めるツールを5つ紹介します。

## 選定のポイント

ツールを選ぶ際は、次の観点を重視しました。

- 既存の言語やエディタと組み合わせやすい
- 起動・実行が速く、待ち時間が少ない
- 設定ファイルがシンプルで、チームへ展開しやすい
- 特定のサービスへ過度に依存しない

もちろん、チームの技術スタックによって最適解は異なります。気になったものは小規模なリポジトリで試すところから始めるのがおすすめです。

## 1. Bun — JavaScript/TypeScriptの実行環境をまとめる

BunはJavaScript/TypeScript向けのオールインワンランタイムです。パッケージマネージャ、バンドラ、テストランナーが一体になっており、複数のツールを別々に設定する手間を減らせます。

```bash
bun init
bun add -d typescript
bun test
```

TypeScriptをそのまま実行できるため、小さなスクリプトやCLIツールの作成が快適です。Node.jsとの互換性も向上していますが、ネイティブモジュールや一部APIの挙動は異なる場合があります。本番導入前に対象プロジェクトで検証しましょう。

## 2. Biome — LintとFormatを1つに

BiomeはRust製のリンタ・フォーマッタです。JavaScript/TypeScriptやJSONを中心に、LintとFormatを高速に実行できます。

```bash
biome check --write .
```

ESLintとPrettierの設定が複雑になりがちなプロジェクトでは、設定を1か所にまとめられるのが魅力です。エディタ連携も用意されており、保存時の自動整形とCIでのチェックを同じ設定で運用できます。既存プロジェクトへ導入する場合は、まずルールを最小限にして差分を確認すると安全です。

## 3. uv — Pythonの依存管理を高速化する

uvはAstralが開発するPythonのパッケージ・プロジェクト管理ツールです。依存解決とインストールが高速で、ロックファイルによる再現性のある環境構築ができます。

```bash
uv init my-app
uv add requests
uv run python main.py
```

Python本体のバージョン管理もできるため、ローカルとCIで同じ環境を用意しやすくなります。仮想環境の作成や依存の追加をコマンドで統一できる点も、チーム開発に向いています。

## 4. Zed — 軽快さを重視したコードエディタ

ZedはRust製のコードエディタです。起動や入力のレスポンスが軽く、LSPやTree-sitterによる補完・構文解析を備えています。共同編集機能もあり、ペアプログラミングやレビューの場面で活用できます。

VS Codeのような拡張機能の豊富さはまだ及ばない部分があるため、利用する言語の対応状況は事前に確認してください。一方で、エディタ自体の動作の軽さを重視する人には有力な選択肢です。

## 5. Ollama — ローカルでLLMを動かす

Ollamaは、ローカル環境で大規模言語モデルを実行するためのツールです。CLIからモデルを取得してすぐに試せる手軽さが特徴です。

```bash
ollama run llama3
```

ローカルで完結するため、コードや文章を外部サービスへ送りたくない場面に向いています。OpenAI互換のAPIを備えており、既存のツールから接続しやすいのも利点です。ただし、モデルのサイズによっては相応のメモリとGPU性能が必要になります。

## 組み合わせの例

たとえば、TypeScriptのプロジェクトではBunとBiomeを、Pythonの処理ではuvを使い、エディタはZed、ローカルLLMはOllamaという構成が考えられます。すべてを一度に導入する必要はありません。まずは1つだけ導入し、効果を確認してから広げていくと定着しやすくなります。

## 導入時の注意点

- ロックファイルは必ずリポジトリへコミットする
- ローカルとCIで同じツールバージョンを使う
- ライセンスやセキュリティポリシーを確認する
- チーム内で設定ファイルの管理ルールを決める

## まとめ

開発ツールは、流行を追うこと自体が目的ではありません。日々の待ち時間や設定の手間を減らし、本来の実装に集中できる環境を作ることが重要です。

今回紹介した5つは、いずれも小さく試せて効果を実感しやすいものばかりです。気になるツールがあれば、まずは手元のプロジェクトで1つだけ導入してみてください。

エディタやIDEの進化は目覚ましい一方で、日常の開発には依然としてターミナルでの作業が多く残っています。ファイルを探す、ログを検索する、差分を確認する。一つひとつは数秒の作業でも、積み重なると無視できない時間になります。

本記事では、既存のコマンドを置き換えるだけで体感速度が変わるCLIツールを7つ紹介します。いずれも設定なしでも使い始められ、慣れてきたら少しずつカスタマイズできるものを選びました。

## なぜ今、CLIツールを見直すのか

最近のCLIツールは、RustやGoで書かれたものが増えています。起動が速く、並列処理に強く、シングルバイナリで配布されるため導入も簡単です。また、`--help`や補完が丁寧に設計されており、昔ながらのコマンドよりも学習コストが低い傾向があります。

ポイントは、すべてを一気に置き換えないことです。まずは毎日使うコマンドを1つだけ変え、手に馴染んだら次へ進む。この順番が定着の近道です。

## 1. ripgrep — 検索の待ち時間をなくす

`ripgrep`（`rg`）は高速なファイル検索ツールです。デフォルトで`.gitignore`を尊重するため、`node_modules`やビルド成果物を無視してくれます。

```bash
rg "TODO" src/
rg -t ts "useEffect"
```

`grep -r`で数秒待っていた検索が、ほぼ即座に返ってくる感覚は一度味わうと戻れません。置き換えとして最も効果を実感しやすいツールです。

## 2. fd — 覚えやすいfind

`fd`は`find`の代替です。大文字小文字を区別しない検索がデフォルトで、拡張子やディレクトリを絞り込む構文も直感的です。

```bash
fd -e ts
fd -t d src
```

`find . -name "*.ts"`のような長いオプションを覚える必要がなく、日常のファイル探索が軽くなります。

## 3. bat — 読むためのcat

`bat`はシンタックスハイライトと行番号を備えた`cat`です。長いファイルは自動でページャーに渡されるため、ログや設定ファイルの確認が楽になります。

```bash
bat README.md
bat -p main.go
```

`-p`を付けると行番号やファイル名のヘッダーを省略でき、既存のスクリプトに組み込む際にも扱いやすくなります。

## 4. eza — 情報を足したls

`eza`は`ls`の現代版です。色分け、アイコン、Gitの状態表示をまとめて確認できます。

```bash
eza -la --git --icons
```

どのファイルが変更済みか、追跡外かを一覧で把握できるため、リポジトリの状態確認が一段と速くなります。エイリアスを`ls`に割り当てるだけでも効果があります。

## 5. zoxide — 移動を減らすcd

`zoxide`はディレクトリ移動を学習するツールです。よく行く場所ほど短いキーワードで移動できます。

```bash
z proj
zi
```

`z`は履歴に基づいて候補へ飛び、`zi`はあいまい検索で選択できます。深いパスを何度も`cd`で辿る作業が減ります。シェルへの初期化が必要なので、利用中のシェルに合わせて設定します。

```bash
# bash の例
eval "$(zoxide init bash)"
```

## 6. fzf — あいまい検索で候補を絞る

`fzf`は対話的なあいまい検索ツールです。単体でも使えますが、他のコマンドと組み合わせると真価を発揮します。

```bash
git branch | fzf
git log --oneline | fzf
```

ブランチ名やコミットを目で探す代わりに、数文字入力して絞り込めます。履歴検索（`Ctrl-R`）やファイル選択と連携させる設定も定番です。

## 7. starship — プロンプトを揃える

`starship`はクロスシェル対応のプロンプトです。Gitブランチ、言語のバージョン、実行時間などを必要な分だけ表示できます。

```bash
# ~/.config/starship.toml
# 表示を絞りたいときは format を編集する
```

情報を盛りすぎると逆に視認性が落ちるため、最初はデフォルトのまま使い、必要な項目だけ足していくのがおすすめです。複数のマシンやシェルで同じ見た目を保てるのも利点です。

## 組み合わせ方

おすすめは、次の順番で導入することです。

1. `ripgrep`と`fd`で検索を速くする
2. `bat`と`eza`でファイル確認を快適にする
3. `zoxide`と`fzf`で移動と選択を短縮する
4. 最後に`starship`で見た目を整える

すべてを入れる必要はありません。自分の作業で「待つ」「探す」「打つ」が多いと感じた場面から選ぶと、効果が実感しやすくなります。

## 導入時の注意点

- 既存コマンドを上書きするエイリアスは、まず別名で試す
- チームで共有するスクリプトでは新しいツールに依存しない
- 補完やシェル初期化の設定は、利用するシェルごとに確認する
- インストール方法はOSやパッケージマネージャによって異なる

特にCIや共有スクリプトでは、環境によってツールが入っていない可能性があります。ローカルの快適さを追求する場面と、再現性を重視する場面を分けて考えると安全です。

## まとめ

CLIツールの見直しは、大きな投資をせずに開発体験を改善できる手段です。今回紹介した7つは、どれも小さく試せて効果を実感しやすいものばかりです。

まずは`ripgrep`を1つ入れて、検索の待ち時間が消える感覚を確かめてみてください。そこから自分の作業に合わせて、必要なツールだけを少しずつ足していくのが、結局は一番長続きします。
