## はじめに

Pythonの開発環境まわりは、長らく「ツールが多すぎる」と言われてきました。パッケージ管理に `pip`、仮想環境に `venv`、Python本体のバージョン管理に `pyenv`、依存関係のロックに `pip-tools` や `Poetry`……。目的ごとに別々のツールを使い分ける必要があり、学習コストも運用コストも小さくありません。

そんな状況を一変させたのが、Astral社が開発する **uv** です。Rust製の高速なパッケージマネージャで、pip・venv・pyenv・pip-toolsなどの役割をひとつに統合します。この記事では、uvの基本から実践的な使い方までを一気に紹介します。

## uvとは

uvは「Python向けの超高速パッケージ・プロジェクトマネージャ」です。主な特徴は次のとおりです。

- **とにかく速い**: Rust実装により、pipと比較して桁違いの速度でインストール・解決が完了する
- **オールインワン**: パッケージ管理、仮想環境、Pythonバージョン管理、ロックファイル、ツール実行を1つのCLIで完結
- **標準規格に準拠**: `pyproject.toml` やロックファイルなど、モダンなPythonの標準的な仕組みを採用
- **クロスプラットフォーム**: macOS / Linux / Windows で同じように動作する

「pipの代替」というよりは、「Pythonプロジェクトの開発体験をまるごと置き換える」ツールだと考えると分かりやすいでしょう。

## インストール

macOS / Linux では公式のインストーラスクリプトを使うのが手軽です。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Windows（PowerShell）の場合は次のコマンドになります。

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Homebrewを使っている場合は `brew install uv`、pip経由なら `pip install uv` でも導入できます。インストール後はバージョンを確認しておきましょう。

```bash
uv --version
```

## プロジェクトを作成する

uvでは、プロジェクト単位で環境を管理するのが基本です。新規プロジェクトは `uv init` で作成します。

```bash
uv init myapp
cd myapp
```

`uv init` を実行すると、`pyproject.toml` や `.python-version` などを含むプロジェクトのひな型が生成されます。`pyproject.toml` は依存関係やプロジェクト設定をまとめる中心的なファイルです。

既存のディレクトリで後からuvを導入したい場合は、そのディレクトリ内で `uv init` を実行すればOKです。

## 依存関係を追加する

パッケージの追加は `uv add` を使います。

```bash
uv add requests
```

これを実行すると、次のことが自動で行われます。

1. `pyproject.toml` の依存関係に追記
2. 依存関係を解決して `uv.lock` を生成・更新
3. 仮想環境 `.venv` を作成し、パッケージをインストール

開発用の依存関係は `--dev` を付けます。

```bash
uv add --dev pytest ruff
```

`uv.lock` は依存関係を厳密に固定するロックファイルです。これをリポジトリにコミットしておけば、チーム全員が同じバージョンの依存関係を再現できます。

## 依存関係を同期する

`uv.lock` の内容に沿って環境を構築するには `uv sync` を使います。クローン直後やCIでのセットアップに便利です。

```bash
uv sync
```

`uv sync` はロックファイルと仮想環境の状態を一致させるように動くため、「ロックファイルにあるのに環境にない」といったズレを解消できます。開発用の依存関係を除外したい場合は `--no-dev` を指定します。

## 仮想環境を意識せずにコマンドを実行する

uvの便利な点は、仮想環境のactivateを意識しなくてよいことです。`uv run` を使えば、プロジェクトの環境でコマンドを実行できます。

```bash
uv run python main.py
uv run pytest
```

仮想環境がまだ存在しない場合は、`uv run` が自動的に作成してくれます。「仮想環境を作り忘れてグローバルにインストールしてしまった」という事故も減らせます。

## Python本体のバージョンを管理する

uvはPythonインタプリタのバージョン管理も担います。特定のバージョンをインストールするには次のようにします。

```bash
uv python install 3.12
```

プロジェクトで使うバージョンを固定する場合は `uv python pin` を使います。

```bash
uv python pin 3.12
```

これにより `.python-version` が更新され、プロジェクトがどのPythonバージョンを前提としているかが明示されます。pyenvを別途インストールする必要がないのは大きなメリットです。

## ツールを一時的に実行する

ちょっとしたCLIツールを試したいだけのときに、グローバル環境を汚さずに実行できるのが `uvx`（`uv tool run` のエイリアス）です。

```bash
uvx ruff check .
uvx black --check .
```

`uvx` はツールを一時的な環境にインストールして実行するため、プロジェクトの依存関係に影響を与えません。常に使うツールは `uv tool install` でインストールしておくこともできます。

```bash
uv tool install ruff
```

## 既存のpipプロジェクトから移行する

`requirements.txt` を使っている既存プロジェクトでも、uvはpip互換のインターフェースを提供しています。

```bash
uv pip install -r requirements.txt
```

ただし、uvの恩恵を最大限に受けるなら `pyproject.toml` + `uv add` のスタイルへ移行するのがおすすめです。`uv add` で依存関係を追加していけば、ロックファイル管理まで含めてuvに一任できます。

## まとめ

uvは、これまで複数のツールに分散していたPythonの開発環境管理を、ひとつの高速なCLIに統合します。この記事のポイントを振り返ります。

- `uv init` でプロジェクトを作成する
- `uv add` / `uv add --dev` で依存関係を追加し、`uv.lock` で固定する
- `uv sync` でロックファイルに沿って環境を再現する
- `uv run` で仮想環境を意識せずコマンドを実行する
- `uv python install` / `uv python pin` でPythonバージョンを管理する
- `uvx` でツールを一時実行する

まずは小さなプロジェクトで `uv init` から試してみてください。一度この速度と手軽さに慣れると、pipとvenvの往復には戻れなくなるはずです。
