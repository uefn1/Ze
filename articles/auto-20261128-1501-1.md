2026年11月19日、PHPのメジャーアップデートとなる **PHP 8.6** がリリースされました。パフォーマンス改善だけでなく、関数型プログラミング寄りの記法や、これまで扱いづらかった時間・I/Oまわりに踏み込んだ変更が含まれています。本記事では、実務で影響の大きい新機能をコード例とともに整理します。

## PHP 8.6の全体像

PHP 8.6の主なトピックは次の4つです。

- 関数の一部引数を固定できる **部分関数適用（Partial Function Application）**
- ナノ秒単位の経過時間を型安全に扱う **Durationクラス**
- 多数のストリームを効率よく監視する **Polling API**
- `clamp()` や `SortDirection` 列挙型など、日々のコードを短くする小粒な改善

加えて、ストリームの例外処理や暗号化拡張の強化、セッションのデフォルトセキュリティ向上も含まれます。一方で後方互換性のない変更もあるため、アップグレード前に移行ガイドの確認が必須です。

## 部分関数適用（Partial Function Application）

PHP 8.6で最も話題になっているのが部分関数適用です。関数の引数の一部を `?` プレースホルダーにして、残りの引数を後から受け取るクロージャを生成できます。

```php
function add(int $a, int $b): int
{
    return $a + $b;
}

$addTen = add(?, 10);
echo $addTen(5); // 15
```

これまでは `fn (int $a) => add($a, 10)` のように無名関数で包む必要がありましたが、部分関数適用を使えば意図がそのままコードになります。`array_map` など高階関数に渡すコールバックの記述がぐっと簡潔になるのが嬉しいポイントです。

```php
$prices = [100, 250, 380];
$withTax = array_map(round(?, 2), array_map(fn ($p) => $p * 1.1, $prices));
```

引数の順序に依存するため、プレースホルダーの位置が直感的かどうかはチーム内でルールを決めておくとよいでしょう。

## Durationクラスでナノ秒の経過時間を扱う

ベンチマークやレイテンシ計測では、これまで `microtime(true)` の差分を自前で計算しがちでした。PHP 8.6では **Durationクラス** が追加され、ナノ秒単位の時間を型として扱えます。

```php
$start = Duration::now();

// ... 何らかの処理 ...

$elapsed = Duration::now()->minus($start);
printf("処理時間: %.3f ms\n", $elapsed->toMilliseconds());
```

単位変換（秒・ミリ秒・マイクロ秒・ナノ秒）がメソッドとして提供されるため、マジックナンバーによる掛け算が減り、計測コードのレビューもしやすくなります。ログ出力やAPM連携のフォーマットも統一しやすくなるはずです。

## Polling APIで多数ストリームを効率的に監視

ソケットやパイプなど複数のストリームを同時に待ち受ける場合、従来は `stream_select()` を直接使い、ファイルディスクリプタの配列を管理する必要がありました。PHP 8.6の **Polling API** は、この監視処理をより高レベルに扱えるようにします。

```php
$polling = new Polling();
$polling->watch($socketA, Polling::READ);
$polling->watch($socketB, Polling::WRITE);

foreach ($polling->wait(timeoutMs: 1000) as $event) {
    if ($event->isReadable()) {
        // 読み取り可能になったストリームを処理
    }
}
```

大量の接続を扱うWebSocketサーバーや、CLIでの並行I/O処理などで効果を発揮します。イベントループを自前で組み立てる場面では、可読性と保守性の両面で恩恵が大きい変更です。

## その他の便利な新機能

### clamp() で値を範囲内に収める

```php
$percent = clamp($raw, 0, 100);
```

`max($min, min($max, $value))` のような入れ子を書かずに済みます。UIの進捗率や設定値の正規化で重宝します。

### SortDirection 列挙型

ソート順を文字列ではなく列挙型で型安全に表現できます。APIのクエリパラメータと内部ロジックの間で `"asc"` / `"desc"` の文字列比較が散らばる問題を減らせます。

### 読み取り専用プロパティのデフォルト値

`readonly` プロパティにデフォルト値を設定できるようになり、コンストラクタを書かずに初期値を表現できるケースが増えました。

```php
class Config
{
    public readonly string $env = 'production';
}
```

## 非推奨・後方互換性の注意点

PHP 8.6は便利な機能が多い一方、次のような破壊的変更を含みます。

- `finally` ブロック内の `return` が非推奨に
- 一部の古い関数が非推奨化
- ストリームや暗号化拡張の挙動変更

特に `finally` 内の `return` は、例外の握りつぶしにつながる危険なパターンです。静的解析ツール（PHPStan / Psalm）をCIに組み込み、非推奨警告を早期に検出する体制を整えておくと移行がスムーズになります。

## まとめ

PHP 8.6は「言語機能の拡張」と「現場の計測・I/O基盤の底上げ」を同時に狙ったリリースです。特に部分関数適用とDurationクラスは、日々のコードの書き方に直接影響します。

導入時は次の順序をおすすめします。

1. まず開発環境でPHP 8.6を試し、非推奨警告を洗い出す
2. 静的解析とテストをCIで回し、破壊的変更の影響範囲を把握する
3. 新機能は新規コードから段階的に採用する

既存プロジェクトでは、いきなり全面移行するよりも、警告をゼロに近づけてからバージョンを上げる方が安全です。PHP 8.6の新機能を味方につけて、計測やI/Oまわりのコードをすっきりさせていきましょう。
