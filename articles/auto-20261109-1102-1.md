## はじめに

Pythonの開発環境構築は、長らく「pip」「venv」「pyenv」「pip-tools」など複数のツールを組み合わせる必要がありました。プロジェクトごとにPythonのバージョンを切り替え、仮想環境を作り、依存関係をインストールし、ロックファイルを更新する——この手順は初心者にとって分かりにくく、CIでも再現性の悩みが尽きません。

そこで注目されているのが **uv** です。uvはRuffで知られるAstral社が開発している、Rust製の高速なPythonパッケージマネージャー兼プロジェクト管理ツールです。pipの代替として使えるだけでなく、仮想環境・Pythonバージョン管理・依存解決・ロックファイル・スクリプト実行までを一貫して扱えます。

この記事では、uvの基本から実践的な使い方、既存プロジェクトへの導入までをまとめます。

## uvとは

uvは次のような機能を1つのCLIにまとめたツールです。

- pip互換のパッケージインストール（`uv pip install`）
- 仮想環境の作成（`uv venv`）
- Python本体のバージョン管理（`uv python install`）
- `pyproject.toml` ベースのプロジェクト管理（`uv init` / `uv add` / `uv sync`）
- 高速な依存解決と `uv.lock` による再現性の担保
- 単発スクリプトの依存を一時的に解決して実行（`uv run --with`）
- CLIツールの隔離実行・インストール（`uvx` / `uv tool install`）

最大の特徴は速度です。Rustで書かれ、依存解決とキャッシュの設計が最適化されているため、特にCIでのインストール時間が大きく短縮されます。また、pipやvenvのワークフローと共存できるため、既存プロジェクトに段階的に導入できるのも利点です。

## インストール

macOS・Linuxでは公式インストーラーが手軽です。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Homebrewやpipxを使う場合は次のとおりです。

```bash
brew install uv
# または
pipx install uv
```

WindowsではPowerShell用のインストーラーが用意されています。

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

インストール後はバージョンを確認しておきましょう。

```bash
uv --version
```

## プロジェクトを新規作成する

uvでは `uv init` でプロジェクトの雛形を作成します。

```bash
uv init my-app
cd my-app
```

生成される主なファイルは次のとおりです。

- `pyproject.toml` — プロジェクトのメタデータと依存関係
- `.python-version` — 使用するPythonバージョン
- `main.py` — エントリーポイントのサンプル（アプリの場合）
- `README.md`

`pyproject.toml` はおおよそ次のような内容になります。

```toml
[project]
name = "my-app"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.12"
dependencies = []
```

ライブラリを作る場合は `--lib`、パッケージとして配布する構成にする場合は `--package` を指定します。

```bash
uv init --lib my-lib
uv init --package my-package
```

## 依存パッケージを追加する

依存の追加は `uv add` です。pip installのように仮想環境を手動で有効化する必要はありません。

```bash
uv add requests
uv add "fastapi>=0.115"
```

開発用の依存は `--dev` を付けます。

```bash
uv add --dev pytest ruff
```

グループを分けたい場合は `--group` を使います。

```bash
uv add --group docs mkdocs
```

削除は `uv remove` です。

```bash
uv remove requests
```

`uv add` を実行すると、`pyproject.toml` の更新、仮想環境の作成、パッケージのインストール、`uv.lock` の生成までが自動で行われます。この一連の流れがコマンド1つで完結するのがuvの大きな利点です。

## ロックファイルと再現性

uvは `uv.lock` を生成し、依存関係を完全に固定します。チーム開発やCIではこのファイルをリポジトリにコミットするのが基本です。

環境をロックファイルどおりに揃えるには `uv sync` を実行します。

```bash
uv sync
```

CIなどでロックファイルの変更を許さずに検証したい場合は `--frozen` が便利です。

```bash
uv sync --frozen
```

ロックファイルだけを更新したい場合は `uv lock` を使います。

```bash
uv lock
uv lock --upgrade
```

`uv.lock` はクロスプラットフォーム対応の形式で、OSやPythonバージョンの違いを吸収してくれます。これにより「自分の環境では動くのにCIでは失敗する」といった依存関係由来のトラブルを減らせます。

## 仮想環境を扱う

uvはプロジェクト直下に `.venv` を作成して管理します。明示的に作りたい場合は `uv venv` を使います。

```bash
uv venv
source .venv/bin/activate
```

Pythonのバージョンを指定して仮想環境を作ることもできます。

```bash
uv venv --python 3.12
```

ただし、uvのプロジェクト管理モードでは仮想環境の有効化は必須ではありません。`uv run` が適切な環境を自動で使ってくれます。

```bash
uv run python main.py
uv run pytest
```

## Python本体のバージョンを管理する

uvはPythonインタープリターのインストールも行えます。pyenvを別途入れる必要がありません。

```bash
uv python install 3.12
uv python list
```

プロジェクトで使うバージョンを固定する場合は次のようにします。

```bash
uv python pin 3.12
```

これで `.python-version` が更新され、以降のコマンドはそのバージョンを使うようになります。複数バージョンでのテストも `uv run --python 3.11` のように切り替えられます。

## スクリプトを手軽に実行する

ちょっとしたスクリプトに依存を追加したいとき、プロジェクトを作るほどではないケースがあります。そんなときは `uv run --with` が便利です。

```bash
uv run --with requests python fetch.py
```

スクリプトファイルの先頭に依存を埋め込むインラインスクリプトメタデータにも対応しています。

```python
# /// script
# requires-python = ">=3.12"
# dependencies = ["requests"]
# ///
import requests

print(requests.get("https://example.com").status_code)
```

このファイルは次のコマンドだけで実行できます。

```bash
uv run fetch.py
```

仮想環境を事前に作る必要がなく、依存はuvが一時的に解決してくれます。ちょっとした検証や自動化スクリプトに向いています。

## CLIツールを隔離して実行する

`uvx`（`uv tool run` のエイリアス）を使うと、グローバル環境を汚さずにCLIツールを実行できます。

```bash
uvx ruff check .
uvx black --check .
```

よく使うツールは `uv tool install` でインストールできます。

```bash
uv tool install ruff
uv tool list
```

pipxに近い使い勝手ですが、依存解決が高速で、ツールごとに独立した環境が作られます。

## 既存プロジェクトへ導入する

既存の `requirements.txt` を使っているプロジェクトでも、uvは段階的に導入できます。まずはpip互換コマンドから試すのがおすすめです。

```bash
uv venv
uv pip install -r requirements.txt
```

`uv pip compile` を使えば、`requirements.in` から固定済みの `requirements.txt` を生成できます。

```bash
uv pip compile requirements.in -o requirements.txt
```

本格的に移行する場合は、`pyproject.toml` に依存を移し、`uv add` で管理する形に切り替えていくとよいでしょう。すべてを一度に置き換える必要はありません。

## 導入時の注意点

uvは非常に便利ですが、いくつか押さえておきたい点があります。

- **ロックファイルはコミットする**: `uv.lock` を共有しないと再現性が失われます。
- **CIのキャッシュを設定する**: uvはキャッシュディレクトリを利用するため、CIでキャッシュを有効にするとさらに高速になります。
- **チーム内でバージョンを揃える**: uv自体のバージョン差異で挙動が変わる可能性があるため、CIとローカルで同じバージョンを使うのが安全です。
- **既存ツールとの役割を整理する**: pip・poetry・pyenvなどと併用する場合は、どのツールが何を管理するのかを決めておくと混乱を避けられます。

## まとめ

uvは「pipの高速版」にとどまらず、Python開発環境をひとつにまとめる総合ツールです。

- `uv init` / `uv add` / `uv sync` でプロジェクト管理が完結する
- `uv python install` でPython本体も管理できる
- `uv run` で仮想環境を意識せずにコマンドを実行できる
- `uvx` でCLIツールを隔離実行できる
- `uv.lock` によりチーム開発・CIの再現性が向上する

まずは小さなプロジェクトか、`uvx` でのツール実行から試してみてください。一度体験すると、Pythonの環境構築に対する印象が大きく変わるはずです。
