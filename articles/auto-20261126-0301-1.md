## はじめに

ここ数年で、開発ツールの世界は「多機能だけど重い」から「速くてシンプル」へと明確に舵を切りました。Rust や Go で書かれた CLI が次々と登場し、これまで Node.js や Python のエコシステムで当たり前だった処理が数倍〜数十倍速くなっています。

この記事では、日常の開発体験（DX）を軽くしてくれるツールを7つ紹介します。「全部入れろ」という話ではなく、**置き換えコストが低く、効果が体感しやすいもの**を中心に選びました。

## 1. Bun — JS ランタイム兼パッケージマネージャ

Node.js の代替として登場した Bun は、ランタイム・バンドラ・テストランナー・パッケージマネージャを1つにまとめています。特に `install` の速さは体感で分かるレベルです。

```bash
# 既存プロジェクトの lockfile を活かしつつ移行
bun install

# テストも内蔵
bun test
```

ポイントは、**いきなり本番を置き換えない**こと。まずはローカルの依存インストールやスクリプト実行から試し、Node.js との互換性が求められる場面では使い分けるのが現実的です。

## 2. Biome — Linter と Formatter の統合

ESLint + Prettier の構成は強力ですが、設定ファイルと実行時間が増えがちです。Biome は Rust 製で、lint と format を1つのツール・1つの設定で扱えます。

```json
{
  "formatter": { "enabled": true, "indentStyle": "space" },
  "linter": { "enabled": true, "rules": { "recommended": true } }
}
```

```bash
biome check --write .
```

CI の実行時間が短くなるのはもちろん、エディタ保存時のレスポンスが軽くなるのが嬉しいところです。ルールセットが ESLint と完全一致ではないため、移行時は `biome check` の差分を一度確認しましょう。

## 3. uv — Python のパッケージ・仮想環境管理

Python の依存管理は pip / venv / pyenv / poetry などが混在しがちでした。uv はこれらを高速にまとめる Rust 製ツールです。

```bash
uv init myapp
uv add requests
uv run main.py
```

`uv run` が仮想環境の activate を不要にしてくれるのが快適です。ロックファイルによる再現性も確保できるので、チーム開発との相性も良好です。

## 4. Ruff — Python の爆速 Linter / Formatter

Ruff も Rust 製で、Flake8・isort・pyupgrade などの役割を1つにまとめます。uv と同じ Astral 製で、組み合わせて使うと Python 開発の立ち上がりがかなり軽くなります。

```toml
# pyproject.toml
[tool.ruff]
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]
```

```bash
ruff check --fix .
ruff format .
```

## 5. mise — ランタイムと環境変数の統合管理

Node・Python・Go・Ruby などのバージョンを、プロジェクト単位でまとめて管理できます。asdf の代替として注目されているツールです。

```bash
# .mise.toml
[tools]
node = "22"
python = "3.12"
```

```bash
mise install
mise exec -- node -v
```

ディレクトリに入るだけでバージョンが切り替わるため、「このリポジトリだけ Node のバージョンが違う」問題を解消できます。

## 6. just — Makefile の代わりになるコマンドランナー

`make` は強力ですが、タブや `.PHONY` など独特の作法があります。just はレシピをシンプルに書けるコマンドランナーです。

```just
# justfile
test:
    bun test

lint:
    biome check .
    ruff check .
```

```bash
just test
just lint
```

プロジェクトの「よく使うコマンド」を1か所に集約できるので、新規参加者のオンボーディングにも効きます。

## 7. Zed — Rust 製の軽量エディタ

VS Code からの乗り換え先として話題になることが多いエディタです。起動と入力のレスポンスが軽く、共同編集機能も備えています。

ただし拡張機能のエコシステムは VS Code ほど成熟していないため、**言語やワークフローによってはまだ不足がある**点は正直に押さえておくべきです。まずはサブのエディタとして試すのがおすすめです。

## 導入時の現実的な進め方

勢いで全部置き換えると、CI やチームの合意形成で詰みます。次の順番が安全です。

1. **ローカル限定のツールから**（mise、just、Ruff など）
2. **CI で効果を測る**（Biome、uv の実行時間を比較）
3. **チームに共有してから**本番設定を変更する

特に lockfile やフォーマッタの変更は、差分が大量に出てレビューが破綻しやすいです。移行は「機能追加と混ぜない」独立した PR に分けましょう。

## まとめ

- 高速ツールの共通点は「**1つのことを軽くやる**」こと
- まずはローカルで試し、CI で効果を測ってから広げる
- 既存エコシステムとの互換性は必ず確認する

「なんとなく重い」と感じている開発環境は、ここ数年で大きく改善できる余地があります。全部ではなく、1つだけでも置き換えてみると効果が実感できるはずです。
