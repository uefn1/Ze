AIコーディングエージェントが当たり前になり、コードを書く速度よりも「書かれたコードを読む・探す・確認する」速度がボトルネックになる場面が増えました。本記事では、そうした日々の確認作業を静かに速くしてくれるCLIツールを7つ紹介します。

## なぜ今、CLIツールを見直すのか

AIが生成した差分は、人間が書いたものより量が多く、確認の対象も広がりがちです。検索、ファイル移動、差分確認といった地味な操作の待ち時間を減らすことは、レビューや設計に使える時間を増やすことにつながります。

紹介するツールはいずれも小さく試せて、既存のワークフローを大きく変えずに導入できます。

## 1. ripgrep — 検索の待ち時間をなくす

`ripgrep`（`rg`）は、高速なコード検索ツールです。`.gitignore`を尊重して検索してくれるため、ビルド成果物や依存ディレクトリを除外する設定を書かずに済みます。

```bash
rg "useEffect" src/
rg -l "TODO" --type ts
rg "fetch\(" -C 2
```

`-l`でファイル名だけを表示したり、`-C`で前後の行を表示したりと、目的に応じた絞り込みが短いコマンドで書けます。まずは`grep`の代わりに`rg`を打つところから始めると定着しやすいです。

## 2. fd — 直感的なファイル検索

`fd`は`find`の代替として使えるファイル検索ツールです。デフォルトで隠しファイルや`.gitignore`対象を除外し、正規表現ではなく直感的なパターンで指定できます。

```bash
fd config
fd -e tsx -x wc -l
fd --type d node_modules -H
```

`-e`で拡張子を指定し、`-x`で見つかったファイルに対してコマンドを実行できます。「特定の拡張子のファイルだけを対象に何かする」という処理が簡潔に書けるのが利点です。

## 3. fzf — あいまい検索で候補を絞る

`fzf`は、あいまい検索のインターフェースを提供するツールです。単体でも使えますが、パイプと組み合わせることで真価を発揮します。

```bash
git ls-files | fzf
fd -e md | fzf --preview 'bat --color=always {}'
```

ファイル一覧を絞り込んだり、プレビュー付きで選択したりできます。シェルの履歴検索（`Ctrl-R`）やディレクトリ移動と連携させる設定も一般的で、一度慣れると手放せなくなります。

## 4. bat — コードを読みやすく表示する

`bat`は`cat`の代替として使える表示ツールです。シンタックスハイライト、行番号、Gitの差分表示を備えています。

```bash
bat src/main.ts
bat --diff src/main.ts
```

AIが生成したコードをざっと確認するとき、行番号と色分けがあるだけで読み違いが減ります。`--diff`を使うと、変更箇所を強調して表示できます。

## 5. zoxide — ディレクトリ移動を短縮する

`zoxide`は、訪問履歴を学習してディレクトリ移動を短くするツールです。`cd`の代わりに`z`を使い、ディレクトリ名の一部を入力するだけで移動できます。

```bash
z proj
z articles
```

頻繁に行き来するディレクトリほど短い入力で移動できるようになります。深い階層を持つモノレポでは特に効果を実感しやすいです。

## 6. delta — Gitの差分を読みやすくする

`delta`は、Gitの差分表示を見やすくするページャです。行番号、シンタックスハイライト、変更の強調が追加され、レビューの負担を減らせます。

```bash
git config --global core.pager "delta"
git diff
```

設定はGitの`core.pager`に指定するだけです。サイドバイサイド表示や行番号の表示も設定で切り替えられます。差分を読む時間が長い人ほど効果が出ます。

## 7. just — よく使うコマンドを整理する

`just`は、プロジェクト固有のコマンドを`Justfile`にまとめて実行できるタスクランナーです。

```makefile
# Justfile
test:
    npm test

lint:
    npm run lint

check: lint test
```

```bash
just check
```

`Makefile`に近い書き方で、タブではなくスペースで書ける点や、引数を扱いやすい点が特徴です。「このリポジトリで何を打てばよいか」をREADMEと`Justfile`の両方に書かずに済み、チームへの共有も簡単になります。

## 小さく導入するコツ

- いきなりすべて置き換えず、1つずつ試す
- まずは手元の環境だけで使い、慣れてからチームへ共有する
- シェルの設定ファイルはGitで管理し、変更履歴を残す
- CIで使う場合は、ローカルと同じバージョンを固定する

ツールの導入は、流行を追うこと自体が目的ではありません。日々の待ち時間を減らし、本来の設計やレビューに集中できる状態を作ることが重要です。

## まとめ

AIがコードを書く時代だからこそ、人間側の「読む・探す・確認する」速度が開発体験を左右します。今回紹介した7つは、いずれも小さく試せて効果を実感しやすいものばかりです。

気になったツールがあれば、まずは1つだけ手元のプロジェクトへ導入してみてください。
