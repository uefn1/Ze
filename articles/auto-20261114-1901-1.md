Pythonの依存管理といえば `pip` と `venv`、あるいは `Poetry` が定番でした。そこに登場したのが、Rust製のパッケージマネージャ **uv** です。「とにかく速い」と話題になっていますが、実際のところ何が嬉しいのか、既存ツールとどう使い分けるのかを整理します。

## uvとは

uv は Astral 社が開発する Python 用のパッケージ・プロジェクトマネージャです。主な特徴は次の通りです。

- Rust で実装されており、依存解決とインストールが非常に高速
- `pip` 互換のインターフェースを持ち、既存の `requirements.txt` をそのまま扱える
- 仮想環境の作成、Python 本体のバージョン管理、ロックファイル生成まで一通りこなす
- `pyproject.toml` ベースのモダンなプロジェクト管理に対応

つまり、これまで `pip` + `venv` + `pyenv` + `pip-tools` など複数ツールで分担していた役割を、uv ひとつに寄せられます。

## なぜ速いのか

uv の速度は、単なる宣伝ではなくアーキテクチャに由来します。

1. **Rust実装**によるオーバーヘッドの小ささ
2. **グローバルキャッシュ**を活用し、同じパッケージを再ダウンロードしない
3. **並列処理**を前提とした依存解決アルゴリズム
4. **ハードリンク**による仮想環境への展開で、ディスクとコピー時間を節約

特にCIのように「毎回クリーンな環境でインストールする」場面では、この差がビルド時間に直結します。

## インストール

公式のインストーラを使うのが手軽です。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

macOS なら Homebrew でも入ります。

```bash
brew install uv
```

インストール後はバージョンを確認しておきましょう。

```bash
uv --version
```

## 基本コマンド早見表

`pip` や `venv` に慣れている人向けに対応関係をまとめます。

| やりたいこと | 従来 | uv |
| --- | --- | --- |
| 仮想環境を作る | `python -m venv .venv` | `uv venv` |
| パッケージを入れる | `pip install requests` | `uv add requests` |
| requirements から入れる | `pip install -r requirements.txt` | `uv pip install -r requirements.txt` |
| 依存を固定する | `pip freeze > requirements.txt` | `uv lock` |
| スクリプトを実行 | `python main.py` | `uv run main.py` |

`uv pip ...` は既存プロジェクトへの移行用、`uv add` / `uv run` は新規プロジェクト向け、と覚えると混乱しにくいです。

## プロジェクトをゼロから作る

まずは雛形を生成します。

```bash
uv init myapp
cd myapp
```

`pyproject.toml` とサンプルコードが生成されます。依存を追加してみましょう。

```bash
uv add httpx
```

これだけで `pyproject.toml` の更新、`uv.lock` の生成、仮想環境へのインストールまで完了します。実行は `uv run` 経由です。

```bash
uv run python main.py
```

`uv run` は仮想環境を自動で同期してから実行するため、「アクティベートし忘れ」による事故が減ります。

## Python本体のバージョンも管理できる

uv はインタプリタの取得もできます。複数バージョンを試したいときに便利です。

```bash
uv python install 3.12
uv python list
```

プロジェクトごとにバージョンを固定したい場合は `.python-version` を置くか、`pyproject.toml` の `requires-python` を設定します。

## CIでの活用

GitHub Actions では公式アクションが用意されています。キャッシュを効かせると効果が大きいです。

```yaml
- uses: astral-sh/setup-uv@v5
  with:
    enable-cache: true

- run: uv sync --frozen
- run: uv run pytest
```

`--frozen` を付けるとロックファイルを変更せずに同期するため、CIでは再現性を保てます。

## 既存プロジェクトからの移行ステップ

いきなり全部置き換えず、段階的に進めるのがおすすめです。

1. まずは `uv pip install -r requirements.txt` でインストールだけ uv に任せる
2. 速度と挙動に問題がないか確認する
3. `uv init` で `pyproject.toml` を整備し、`uv add` へ移行する
4. ロックファイルをコミットし、CIを `uv sync --frozen` に切り替える

`pip` と完全に互換ではない細かい差異はあるので、社内ライブラリや特殊なビルド手順がある場合は事前に検証しましょう。

## 使ってみた所感

体感として最も差が出るのは、依存が多いプロジェクトやCIの初回セットアップです。数十秒〜数分単位で待っていた処理が数秒に縮むことも珍しくありません。また `uv run` によって「環境を整えてから実行する」流れが自然になり、環境起因のトラブルが減りました。

一方で、チームに導入する際は「どのコマンドを標準とするか」を決めておかないと、`pip` と `uv` が混在して混乱します。まずは `uv` に一本化する方針を明文化するのが安全です。

## まとめ

- uv は pip・venv・pyenv・pip-tools の役割をまとめて担うRust製ツール
- 速度だけでなく、ロックファイルと `uv run` による再現性の向上が大きな利点
- 既存プロジェクトは `uv pip` から段階的に移行するのが現実的

まだ触れていない方は、まず1つのプロジェクトで `uv init` から試してみるのがおすすめです。
