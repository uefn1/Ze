Pythonの開発環境まわりは、長らく「道具が分散しがち」な領域でした。依存関係は `pip`、仮想環境は `venv`、Python本体のバージョンは `pyenv`、グローバルなCLIツールは `pipx`……と、目的ごとに別のツールを使い分ける必要があります。

そんな状況をひとつにまとめようとしているのが、Ruffを開発したAstral社の **uv** です。本記事では、uvの基本から日常的な使い方までを一通り紹介します。

## uvとは

uvは、Rustで実装されたPythonのパッケージマネージャ兼プロジェクトマネージャです。主に次のような機能を持ちます。

- `pip` 互換のパッケージインストール
- `venv` の代替となる仮想環境管理
- Python本体のバージョン管理
- `pyproject.toml` とロックファイルによるプロジェクト管理
- `pipx` のようなCLIツールの実行・インストール

単一のバイナリで動作し、起動が軽いのも特徴です。複数のツールを覚えるのがつらい、という人には特に向いています。

## インストール

macOS / Linuxでは公式のインストールスクリプトを使うのが手軽です。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Windows（PowerShell）の場合は次のとおりです。

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Homebrewやpipx経由でも導入できます。

```bash
brew install uv
# または
pipx install uv
```

インストールできたか確認しましょう。

```bash
uv --version
```

## プロジェクトを作成する

新しいプロジェクトは `uv init` で始められます。

```bash
uv init myapp
cd myapp
```

生成される `pyproject.toml` に依存関係を追加していきます。

```bash
uv add requests
```

`uv add` を実行すると、依存関係の解決、`pyproject.toml` の更新、`uv.lock` の生成、仮想環境（`.venv`）の作成までがまとめて行われます。

```bash
uv run main.py
```

`uv run` は、プロジェクトの仮想環境を自動で使ってコマンドを実行してくれます。`source .venv/bin/activate` を忘れる心配がありません。

## 依存関係の管理

よく使うコマンドを整理しておきます。

```bash
uv add requests          # 依存関係を追加
uv add --dev pytest      # 開発用の依存関係を追加
uv remove requests       # 依存関係を削除
uv sync                  # ロックファイルに合わせて環境を同期
uv lock                  # ロックファイルを更新
uv tree                  # 依存関係をツリー表示
```

`uv.lock` はリポジトリにコミットしておくのが基本です。チーム全員が同じ依存関係を再現できます。

pipと同じ感覚で使いたい場合は、`uv pip` サブコマンドも用意されています。

```bash
uv pip install requests
uv pip freeze
```

## Pythonバージョンを管理する

uvはPython本体のインストールも扱えます。

```bash
uv python install 3.12
uv python list
```

プロジェクトで使うバージョンを固定するには `uv python pin` を使います。

```bash
uv python pin 3.12
```

これで `.python-version` が作成され、`uv run` や `uv sync` がそのバージョンを使ってくれます。複数プロジェクトでバージョンを行き来する場合も、切り替えを意識せずに済みます。

## スクリプトとCLIツールを活用する

ちょっとしたスクリプトを書くときは、PEP 723のインライン依存関係が便利です。

```python
# /// script
# dependencies = ["requests"]
# ///

import requests

res = requests.get("https://example.com")
print(res.status_code)
```

このファイルは、依存関係を事前にインストールしなくても実行できます。

```bash
uv run script.py
```

CLIツールの実行も簡単です。`uvx` は `uv tool run` のショートカットで、一時的にツールを実行できます。

```bash
uvx ruff check .
```

常に使うツールはインストールしておきましょう。

```bash
uv tool install ruff
```

## 従来ツールとの比較

ざっくりとした役割の対応は次のとおりです。

| やりたいこと | 従来 | uv |
| --- | --- | --- |
| パッケージ導入 | pip | `uv add` / `uv pip install` |
| 仮想環境 | venv | `uv venv` / `uv sync` |
| Python本体 | pyenv | `uv python` |
| CLIツール | pipx | `uv tool` / `uvx` |
| プロジェクト管理 | Poetryなど | `uv init` / `uv lock` |

すべてを完全に置き換えられるわけではありませんが、日常的な操作の多くをuvに寄せられます。

## 移行と運用のコツ

既存プロジェクトから移行する場合は、`requirements.txt` を取り込むところから始めるとスムーズです。

```bash
uv init
uv add -r requirements.txt
```

CIではロックファイルを厳密に使う `--frozen` が役立ちます。

```bash
uv sync --frozen
```

Dockerイメージに組み込む場合も、公式イメージや単体バイナリを利用できます。キャッシュを効かせたいときは、依存関係の定義だけ先にコピーして `uv sync` する構成が定番です。

また、いきなりすべてを移行する必要はありません。まずはローカル開発で `uv run` と `uv add` から試し、慣れてきたらCIやDockerへ広げていくのが安全です。

## まとめ

uvは、Pythonの依存管理・仮想環境・バージョン管理・ツール実行をまとめて扱えるツールです。

- `uv init` でプロジェクトを開始する
- `uv add` で依存関係を追加し、`uv.lock` をコミットする
- `uv run` で仮想環境を意識せず実行する
- `uv python` でPython本体のバージョンも管理する
- `uvx` でCLIツールを手軽に試す

まずは小さなプロジェクトで触ってみて、開発体験の軽さを確かめてみてください。
